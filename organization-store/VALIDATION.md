# P&T AI Square 구현 검증 — 2026-10-25

공통 앱 0.23.32에 범용 확장 연결부를 추가하고, P&T AI Square 0.1.0은 별도 설치 파일로 생성했습니다. 전용 본문 화면과 항목별 상세 팝업, 웹 유형 색상, 등록자·조회수, 설치 범위 선택을 반영했습니다. 운영 서버 게시, 릴리즈 변경, 현재 PC의 앱 재설치는 수행하지 않았습니다.

## 전용 화면·설치 범위 추가 검증

- 공통 앱 관련 회귀 216개 통과, Windows symlink 시험 1개 제외. 최종 확장 frontend 20개 및 backend 23개 통과.
- worker·정본 설치 엔진·중단 복구 106개 통과, 공식 MCP SDK 미설치 1개 제외. 조회수 2초 제한 보완 후 worker 시험 17개 통과.
- KEY·등록자·조회수·카탈로그·부서 권한 API 62개 통과. 실제 Flask/Mongo 설치·업데이트·복구 8개 통과(62개와 6개 중복). 현재 업무 / 선택한 폴더 / 개인 계정 범위를 각각 확인했습니다.
- 설치기 회귀 15개 통과. 공통 EXE 실제 추출 파일 179개를 소스 번들과 대조했으며 조직 전용 코드는 포함하지 않았습니다.
- 웹 상세 열람 기록과 비동기 응답 시험 11개 통과. 상세 탭 전환·권한 거절·설치 준비는 조회수를 늘리지 않습니다. 같은 사용자·항목은 웹/앱을 합쳐 30분 동안 중복 집계하지 않으며 추천 점수는 유지합니다.
- 조회수 기록 실패는 상세 내용을 막지 않습니다. 확장의 부가 집계 요청만 2초로 제한하고 자동 재시도하지 않습니다.
- 선택한 폴더가 다운로드 도중 교체되는 경합을 실제 파일로 재현했습니다. 수정 후 원래/대체 폴더를 변경하지 않고 설치를 거절하는 것을 독립 검토로 확인했습니다.
- 최종 브라우저 결과: `../outputs/square-page-qa/browser-results.json`. 전용 화면, 일반대화 진입, 상세 팝업의 필터 유지, 등록자·유형색·통계, 현재 업무/개인 계정/특정 폴더 설치 준비, 폴더 선택 취소, 초안 보존, 복구, 다크/좁은 화면을 확인했습니다. 네이티브 picker 입력은 격리 시험 폴더로 대체했고 실제 서버의 토큰 발급·후속 요청 경계는 그대로 사용했습니다.
- 화면 12회 전환 후 Documents 3 / DOM Nodes 3,614 / 이벤트 리스너 409로 유지했습니다. 워밍업 후 JS heap 차이는 226,196바이트(약 221KB)이며 전체 OS 메모리가 아닌 Chromium renderer 측정입니다.
- 최신 캡처: `../outputs/square-page-qa/02-catalog.png`, `03-detail.png`, `09-directory.png`. 표시된 항목·이름·통계는 검증용 자료입니다.

## 확인한 동작

- 공통 호스트 backend 20개 / frontend 16개 시험 통과. 기존 종료·승인·프로세스 관련 회귀 34개 통과.
- KEY/권한/부서별 카탈로그 관련 59개 시험 통과. 실제 Flask/Mongo와 파일 설치·업데이트·좋아요·다운로드 집계를 연결한 시험 6개 통과.
- 기존 MCP 엔진, 실제 HTTP·stdio worker, 설치 중 강제 종료와 동시 파일·설정 변경 시험 117개 통과, 1개 건너뜀. 건너뛴 시험은 `test_local_mcp.py::test_stdio_initialize_list_and_call_actual_sdk`이며 검증 인터프리터에 공식 `mcp` Python SDK가 없기 때문입니다. 스토어 자체는 이 SDK를 사용하지 않으며 실제 스토어 worker·HTTP·설치 시험은 통과했습니다. 전체 플랫폼 시험을 전부 통과했다고 주장하지 않습니다.
- 별도 설치기 15개 시험 통과. 실제 .NET 설치 도우미를 격리된 폴더에서 실행했습니다. 소유하지 않은 경로·링크·변조 파일을 거부하고, 업데이트 중 강제 종료 후 재설치, 사용자 데이터 보존 제거를 확인했습니다. NSIS 설치 EXE 자체는 빌드했으며 현재 사용자 프로필에 설치하지 않았습니다.
- 기존 스킬 ZIP 15개 최신 여부 확인, 관련 패키지 시험 48개 통과. 이 작업으로 해당 스킬 ZIP 내용은 바뀌지 않았습니다.
- 변경한 정본 MCP 소스의 다운로드용 ZIP은 `pt_ai_square/static/guides/pt-square-mcp.zip`에 다시 생성했습니다.
- 최종 배포 패키지를 실제 .NET 설치 도우미로 임시 폴더에 설치하고, 실제 공통 앱 호스트에서 동봉된 worker의 `status`를 실행했습니다. 제거 후 확장 코드만 삭제되고 데이터가 유지되는 것까지 통과했으며 개인 프로필은 변경하지 않았습니다 (`tests/verify_preview.py`).

## 실제 UI

Chromium에서 실제 공통 앱과 격리 iframe을 사용했습니다. 카탈로그 데이터만 합성 자료이며 실제 조직 KEY나 Claude 요청을 사용하지 않았습니다.

- 연결 버튼·KEY 비우기, 검색·필터·좋아요, 파일 다운로드와 설치 구분.
- 명시적인 설치 범위 선택, 변경 경로 확인, 설치 목록·상태 확인·복구.
- 스토어를 닫고 다시 열어도 기존 채팅 입력 보존, iframe 제거.
- EXE 항목은 다운로드만 제공, 설치 완료로 표시하지 않음.
- 중단된 설치에서 사용자 변경이 있으면 확인 필요 카드 표시.
- 다크/라이트·좁은 화면, 앱 스타일에 맞춘 드롭다운, 코드 문자열을 검색어로 입력해도 실행하지 않음.

## 미설치 사용자와 초기 연결부 비교 기록

설치된 확장이 없으면 확장 UI JS/CSS, iframe, 스토어 프로세스, 플랫폼 네트워크 요청, 주기 조회가 생성되지 않습니다. 범용 호스트 모듈 자체의 소량 메모리는 추가됩니다.

아래는 전용 화면 변경 이전, 초기 연결부 구현 당시 동일 PC에서 HEAD와 수정본을 교차 20회 실행한 격리 비교 기록입니다. `tracemalloc`을 켰으며, 아래 시간은 전체 Windows 창 실행 시간이 아니라 `LocalApp` 생성/응답 비용입니다. 최신 화면 전환 결과는 위 추가 검증을 참고하세요.

## 적용 조건과 남은 운영 확인

1. 공통 앱은 버전 숫자뿐 아니라 실제 확장 연결부 포함 여부를 확인해야 합니다. 이번 개발본과 이전 배포본 모두 0.23.32일 수 있습니다.
2. 사내 플랫폼에 이번 KEY 좋아요·조회수 API, 등록자 정보, 부서 권한 판정 보완을 반영해야 전체 연동을 확인할 수 있습니다. 기존 DB·업로드 자료 초기화는 필요하지 않습니다. 조회수는 적용 이후부터 기록하며 과거 이력을 추정하지 않습니다.
3. 실제 조직 KEY, 사내망 인증서·프록시·VDI 정책, 실제 MCP 실행과 Claude 연결은 해당 운영 환경에서 추가 확인해야 합니다. 파일 배치·설정 저장을 실제 MCP 연결 성공으로 취급하지 않습니다.
4. 설치 도중 사용자 변경을 발견하면 덮어쓰지 않습니다. 이때 안내된 대상/보관본을 확인해야 하며 같은 설치를 자동 재실행하지 않습니다.

## 2026-10-25 서버 주소 포함 다운로드

- 웹의 `/local-access/workspace-extension.zip`은 `PTAI_PUBLIC_URL` 또는 접속한 origin을 주소 파일에 넣고, 사전 빌드한 EXE를 수정 없이 동봉합니다. 두 서버의 응답 분리, 쿼리/프록시 헤더로 주소를 바꾸지 못하는지, 브라우저 인증, 비밀값 미포함, `no-store`, 잘못된 실행 주소 거부를 검증했습니다.
- 실제 빌드한 네이티브 설치 도우미로 격리 폴더에 설치한 뒤 **설치 패키지에 포함된 worker**를 새 프로세스로 실행했습니다. 로컬 HTTP 시험 서버에서 주소 없이 KEY만 전달해 인증 성공, HTTP 확인 없이는 차단, 이후 다른 주소 파일을 받아도 기존 인증 연결 유지, 제거 후 연결 자료 보존을 확인했습니다. NSIS 설치 파일 생성은 검증했으며 실제 PC에 설치 UI를 실행하지 않았습니다.
- 실제 Chromium에서 주소 자동 표시, KEY 입력, HTTP 확인, 명시적 주소 변경 시 KEY/확인 초기화, 기존 연결 우선, 잘못된 주소 파일의 수동 복구 화면을 확인했습니다.
- 긴 설치 경로에서 Python 모듈 검색이 Windows 260자 제한에 걸리는 사례를 발견해 worker의 vendored import 경로에 확장 경로를 적용했습니다. 260자를 넘는 중첩 모듈과 긴 경로 전체 연결 시험을 통과했습니다.
- worker/주소 입력/기존 HTTP 기능 35개, 추가 긴 경로 회귀 1개, 설치 도우미 21개 통과. 웹 다운로드 및 기존 MCP 독립 검증 36개 통과(기존 MongoDB 의존 2개 제외), AX 웹 UI 10개 및 Chromium 연결 폼 검증 통과. 실제 다운로드→설치→인증 통합 시험 통과.
- 공통 배포 ZIP 16개 재생성·`--check`: 변경 없음. 관련 플랫폼 스킬 설치기 19개·패키지 24개 통과. 별도 외부 제조 Oracle MCP까지 포함한 광범위 검사는 해당 MCP 시험의 stdio 준비 전 대기로 중단했으며 이 외부 연결 시험은 미완료입니다. 현재 확장 연결 흐름 검증과는 구분합니다. 시험 프로세스는 종료했습니다.
- 최종 확장 빌드: `78e836d6636af91841976c105e71886ee7297e9171c3e1c2ed8241a3b6710927`. 설치 EXE SHA-256: `e251b0a4f11bdb60cf2f76969a7a81fb9362bf1a5ff7cff4ca840896b6f94733`.
- 웹에서 생성하는 확장 ZIP은 접속한 서버 주소만 포함하며 설치 EXE 원본을 유지합니다. 공개 배포물에는 조직 주소를 미리 넣은 ZIP을 포함하지 않습니다. **사내 운영 서버 연결·실제 개인 KEY 인증은 검증하지 않았습니다.** 공통 앱 버전과 실제 사용자 프로필은 변경하지 않았습니다.
