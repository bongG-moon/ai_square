# AX Workspace용 P&T AI Square 확장

공통 AX Workspace는 범용 확장 연결부만 제공합니다. P&T AI SQUARE의 주소, KEY 연결, 카탈로그, 설치 엔진과 UI는 이 별도 패키지에 포함됩니다. 스토어를 설치하지 않은 사용자에게 메뉴가 생기거나 플랫폼에 접속하는 작업은 없습니다.

## 사용 순서

1. **확장 가져오기 기능을 지원하는 최신 AX Workspace**를 사용합니다. 앱 내부 업데이트로 활성화된 실행 자료도 설치기가 확인합니다. 초기 0.23.32 배포본에는 해당 기능이 없을 수 있으므로 버전 숫자만으로 호환성을 판단하지 않습니다.
2. 웹의 **AX Workspace** 탭에서 관리자가 등록한 `PNT-AI-Square-0.1.0-Setup.exe`를 받아 실행합니다. EXE가 설치된 AX Workspace를 직접 열기 때문에 `.axextension` 파일 연결이나 연결 프로그램 선택이 필요 없습니다. 앱에서 이름·버전·설치 위치·서버 주소를 확인하고 **설치**하면 왼쪽 메뉴에 **P&T AI Square**가 나타납니다. 사용자는 압축 해제나 Python 설치를 하지 않습니다. 현재 Windows 계정의 확장 폴더에만 설치하며 일반 대화와 업무 모드 모두에서 열 수 있습니다. 기존 ZIP은 설정의 **확장 ZIP 가져오기**에서도 지원합니다.
3. 배포자가 서버 주소를 담은 `connection.json`을 포함했다면 앱에서는 웹 `/local-access`에서 발급받은 **기존의 유효한 개인 KEY만 입력**합니다. 주소 파일이 없는 범용 설치 파일은 서버 주소도 직접 입력합니다. HTTP 서버는 최초 연결 시 KEY와 통신 내용이 암호화되지 않음을 확인합니다. 같은 주소의 동의는 앱을 다시 열어도 유지하며 HTTPS에는 이 확인이 없습니다. 새 KEY를 자동 발급하거나 교체하지 않습니다. 기존 플랫폼 MCP 연결이 있다면 **저장된 플랫폼(MCP) 연결 사용**을 선택할 수도 있습니다. 이 버튼은 저장된 주소·KEY를 재사용하며 MCP를 새로 설치하거나 실행하지 않습니다.
4. 기능을 검색하고 상세 화면의 **설치·연결 → 바로 설치하기**를 선택합니다. 설치 정보가 없는 ZIP도 같은 버튼에서 파일 구조를 확인한 뒤 설치 위치 선택으로 이어집니다. 별도의 다운로드 버튼을 먼저 누르거나 링크를 복사할 필요가 없습니다.
5. **공통으로 사용(내 계정) / 업무를 선택해 사용** 중 선택하고, 업무 설치라면 앱에 등록된 업무 목록에서 고릅니다. 실제 변경 경로를 확인한 뒤 설치하면 앱이 파일을 다운로드·검증하고 배치합니다. MCP는 등록된 실행 정보로 연결 설정까지 반영합니다. 진행 중인 대화를 자동으로 끊거나 Claude를 재시작하지 않습니다.

일반 대화에서도 기존 업무를 설치 대상으로 선택할 수 있습니다. 공통 설치는 현재 Windows 계정의 여러 업무에 적용하며 PC의 모든 계정에 설치하는 동작이 아닙니다. 목록에 없는 폴더는 추가 선택에서 앱의 폴더 선택 창으로 지정합니다. 설치 대상을 골라도 현재 대화·초안·폴더 신뢰 설정은 바뀌지 않습니다. 확장 화면이 임의 경로를 지정할 수 없고, 서버가 발급한 15분 유효 토큰과 실제 경로를 설치 준비·확정 시 다시 대조합니다. 선택한 업무가 보관·삭제되거나 폴더가 변경되면 다시 선택해야 합니다.

연결을 확인하는 동안 버튼에 **연결 확인 중…**을 표시하고 다른 연결 요청이 겹치지 않게 합니다. 실패 이유는 연결 버튼 바로 위에 표시하며, 잘못된 KEY나 새 연결의 저장 실패로 기존 연결을 덮어쓰지 않습니다. KEY 인증 실패 시 **웹에서 KEY 확인**에서 유효한 KEY를 확인한 뒤 이 화면의 입력란에 다시 입력하세요. 저장된 MCP 연결을 선택해 서버가 바뀌면 이전에 입력한 KEY는 지웁니다.

업무 목록 선택은 공통 앱의 새 확장 연결부가 필요합니다. 같은 0.23.32라도 이전 빌드에서는 앱 업데이트 안내가 표시되며 공통 설치·폴더 선택은 계속 사용할 수 있습니다. 이 연결부는 확장 화면의 명시적인 요청 때만 목록을 읽고 폴더 전체 스캔이나 상시 조회를 추가하지 않습니다.

## 화면과 상세 정보

목록은 넓은 화면에서 3열, 좁은 화면에서는 2열 또는 1열로 표시합니다. 설명은 두 줄까지만 보이고 긴 내용은 말줄임 처리합니다. 카드를 열면 전체 설명을 읽을 수 있습니다. 본문은 앱과 같은 Noto Sans KR 13px이며, 상세·설치·등록 팝업에도 같은 글꼴과 조작 요소 크기를 적용합니다. 글꼴은 AX 앱의 내장 파일을 재사용하므로 별도 외부 폰트 서버에 접속하지 않습니다.

상단 **P&T AI Square**를 누르면 연결한 플랫폼 홈페이지를 엽니다. 카드의 제목뿐 아니라 설명·등록자·여백을 눌러도 상세를 확인할 수 있으며, 별도 버튼과 텍스트 선택은 그대로 사용할 수 있습니다. 검색은 이름·기능·등록자 이름을 지원합니다. 등록자 검색에는 최신 플랫폼 서버도 함께 반영되어야 합니다.

**설치된 기능**에서는 실제 도구 이름을 먼저 표시하고 유형·설치 버전·사용 범위·설치 위치를 나눠 보여줍니다. 예전 설치 기록에 이름이 없으면 현재 연결된 플랫폼에서 확인합니다. 서버 연결이나 사용 권한 때문에 확인하지 못한 경우에도 설치 기록과 파일은 보존하며, 기존 설치 위치와 이름 확인 안내를 표시합니다. **상태 확인**과 **이전 상태로 복구**는 기존 파일 검사와 사용자 변경 보호 절차를 유지합니다.

**설치 진행 상태**는 설치 버튼과 바로 아래 안내에 표시합니다. 준비·최종 확인·설치를 구분하며 팝업을 닫아도 스토어 상단에서 확인할 수 있습니다. 응답이 늦으면 완료로 추정하지 않고 **설치 결과 확인 필요**로 표시합니다. **설치된 기능 확인**은 이번 준비안과 일치하는 저장 기록으로 결과를 확인하며, 이전 설치 기록을 이번 설치 성공으로 취급하거나 같은 설치를 자동 재실행하지 않습니다. 설치 결과가 확인되지 않으면 목록을 확인하고 **확인 마침**으로 검토를 끝낼 수 있습니다. 중단 설치 복구가 필요한 경우에는 먼저 해당 안내를 따릅니다. 설치 중에는 중복 설치와 플랫폼 연결 변경을 막으며 주기적 진행 조회나 추정 백분율은 사용하지 않습니다.

현재 자동 설치는 파일 배치와 MCP 연결 설정 저장까지 수행합니다. **설치 중 KEY·서버 주소를 입력받거나 설치 스크립트·의존성 설치를 실행하지 않습니다.** 스토어 로그인 KEY를 설치하는 기능에 전달하지도 않습니다. 추가 설정이 필요한 기능은 완료 화면의 **설정 안내 보기**에서 등록자 안내에 따라 설정하고, Claude를 다시 연결해 실제 동작을 확인하세요. 파일 설치 완료와 실제 연결·실행 성공은 구분됩니다.

**업데이트**에는 현재 설치 버전보다 새로운 배포가 확인된 기능만 표시합니다. 이미 최신인 기능, 이전 버전으로 복구된 배포, 사용 권한이나 연결 문제로 확인하지 못한 기능을 업데이트 카드로 섞지 않습니다. 일부 조회가 끝나지 않았으면 그 상태를 별도 안내하며, 모든 기능이 최신이라고 표시하지 않습니다. 실제 설치는 변경 내용과 사용할 공간을 확인한 뒤 진행합니다.

화면 탭·상세 내용·팝업은 약 0.3초의 투명도와 작은 이동 효과로 전환합니다. 전환 효과를 기다렸다가 버튼을 처리하지 않으며, Windows의 동작 줄이기 설정을 따릅니다.

## 앱에서 도구 등록

1. 연결 후 상단의 **도구 등록**을 누릅니다. 플랫폼 KEY에 **업로드 포함** 권한이 필요합니다. 조회 전용 KEY는 목록과 상세를 계속 이용할 수 있으며 등록 창에서 권한 안내를 표시합니다.
2. 신규 등록 또는 **본인이 등록한 기존 도구의 새 버전**을 선택합니다. 내 도구는 웹·앱 등록 경로에 관계없이 전체 목록을 페이지별로 가져옵니다. ZIP 추천 항목은 이 목록을 대체하지 않습니다. 파일은 선택 버튼 또는 끌어놓기로 ZIP·MD·AXEXTENSION·EXE·MSI·PS1 중 한 개(64MiB 이하)를 올립니다. URL·명령어 안내만 등록하는 방식도 지원합니다. 파일은 업로드 자료이며 선택·검토 과정에서 실행하지 않습니다.
3. 배포 Skill로 준비한 ZIP을 선택하면 `ai-square.json`과 사용 안내 파일에서 이름·설명·프로그램·유형·설치 안내·변경 내용을 자동 입력합니다. 직접 작성한 내용은 유지하며, 다른 ZIP을 고르면 이전 파일의 자동 입력 정보는 교체합니다. **ZIP 정보 다시 적용**으로 원본 값을 다시 채울 수도 있습니다. 조직·업무 분류·공개 범위는 직접 선택합니다. 같은 이름이나 packageId를 이유로 자동 업데이트하지 않습니다.
4. 등록 대상과 공개 범위를 확인한 후 **등록하기**를 누르면 앱 안에서 등록을 완료합니다. KEY의 업로드 권한, 소유권, 파일 해시, 공개 범위, 초안 digest, 기존 버전 충돌과 중복 요청 검사는 서버에서 유지합니다. 응답이 끊기면 **등록 결과 확인**으로 먼저 상태를 확인합니다. 구형 플랫폼에서 직접 등록이 지원되지 않으면 플랫폼도 업데이트해야 합니다.

등록 창을 닫아도 현재 스토어 화면의 입력은 유지됩니다. 내용을 수정하면 이전 초안을 그대로 게시하지 않고 다시 검토합니다. 서버가 받은 같은 요청의 재시도는 동일 초안을 사용하며 중복 배포를 만들지 않습니다. 다른 KEY나 서버로 바뀐 경우 기존 준비안을 사용할 수 없습니다. 실제 사내 서버에 등록하려면 해당 서버의 기존 게시 초안 API가 지원되어야 합니다.

파일 선택과 내장 글꼴 공유에는 이번 공통 앱 연결부가 필요합니다. 버전이 같은 0.23.32라도 이전 빌드에서는 파일 등록에 업데이트 안내가 표시됩니다. 기존 조회·설치 기능은 유지합니다. 새 연결부는 사용자가 등록 파일을 선택할 때만 작동하며 백그라운드 조회를 추가하지 않습니다.

P&T AI Square는 스킬과 기능처럼 본문을 사용하는 전용 화면입니다. 개별 항목만 **소개 / 설치·연결 / 버전 / 의견** 상세 팝업으로 열립니다. 팝업을 닫으면 검색·필터·스크롤 위치가 유지됩니다. 웹의 유형별 색상으로 Skill, Tool, MCP, 하네스와 플러그인을 구분합니다.

카드와 상세에 **등록자**, **조회**, **좋아요**, **다운로드**를 표시합니다. 등록자는 게시한 사용자이며 입력한 담당자와 구분합니다. 예전 서버에서 등록자·조회수를 제공하지 않으면 정보 없음 또는 `—`로 표시합니다. 서버의 실제 통계만 표시하며 누락된 값을 임의로 0으로 만들지 않습니다.

조회수는 이번 서버 개선부터 집계합니다. 웹과 확장의 상세 열람을 같은 API에 기록하며 동일 사용자의 같은 항목 열람은 30분 동안 한 번만 셉니다. 탭 전환, 설치 준비, 자동 갱신, 단순 상세 GET은 조회수를 증가시키지 않습니다. 이전 열람 이력은 추정하여 채우지 않고, 좋아요·다운로드 및 추천 순위 계산은 유지합니다.

## 설치 상태의 의미

| 기능/배포 형식 | 스토어에서 하는 일 | 완료 표시의 의미 |
| --- | --- | --- |
| 설치 선언이 있는 Claude Skill | 파일 확인 후 `.claude/skills/<slug>`에 설치 | 파일 설치 완료 |
| 설치 선언이 없는 표준 Skill ZIP | ZIP의 최상위 `SKILL.md`와 유효한 Skill 이름을 확인하고 대상 경로 검토 후 설치 | 파일 설치 완료. ZIP 안의 스크립트는 설치 과정에서 실행하지 않음 |
| 설치 선언이 있는 Claude MCP | 파일 설치와 기존 MCP 설정에 해당 항목 병합 | 연결 설정 완료. 실제 서버 실행은 다음 Claude 연결에서 확인 |
| EXE/MSI/PS1, 설치 방식을 확인할 수 없는 일반 ZIP, 하네스 | 파일 다운로드와 등록자의 설치 안내 제공 | 다운로드 완료. 설치·실행 완료로 표시하지 않음 |
| URL/명령어형 항목 | 상세의 주소·사용 방법과 웹 이동 제공 | 연결/설치 안내 확인 |

플랫폼의 `installProfile`은 설치 동작을 선언하는 서버 정보입니다. 기존 선언이 없을 때만 ZIP의 실제 표준 Skill 구조로 파일 배치를 준비하며, 잘못된 선언·수동 설치 선언을 추측으로 덮어쓰지 않습니다. 배포 파일의 유형이나 README 문구만 보고 명령을 만들어 실행하지 않습니다. 별도 의존성 설치·하네스 설정처럼 명령 실행이 필요한 일반 ZIP에는 등록자의 정확한 설치 정보가 필요합니다. 이 버전은 임의 셸 명령이나 EXE/MSI를 자동 실행하지 않습니다.

**설치된 기능**에서 파일·설정 상태를 확인하거나 이전 상태로 복구합니다. 처음 설치한 기능의 복구는 해당 설치를 제거하는 동작입니다. 사용자가 이후 변경한 파일·설정은 자동으로 덮어쓰지 않습니다. 업데이트는 사용자가 **업데이트** 화면을 열 때 조회하며, 새 버전을 자동 설치하지 않습니다.

## 웹과 연결하는 정보

### 앱 내부 업데이트 후 확장 설치

새 Setup은 최초 설치된 EXE만 호출하지 않고, 현재 Windows 계정의 **업데이트 완료된 앱**을 우선 확인합니다. 업데이트 기록·앱 경로·전체 파일 해시를 확인한 뒤 해당 버전의 기존 설치 확인 기능을 엽니다. 따라서 원래 설치 EXE가 확장 기능을 모르더라도, 앱 내부 업데이트로 지원 버전을 적용했다면 기본 앱을 다시 설치하지 않아도 됩니다. 같은 버전 안에서 수정된 빌드도 업데이트 기록을 우선합니다.

업데이트 파일이 없으면 확장 기능을 지원하는 설치 EXE를 사용합니다. 업데이트 기록이 손상됐거나 검증되지 않은 파일이 있으면 실행하지 않고 복구 방법을 안내합니다. 실행 중인 업무·초안·KEY·예약·기존 연결은 변경하지 않습니다. 앱에 설치 확인을 한 번 전달한 후에는 오류가 나도 다른 실행기로 자동 재전달하지 않습니다.

이 수정은 **새 Distribution으로 다시 만든 확장 Setup.exe부터** 적용됩니다. 이미 웹에 올리거나 내려받은 확장 EXE는 자동으로 바뀌지 않습니다. 확장 버전은 0.1.0을 유지하며 관리자가 새 Distribution에서 같은 서버 주소로 EXE를 다시 만든 뒤 직접 교체 등록합니다.

### 완성된 프로그램을 AX Workspace 탭에 등록하기

이 폴더는 선택 확장의 개발 소스입니다. 웹에 특정 확장 소개나 고정 설치 파일을 내장하지 않습니다. 프로그램을 완성한 뒤 관리자가 **AX Workspace → 파일 등록**에서 이름·설명·분류·배포 버전과 완성된 파일을 등록합니다. 이후 KEY 페이지에서 AX Workspace 탭으로 이동한 사용자가 해당 카드를 찾아 받습니다.

서버 주소는 **배포자**가 지정합니다. 확장 코드·`extension.json`·`connection.json`·설치 안내를 검증 가능한 ZIP으로 묶고, 이를 기존 앱에 전달하는 **Setup.exe**를 만듭니다. EXE는 확장을 사용자 프로필에 직접 설치하지 않고 AX Workspace의 검증·설치 확인 절차를 사용합니다. 주소 파일은 `{"schemaVersion": 1, "baseUrl": "https://square.company.example"}` 형식입니다. 서버 실행 주소 `0.0.0.0` 대신 사용자가 접속하는 주소를 사용하고 KEY·쿠키·MongoDB 접속 정보를 넣지 않습니다. 사내 주소가 포함된 최종 설치 파일은 사내 배포용으로 관리하고 공개 Git에 올리지 않습니다.

Git 릴리즈에서 받은 **`PNT-AI-Square-0.1.0-Distribution.zip`**은 서버 주소가 없는 관리자용 준비 자료입니다. **Windows에서 전체 압축을 풀고** `configure_server.py` 상단의 **`SERVER_URL`**에 실제 서버 주소를 입력하세요. 출력 설정은 기존 변수명 `OUTPUT_ZIP`을 유지하지만 기본값은 `PNT-AI-Square-0.1.0-Setup.exe`입니다. Python 3.10 이상이 필요하고, EXE 생성용 NSIS 도구와 라이선스는 Distribution에 함께 들어 있습니다. 별도 pip 설치·NSIS 시스템 설치·빌드 중 인터넷 다운로드는 하지 않습니다.

```powershell
python configure_server.py
```

생성된 **Setup.exe 하나를 웹에 등록**합니다. 기본 출력 위치는 Python 파일과 같은 폴더입니다. 주소를 비워 두면 수정할 위치를 안내하고 종료합니다. 기존 `--server-url`·`--output` 옵션과 수동 가져오기용 `.zip`·`.axextension` 출력도 유지합니다. 지정한 옵션이 파일 상단 설정보다 우선하며, 명시적으로 `--output`에 상대 경로를 주면 실행한 폴더를 기준으로 합니다.

`Distribution.zip` 자체를 사용자 설치 파일로 올리지 않습니다. 도우미는 동봉 template의 전체 SHA256과 각 payload 파일·경로·빌드 해시를 검사합니다. 확장 실행 코드는 유지한 채 주소·등록 정보·안내를 구성하고, NSIS로 이를 전달하는 EXE를 생성합니다. 빌드 중 확장 코드를 실행하거나 서버에 접속하거나 개인 프로필을 바꾸지 않으며 기존 출력 파일을 덮어쓰지 않습니다. HTTP 전송 주의 안내를 설치 자료와 실행 결과에 표시합니다. 해시는 전자서명이 아니므로 Git 릴리즈의 출처와 공개 체크섬을 함께 확인하세요. 상세 절차는 [DISTRIBUTION_README.txt](DISTRIBUTION_README.txt)를 따릅니다.

EXE는 ZIP처럼 내부 `ai-square.json`으로 웹 등록 항목을 자동 입력하지 않습니다. AX Workspace의 **파일 등록**에서 이름 **P&T AI Square 확장**, 분류 **플러그인**, 버전 **0.1.0**, 설치 설명을 직접 입력하고 생성된 EXE를 첨부하세요. 웹은 등록된 EXE를 다운로드만 제공하며 자동 실행하지 않습니다.

웹은 등록한 파일을 원본 그대로 제공합니다. EXE를 ZIP에 추가하거나 `connection.json`을 만들지 않으며 `PTAI_PUBLIC_URL`도 AX 자료실 파일에 적용하지 않습니다. `PTAI_PUBLIC_URL`에 따른 주소 포함 기능은 별도의 로컬 MCP 다운로드에만 유지됩니다.

공통 앱은 ZIP 경로·크기·해시·대상 폴더를 검사한 뒤 사용자 확인을 받아 설치합니다. 주소 파일은 `extension-data/pt-ai-square.store/connection.json`에 저장합니다. 이미 인증된 연결이 있으면 기존 주소·KEY를 우선 사용하며 새 ZIP의 주소로 자동 전환하지 않습니다. 다른 서버로 바꾸려면 연결 화면의 **서버 주소 변경**에서 해당 서버의 KEY로 다시 연결합니다.

완성된 EXE를 웹의 `static/guides`에 복사하지 않고 관리자가 자료실에 직접 등록합니다. 이전 `/local-access/workspace-extension.zip`과 `/static/guides/ax-workspace-extension-setup.exe` 링크는 로그인 후 AX Workspace 탭(`/?view=ax`)으로 이동합니다. 이미 사용자가 설치한 프로그램이나 내려받은 파일을 자동 교체하지 않습니다. `build.py`의 `StoreInstaller.exe` 기반 설치기 생성은 **구형 방식의 참고·회귀 시험용**이며 새 배포에는 사용하지 않습니다.

| 용도 | 기존 플랫폼 계약 |
| --- | --- |
| KEY/계정 확인 | `GET /api/integration/me` |
| 검색·조직·유형·정렬 | `GET /api/catalog`, `/api/catalog/options` |
| 상세/현재 배포/업데이트 | `/api/tools/{id}`, `/manifest`, `/version-check` |
| 좋아요 | `PUT /api/tools/{id}/like` + 명시적 `liked: true/false` |
| 상세 열람 집계 | `POST /api/tools/{id}/view` + 빈 JSON. 실패해도 상세 열람 유지 |
| 다운로드 | `/download/{id}/{release}` |

좋아요와 다운로드는 웹의 같은 기록을 사용합니다. 설치 기록이 있는 항목의 새 버전 수신은 서버가 제공하는 `purpose=update` 경로로 처리합니다. 검증된 기존 다운로드 파일을 다시 사용하는 경우에는 가짜 다운로드 요청을 보내지 않습니다. 앱의 로컬 설치 기록과 서버의 다운로드 수는 서로 다른 정보입니다.

이번 플랫폼 보완에는 **개인 KEY의 좋아요·상세 열람 API 허용**, **목록·상세의 부서 권한 판정 일치**, **실제 등록자 이름과 조회수 제공**이 포함됩니다. 사내 플랫폼에도 이 서버 수정이 반영되어야 같은 결과를 얻습니다. `orgId`는 분류용 조직이며 SSO의 `dept_cd`와 같은 값으로 간주하지 않습니다.

## 데이터·수명·분리

- 확장 소스: `%LOCALAPPDATA%\CompanyAgent\extensions\pt-ai-square.store`.
- 스토어 연결/다운로드/기록: 공통 앱 상태 폴더 옆 `extension-data\pt-ai-square.store`.
- 설치 패키지와 사용자 데이터는 분리됩니다. 확장 제거가 기존 대화, Claude 설정, 다운로드한 파일이나 설치된 Skill/MCP까지 지우지 않습니다.
- KEY는 현재 Windows 계정의 DPAPI로 암호화하며 URL·명령행·로그·대화에 넣지 않습니다. UI 입력 값은 연결 시도 후 비웁니다.
- 기존 MCP 연결을 재사용하면 원본 설정과 설치 기록을 공유하되, 연결 해제로 원본 KEY를 취소하지 않습니다.
- 전용 화면 안의 격리된 iframe은 앱 토큰·대화 내용을 받지 않습니다. 네트워크 호출은 명시된 작업을 처리하는 Python worker에서만 실행합니다.
- worker는 작업 요청 때 실행하고 끝나면 종료합니다. 상주 스토어 서버, 주기적 폴링, 앱 시작 시 카탈로그/업데이트 전체 조회가 없습니다.
- 화면을 닫아도 이미 시작한 설치를 자동 취소하거나 재실행하지 않습니다. 앱 종료/시간 초과로 프로세스가 중단된 경우 설치 기록을 다시 확인합니다.
- 설치 변경 전에 복구 기록을 저장합니다. 중단 후 파일·설정이 승인한 결과와 정확히 일치하면 기록을 확정하고, 일부만 변경되었으면 이전 상태로 되돌립니다. 예상과 다른 사용자 변경은 **중단된 설치 확인 필요**로 표시하며 보관 경로를 안내합니다. 파일 다운로드나 실행 명령을 자동 반복하지 않습니다.
- 공통 호스트는 **운영체제 수준의 코드 샌드박스가 아닙니다**. 설치된 Python 확장은 사용자 권한으로 실행하므로 조직이 검토한 설치 파일만 배포해야 합니다. 파일 해시는 손상 탐지이며 게시자 전자서명과 같지 않습니다.

## 소스 구성

- `ui/`: 연결, 카탈로그, 상세, 설치 범위·준비안 확인, 설치/업데이트 관리 화면.
- `worker.py`: 공통 호스트 stdio 계약과 기존 플랫폼 설치 엔진 연결.
- `extension.template.json`: 범용 호스트용 ID/진입점/작업 목록.
- `package_for_upload.py`: 웹에 직접 등록할 EXE와 서버 주소 없는 관리자 Distribution을 생성합니다.
- `configure_server.py`: 관리자 Distribution에 동봉하는 서버 설정 도우미. 검증된 template에 서버 주소를 넣고 Setup.exe 또는 호환 ZIP을 생성합니다.
- `installer/ImportExtension.nsi`: 기존 AX Workspace의 확장 가져오기를 호출하는 새 NSIS 설치 진입점입니다. 파일 연결을 사용하지 않습니다.
- `build.py`: 공통 확장 소스 패키징 함수. `StoreInstaller.cs`·`Store.nsi`는 구형 설치 방식의 참고·회귀 시험 소스입니다.
- `tests/`: 개인 프로필 대신 격리 경로와 합성 자료를 사용하는 시험.
- `../pt_ai_square/integrations/pt-square-mcp/pt_square_mcp`: 설치 엔진 정본. 빌드 시 정확한 소스를 vendor로 포함합니다. 복사본을 직접 편집하지 않습니다.

확장 개발 규격은 공통 앱 소스의 `docs/WORKSPACE_EXTENSIONS.md`를 참고합니다. UI의 네트워크 주소·KEY·실행 동작은 공통 앱에 하드코딩하지 않습니다.

### 독립 Git 저장소에서 개발·검증하기

이 저장소에는 `organization-store/`와 그 옆 `pt_ai_square/`가 함께 있습니다. worker는 개발 중에는 이 이웃 폴더의 MCP 정본을 읽고, 배포 패키지에서는 동봉된 `vendor/pt_square_mcp/`를 읽습니다. 별도 AX Workspace 소스나 개인 설정을 웹 저장소에 복사할 필요는 없습니다. 웹 운영 서버는 관리자가 등록한 완성 파일을 전달하므로 빌드 도구가 필요하지 않습니다.

소스에서 EXE를 생성하려면 Windows의 Python과 검증한 NSIS 3.12 컴파일러가 필요합니다. NSIS 경로는 `NSIS_MAKENSIS`로 지정할 수 있으며 프로그램이 빌드 도구를 자동 다운로드하지 않습니다. 배포된 Distribution에는 필요한 NSIS 도구가 이미 들어 있습니다. 아래 예시 주소를 실제 접속 주소로 바꾸고 새 출력 폴더를 지정합니다.

```powershell
python organization-store/package_for_upload.py --server-url 'https://square.company.example' --output-directory outputs/square-upload
```

출력 중 `PNT-AI-Square-0.1.0-Setup.exe`를 등록하고 `SHA256SUMS.txt`·등록 안내·빌드 보고서는 관리자가 보관합니다. EXE의 웹 등록 정보는 직접 입력합니다. 파일 생성은 웹 업로드·게시·개인 프로필 설치를 하지 않습니다.

공개 Git 릴리즈용은 주소를 넣지 않고 별도로 생성합니다. 아래 출력의 `Distribution.zip`과 체크섬을 전달하면 관리자가 사내에서 위 `configure_server.py` 명령을 실행할 수 있습니다. 기존에 만든 서버 포함 EXE나 ZIP을 공개 ZIP 안에 다시 넣지 않습니다.

```powershell
python organization-store/package_for_upload.py --distribution --output-directory outputs/square-public
```

다음 시험은 플랫폼 개발·테스트 의존성을 설치한 Python에서 실행합니다. 구형 네이티브 설치기 시험은 새 EXE 전달 방식의 검증과 분리합니다.

```powershell
python -m pytest organization-store/tests/test_upload_package.py organization-store/tests/test_distribution_package.py organization-store/tests/test_worker.py organization-store/tests/test_onboarding.py -q
```

실제 AX 호스트와의 패키지 검증·브라우저 시험을 추가하려면 확장 연결부가 구현된 **별도 공통 앱 소스**를 지정합니다. 이 경로가 없으면 해당 호스트 통합 시험만 사유와 함께 건너뜁니다. NSIS EXE를 새로 생성하는 시험에는 NSIS도 필요합니다. 다른 worker·설치 보호 시험 전체를 건너뛰지는 않습니다. 이전 서버가 확장 ZIP을 조립하던 다운로드 시험은 현재 AX 자료실의 원본 전달 정책과 구분합니다.

```powershell
$env:AX_WORKSPACE_SOURCE = 'C:\src\AX-Workspace'
$env:NSIS_MAKENSIS = 'C:\build-tools\nsis-3.12\makensis.exe'
python -m pytest organization-store/tests -q
python organization-store/tests/serve_browser_fixture.py --output outputs/square-page-qa
```

브라우저 fixture를 실행한 상태에서 별도 터미널의 `node organization-store/tests/browser-ui.cjs`와 `browser-lifecycle.cjs`로 실제 공통 화면을 확인합니다. Playwright 모듈은 `PLAYWRIGHT_MODULE`로 지정할 수 있으며 Chromium 시험은 설치된 Microsoft Edge를 사용합니다. `browser-onboarding.cjs`는 합성 호스트 메시지로 폼만 검사하므로 AX 소스가 필요하지 않습니다.

빌드된 패키지의 실제 호스트 검증은 `python organization-store/tests/verify_preview.py --host-source 'C:\src\AX-Workspace'`로 실행합니다. `--preview`로 별도 빌드 결과 폴더를, `--host-exe`로 검사할 공통 앱 EXE를 지정할 수 있습니다. 개인 프로필·실행 중인 앱을 재설치하는 명령은 아닙니다.

## 검증 범위

- 미설치 시 추가 UI·worker·네트워크·주기 작업이 없는지, 기존 종료·초안 처리 회귀.
- 실제 Chromium + 공통 앱 + 격리 iframe의 연결/검색/좋아요/다운로드/설치 확인/복구/다크·좁은 화면. UI 시험의 서버 자료는 합성 데이터입니다.
- 실제 Python worker/HTTP/해시 다운로드/설치 엔진, Flask/Mongo의 KEY·권한·웹 집계 계약.
- 중단된 파일 설치의 복구, 수정한 사용자 파일 보호, 별도 설치기의 갱신/제거.

개발 PC의 격리 시험이며 사내 운영 서버·VDI 보안 정책·실제 조직 KEY를 사용한 실운영 검증을 대신하지 않습니다. 실제 Claude/MCP 실행 여부를 설치 파일 검사만으로 성공 처리하지 않습니다.

## AI에게 설치 요청

자동 설치 규격이 없는 배포 파일은 상세의 **설치·연결 → AI에게 설치 요청**을 사용합니다. 전체 공간(내 계정) 또는 업무 폴더를 고르고 요청을 처리할 기존 업무를 선택합니다. 공통 설치도 기존 업무에서 처리하며, 앱이 새 폴더의 신뢰나 승인 권한을 자동 부여하지 않습니다.

호스트가 선택한 업무 아래 `.ax-install-requests/<요청 번호>/`에 자료를 내려받고 해시를 검증한 후 정상 이어 할 일 대기열에 추가합니다. 진행 중인 작업과 앞선 대기 요청이 없으면 자동 실행하며, 작업 중이면 끝난 뒤 순서대로 실행합니다. 사용자가 일시 정지했거나 전송 확인이 필요한 요청은 임의로 재개하지 않습니다. `installRequestNavigation`을 지원하는 앱에서는 요청을 보낸 뒤 선택한 업무 화면으로 이동해 진행 상황과 추가 질문을 확인합니다. 원래 화면과 대상 업무의 초안을 각각 유지하고, 요청을 기다리는 동안 다른 화면으로 이동했다면 뒤늦게 화면을 바꾸지 않습니다.

공통 설치는 현재 Windows 계정의 공통 설치 위치를 사용합니다. 선택한 업무 폴더는 자료 보관과 설치 실행·승인·기록을 위한 작업 공간이며 공통 설치 범위를 그 업무로 제한하지 않습니다. 설치 기록을 모으려면 사용자가 만든 ‘공통 도구 관리’ 업무를 선택할 수 있습니다. 기존 업무의 모델·승인 모드·폴더 신뢰를 사용하며 추가 입력은 대화에서 질문합니다. 자료 다운로드·설치 요청 전달·실제 설치 완료는 구분합니다. AI 요청은 자동 설치 완료 기록으로 간주하지 않습니다.

새 기능을 쓰려면 공통 앱의 `publishUpload`·`installRequests` 연결부와 플랫폼의 페이지 조회·직접 등록 API를 함께 반영해야 합니다. 구형 앱에서는 기존 파일 선택과 다운로드를 사용할 수 있습니다. 조직용 기능이 없는 앱에는 스토어 조회나 설치 작업이 발생하지 않습니다.
