처음에는 아래 1~5단계를 순서대로 따라가세요. 사이트에서 받은 ZIP은 서버 주소와 다운로드 폴더를 자동 설정합니다. 처음 한 번 AI에 MCP를 등록한 뒤 “AI SQUARE 연결해줘”라고 요청하세요. 안내에 따라 채팅에서 개인 KEY를 전달하면 연결됩니다.

서버 주소 자동 설정다운로드 폴더 자동 생성실제 계정 인증 확인

이미 MCP가 등록되어 있다면 다시 등록할 필요가 없습니다. 최신 ZIP을 기존 MCP 위치에 반영하고 AI 프로그램을 다시 시작한 뒤, 채팅에서 아래 KEY 연결을 진행하세요. 기존 .venv와 개인 설정은 보존합니다.

STEP 01 · 준비

Python과 사용할 AI를 확인합니다.

Windows PC에 Python 3.11 이상과 로컬 stdio MCP를 지원하는 AI 프로그램이 필요합니다. 아래에서는 Claude Code 등록 방법을 예시로 설명합니다.

  1. Windows 시작 메뉴에서 PowerShell을 엽니다.
  2. 아래 명령을 입력하고 Enter를 누릅니다. Python 3.11 이상이 표시되어야 합니다.
python --version

Python이 없다면 회사에서 허용하는 방법으로 설치한 후 새 PowerShell 창에서 다시 확인합니다. Claude Code를 사용할 경우 claude --version으로 실행 가능한지도 확인하세요. 이 단계에는 KEY를 입력하지 않습니다.

STEP 02 · 사이트에서 받기

KEY와 MCP ZIP을 받습니다.

  1. AI SQUARE에 로그인하고 우측 상단 열쇠 아이콘을 누릅니다.
  2. 연결 KEY 발급을 누릅니다. 개인 KEY 하나로 검색·다운로드·좋아요와 본인 도구 신규 등록·새 버전 게시를 사용할 수 있습니다. 기존 유효한 읽기 KEY도 그대로 사용하며 권한 선택이나 재발급은 필요 없습니다.
  3. 같은 화면의 내 PC에서 시작하기 → MCP로 연결하기 → 로컬 MCP 받기를 누릅니다. 다운로드 버튼은 확장 프로그램 안내 아래에 항상 표시됩니다. 번호가 붙은 연결 순서는 필요할 때 펼쳐볼 수 있습니다.
  4. 받은 ZIP을 마우스 오른쪽 버튼으로 눌러 모두 압축 풀기를 선택합니다. 폴더 안에 Connect.cmd, run_mcp.py, requirements.txt가 보이는지 확인합니다.

AI가 이 폴더의 MCP를 실행하므로 이후 임의로 이동하거나 삭제하지 마세요. 다른 위치로 옮기면 AI에 등록된 경로도 수정해야 합니다.

사이트에서 받는 ZIP의 connection.json에는 해당 사이트 주소만 포함됩니다. 개인 KEY나 사번은 들어 있지 않습니다. GitHub에서 직접 받은 공통 ZIP에는 운영 주소가 없으므로, 자동 연결을 사용하려면 웹 화면에서 받으세요.

로컬 MCP는 Python 코드가 담긴 ZIP으로 제공하며 EXE 설치 파일로 자동 변환하지 않습니다. 완성된 앱·플러그인 설치 파일은 AX Workspace 탭에서 관리자가 별도로 등록해 배포합니다.

KEY 원문은 발급 직후 한 번만 표시됩니다. 재발급하면 이전 KEY는 사용할 수 없으므로, 이미 연결한 프로그램에도 새 KEY를 반영해야 합니다.

STEP 03 · AI에 최초 한 번 등록

AI가 이 MCP를 실행하도록 등록합니다.

이미 pt-ai-square가 등록되어 있다면 실행 경로가 맞는지 확인하고 다음 단계로 갑니다. 처음이라면 아래 순서대로 전용 실행 환경을 만들고 등록합니다.

Claude Code에 설치를 맡기려면

압축을 푼 MCP 폴더를 Claude Code의 작업 폴더로 열고 아래처럼 요청하세요. KEY는 요청문에 넣지 않습니다.

현재 폴더의 pt-square-mcp를 설치해줘.
run_mcp.py와 requirements.txt를 확인하고 전용 .venv에 라이브러리를 설치해줘.
등록 범위는 내 계정 / 현재 프로젝트 중 먼저 선택받아줘.
기존 MCP 설정은 유지하고 pt-ai-square로 등록한 뒤 실제 도구 연결을 확인해줘.
등록이 끝나면 connect_account로 연결 주소와 KEY 입력 안내를 보여줘.
KEY를 명령줄이나 MCP 설정 JSON에 넣지 말고, 채팅 입력은 대화·모델·도구 호출 기록에 남을 수 있다고 먼저 알려줘.

첫 설치는 Claude Code의 로컬 파일·명령 실행 도구로 진행합니다. 아직 등록되지 않은 MCP가 스스로 설치하는 것은 아닙니다. 도구가 보이지 않으면 Claude Code를 다시 시작한 뒤 “AI SQUARE 연결해줘”라고 요청하세요. 회사의 설치 권한·패키지 저장소 설정을 따릅니다.

직접 등록하려면 다음 순서를 따르세요.

① MCP 폴더에서 PowerShell 열기

파일 탐색기에서 run_mcp.py와 requirements.txt가 보이는 폴더를 엽니다. 위쪽 주소 표시줄에 powershell을 입력하고 Enter를 누르세요. 그 폴더에서 열린 PowerShell에 아래 명령을 한 줄씩 입력하고 Enter를 누릅니다.

python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt

첫 줄은 전용 실행 환경을 만들고 두 번째 줄은 공식 MCP SDK 1.30.0을 그 안에 설치합니다. 회사망에서는 기존 사내 Python 패키지 저장소를 사용하세요. MCP 등록에는 KEY가 필요하지 않습니다. 등록 후 채팅에서 개인 KEY를 연결합니다.

② Claude Code에 등록하기

같은 PowerShell 창에서 아래 두 줄을 실행하면 현재 MCP의 전체 경로를 기억합니다. 경로를 직접 타이핑하지 않아도 됩니다.

$mcpPythonPath = (Resolve-Path -LiteralPath '.\.venv\Scripts\python.exe').Path
$mcpScriptPath = (Resolve-Path -LiteralPath '.\run_mcp.py').Path

등록 범위를 선택하고 아래 두 방법 중 하나만 실행하세요.

내 계정에서 여러 업무에 사용하려면 같은 PowerShell에서 실행합니다.

claude mcp add --transport stdio --scope user pt-ai-square -- "$mcpPythonPath" "$mcpScriptPath" serve

특정 업무 폴더에서만 사용하려면 아래 경로를 실제 업무 폴더로 바꾼 뒤 실행합니다. 경로를 기억시킨 같은 PowerShell 창에서 진행하세요.

Set-Location -LiteralPath 'C:\실제업무폴더'
claude mcp add --transport stdio --scope project pt-ai-square -- "$mcpPythonPath" "$mcpScriptPath" serve

성공 메시지가 나오면 Claude Code를 다시 시작합니다. 이미 등록되었다고 나오면 중복 추가나 삭제부터 하지 말고 claude mcp get pt-ai-square로 실행 경로를 확인하세요. Claude Code 공식 MCP 등록 안내

다른 로컬 MCP 지원 프로그램을 사용하는 경우

해당 프로그램의 MCP 설정 화면 또는 파일에 이름 pt-ai-square, 실행 프로그램 .venv\Scripts\python.exe의 전체 경로, 인자 run_mcp.py의 전체 경로와 serve를 입력합니다. JSON 설정을 받는 프로그램은 아래 형식을 참고하되 해당 앱의 규칙을 따르세요. 예시 경로는 실제 압축 해제한 절대 경로로 바꾸고 기존 MCP 항목은 유지합니다.

{
  "mcpServers": {
    "pt-ai-square": {
      "command": "C:\\Users\\내계정\\Tools\\pt-square-mcp\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\내계정\\Tools\\pt-square-mcp\\run_mcp.py", "serve"]
    }
  }
}

KEY는 위 JSON에 넣지 않습니다. 웹 대화창에 이 JSON을 붙여넣는 것으로 등록되지는 않습니다. 설정을 저장하고 AI 프로그램을 다시 시작합니다.

STEP 04 · 채팅에서 KEY 연결

“AI SQUARE 연결해줘”라고 요청하세요.

이 안내는 MCP 1.6.0 이상과 최신 웹 서버 기준입니다. KEY 연결·폴더 선택·도구 등록은 채팅에서 진행합니다. 예전 MCP는 최신 ZIP의 파일로 기존 실행 폴더를 갱신하고 AI 프로그램을 다시 시작하세요. 웹 서버만 업데이트해도 이미 설치한 MCP 코드는 바뀌지 않습니다. 기존 .venv와 개인 설정은 보존하며 MCP SDK는 기존 1.30.0을 사용합니다.

  1. Claude Code에 “AI SQUARE 연결해줘”라고 요청합니다. AI가 connect_account를 호출해 연결할 사이트와 KEY 입력 안내를 보여줍니다.
  2. 사이트가 맞는지 확인하고 웹에서 발급한 개인 KEY를 채팅으로 전달합니다. AI가 이를 도구의 key 인자로 전달하므로 별도 프로그램이나 입력창을 열 필요가 없습니다.
  3. HTTP 사이트는 표시된 정확한 주소로 KEY가 암호화되지 않고 전송되는 것에 동의해야 합니다. 지원하는 AI에서는 채팅 안의 확인 질문(HITL), 미지원 AI에서는 일반 채팅으로 동의를 받습니다. AI는 실제 동의한 주소만 accept_http_origin으로 전달합니다. 이미 동의하여 저장된 같은 주소는 다시 확인하지 않습니다.
  4. 실제 서버 인증에 성공하면 AI가 본인 이름·부서와 연결 결과를 알려줍니다. 잘못된 KEY나 접속 실패는 연결 완료로 처리하지 않으며 기존 정상 설정을 유지합니다.

채팅 입력은 비밀 입력창이 아닙니다. KEY가 대화 내용·모델 입력·도구 호출 입력 기록에 남을 수 있습니다. MCP는 KEY를 결과나 오류 메시지에 다시 출력하지 않지만, 로컬 암호화 저장이 채팅 기록을 삭제하지는 않습니다.

KEY를 일반 MCP 폼 elicitation으로 요청하지 않습니다. 호스트 확인 기능(HITL)은 HTTP 연결 동의나 폴더 경로처럼 비밀이 아닌 내용만 확인합니다. HTTP 동의는 전송 암호화를 제공하지 않고 회사 웹 주소·포트·SSO 방식도 바꾸지 않습니다.

KEY는 실제 인증 성공 후 Windows의 현재 사용자 계정에 묶인 DPAPI로 암호화해 보관합니다. 실행 명령줄이나 MCP 설정 JSON에는 KEY를 넣지 않습니다.

STEP 05 · 실제 연결 확인

내 계정으로 연결되었는지 확인합니다.

AI 대화창에 “AI SQUARE의 connection_status를 실행해서 내 계정 연결 상태를 확인해줘”라고 요청하세요. 실제 도구 호출 결과에 본인 계정·부서·허용 작업이 표시되면 사용할 준비가 끝납니다. 이미 연결을 마쳤다면 KEY를 다시 보내지 않아도 됩니다.

Claude의 Connected는 로컬 MCP와 통신한다는 뜻입니다. AI SQUARE 계정 연결은 실제 서버 인증까지 확인해야 합니다. connection_status나 connect_account 도구를 찾지 못하면 3번의 MCP 등록과 AI 프로그램 재시작을 확인하세요. 인증 오류가 나오면 아래 KEY 재연결 안내를 따릅니다.

이제 “회의록 요약 도구 찾아줘” 또는 “첫 번째 도구를 받아줘”라고 요청해보세요. 다운로드 결과에 실제 저장 경로가 표시됩니다.

연결 후에는 이렇게 요청하세요.

하고 싶은 일요청 예시와 동작
검색·추천“메일 조회 도구 추천해줘.” 이름·등록자·담당자·태그·설명·업무를 검색하고, 제공되는 부서 선호 정보를 추천 근거로 안내합니다. “김하늘님이 등록한 도구 찾아줘”처럼 요청할 수도 있습니다. 실제 등록자는 현재 플랫폼 계정 이름을 기준으로 찾으며 접근 권한은 그대로입니다.
파일 받기“첫 번째 도구를 받아줘.” 자동 다운로드 폴더에 받고 저장 경로를 알려줍니다. 이 단계에서 파일을 실행하지 않습니다.
설치“이 Skill을 현재 프로젝트에 설치해줘.” 설치 범위·경로·변경 내용을 확인하고 진행합니다. 지원하는 설치 정보가 있는 항목만 자동 설치할 수 있습니다.
신규 등록“이 폴더의 Skill을 공통 업무에 새 도구로 전체 공개 등록해줘.” 원본·설명·흐름과 분류를 확인하고 채팅에서 게시까지 진행합니다. 대상·공개 범위가 이미 명확하면 다시 승인받지 않습니다.
새 버전“도구 ID 123을 이 새 ZIP으로 업데이트하고 공개 범위는 유지해줘.”처럼 본인 도구를 지정합니다. 번호를 모르면 후보에서 선택하세요. ZIP의 packageId가 달라도 최초 플랫폼 ID를 유지하며 같은 도구에 새 배포 번호가 생깁니다. 별도 웹 승인 없이 진행합니다.
URL 연결형 등록사내 API·MCP도 http://mcp.example.internal:8080/mcp처럼 HTTP 또는 HTTPS 주소와 연결 안내로 등록할 수 있습니다. 필요한 포트·경로를 포함하고 주소에 아이디·비밀번호·개인 KEY를 넣지 않습니다. 게시 대상과 공개 범위를 채팅에서 정합니다.
버전 확인“설치한 도구가 최신인지 확인해줘.” 버전만 확인하고 PC 파일을 자동으로 교체하지 않습니다.
KEY 다시 연결“AI SQUARE KEY 다시 연결해줘.” 현재 서버 주소와 채팅 기록 안내를 확인한 뒤 새 KEY를 전달합니다. 실제 계정 인증 결과로 연결을 확인합니다.

다운로드는 웹·MCP를 합쳐 사번·도구당 최초 1회만 집계합니다. 반복 수신과 업데이트는 추가 집계하지 않습니다. 기존 업로드 파일은 그대로 검색·다운로드할 수 있고, 자동 설치는 설치 정보가 등록된 항목에 한해 지원합니다.

MCP 등록은 채팅에서 완료합니다. AI가 초안의 대상·내용·공개 범위를 요청과 대조하고 게시합니다. 이미 명확한 등록 요청을 다시 승인받거나 웹 승인 화면을 필수로 열지 않습니다. 필요한 정보가 없거나 준비한 내용이 달라졌을 때만 채팅으로 확인합니다. 웹에서 먼저 검토하는 방식도 원하면 사용할 수 있습니다.

URL 연결형은 주소와 사용 안내를 공유합니다. 등록만으로 해당 원격 서버를 호출하거나 AI 프로그램에 원격 MCP 설정을 추가하지 않습니다. 실제 연결은 등록자의 안내와 사용하는 프로그램의 지원 방식을 따릅니다. 이 항목의 주소와 AI SQUARE 개인 KEY를 연결하는 사이트 주소는 별개이며, 플랫폼 KEY의 HTTP 연결 확인 규칙은 그대로입니다.

업데이트할 ZIP의 식별자를 직접 고칠 필요가 없습니다. 플랫폼은 기존 도구 ID와 최초 정상 packageId를 유지하고, 새 파일의 식별자는 원본 정보로 따로 기록합니다. ZIP을 다시 압축하거나 내부 내용을 바꾸지 않습니다. 이름이 비슷한 항목을 임의로 덮어쓰지 않으며, 설치 위치·실행 파일이 달라졌다면 새 설치 정보를 확인합니다.

AUTOMATIC DOWNLOADS

받은 파일은 여기에서 확인합니다.

C:\Users\내계정\AI_SQUARE\downloads\
└─ server-서버식별자\
   └─ tool-123\
      ├─ v1\
      └─ v2\

계정 이름은 자동으로 인식합니다. 폴더는 필요할 때 생성하고 서버·도구·버전별로 나누어 저장합니다. 로컬 시험 사이트와 운영 사이트에 같은 도구 번호가 있어도 파일이 섞이지 않습니다. 다운로드 결과에 실제 저장 경로가 표시됩니다.

다운로드 위치는 받은 파일을 보관하는 곳이고, 설치 위치는 AI가 그 기능을 사용하는 곳입니다. 파일은 위의 자동 폴더에 받고, 실제 설치 위치는 아래 세 가지 중에서 선택합니다. 다운로드만으로 설치하거나 실행하지 않습니다.

INSTALL LOCATION

어디에서 사용할지 선택하세요.

  1. AI에게 “이 Skill을 설치해줘”라고 요청합니다. 확인된 현재 프로젝트가 하나이면 그 경로가 기본 후보로 표시됩니다.
  2. 공통 (내 계정)은 이 PC의 내 계정에서 여러 프로젝트에 사용할 때, 현재 프로젝트는 지금 작업 중인 폴더에만 설치할 때 선택합니다. 기타 경로는 원하는 다른 프로젝트의 전체 경로를 채팅에 입력합니다.
  3. 프로젝트를 확인할 수 없거나 후보가 여러 개이면 AI가 채팅에서 경로를 묻습니다. MCP가 실행된 폴더를 현재 프로젝트라고 임의로 정하지 않습니다.
  4. 표시된 전체 경로·접근 목적을 확인합니다. 지원하는 AI는 비밀정보가 없는 확인 질문을, 미지원 AI는 채팅 답변을 사용합니다. 별도 Windows 폴더 선택 창은 열지 않으며 취소하면 접근 범위를 추가하지 않습니다.
  5. 이어서 준비안의 설치 범위·실제 경로·변경할 파일·실행할 명령을 확인하고 설치를 승인합니다. 폴더 접근 확인과 설치 승인은 별도입니다.

공통 (내 계정)은 다른 사람의 계정이나 PC 전체에 설치하는 뜻이 아닙니다. 기본 다운로드 폴더가 PC 전체 접근 권한을 주지도 않습니다. 받은 파일은 계속 AI_SQUARE\downloads에 자동 저장됩니다.

“이 프로젝트를 등록해줘”라고 요청할 때도 확인된 현재 프로젝트를 원본 후보로 사용합니다. 다른 원본은 채팅에서 경로를 지정하세요. 후보를 보여주는 것만으로 접근을 허용하거나 게시하지 않습니다. 대상·내용·공개 범위가 정해지면 사용자의 등록 요청에 따라 채팅에서 게시까지 완료합니다.

RECONNECT · 재설치 없이

KEY가 바뀌면 채팅에서 다시 연결하세요.

MCP에서 401 인증 오류가 발생하면 현재 연결된 서버의 KEY 발급 화면 링크와 재연결 방법을 안내합니다. 예를 들어 현재 주소가 http://회사서버:5000이면 링크는 http://회사서버:5000/local-access입니다.

  1. 안내된 링크로 회사 웹에 로그인하고 내 연결 KEY → KEY 재발급에서 새 KEY를 복사합니다. 재발급하면 이전 KEY는 사용할 수 없습니다.
  2. AI에게 “AI SQUARE KEY 다시 연결해줘”라고 요청합니다. connect_account 또는 기존 reconnect_key가 현재 연결 주소와 채팅 기록 안내를 보여줍니다.
  3. 주소가 맞는지 확인하고 새 KEY를 채팅으로 전달합니다. HTTP 주소에 아직 동의하지 않았다면 해당 정확한 주소의 비암호화 연결 동의를 먼저 확인합니다.
  4. 본인 이름·부서가 확인되면 완료입니다. 다음 요청부터 새 KEY를 사용합니다. 계정 비활성화는 재발급으로 해결되지 않으므로 운영자에게 문의합니다.

KEY는 대화·모델·도구 호출 입력 기록에 남을 수 있습니다. 기존 설정이 있으면 현재 MCP 서버 주소를 유지하고, 최초 연결은 웹에서 받은 ZIP의 주소를 사용합니다. 별도 설정 파일을 사용하는 경우에도 실행 중인 MCP의 설정이 기준입니다.

KEY만 바뀐 경우 MCP나 설치한 도구를 재설치할 필요는 없습니다. 재연결도 별도 KEY 창 없이 채팅에서 진행합니다. MCP 코드 자체를 교체했다면 AI 프로그램을 다시 시작합니다.

재연결이 중단된 설치·업로드를 자동으로 다시 실행하지는 않습니다. 게시 초안은 생성한 KEY ID에 연결되어 있으므로 재발급 후에는 새 초안을 준비합니다. 새 내용이 기존 요청과 같은지 대조하고, 달라진 사항이 있을 때 채팅에서 확인합니다. 이미 게시한 도구·버전과 PC의 설치 파일은 유지됩니다.

연결 안내와 문제 해결

Connect.cmd는 채팅 연결 방법을 안내하는 파일입니다. 실행해도 KEY 입력창을 열거나 KEY를 받지 않습니다. 처음 한 번 MCP를 등록한 뒤 AI 채팅에서 연결을 요청하세요.

아직 KEY 창이나 폴더 창이 열립니다.

이전 MCP가 실행 중일 수 있습니다. 최신 ZIP의 파일을 AI에 등록된 실제 MCP 폴더에 반영하고 AI 프로그램을 완전히 종료한 뒤 다시 실행하세요. 기존 .venv와 개인 설정은 보존합니다. 웹 서버만 업데이트해도 PC에 설치된 MCP 코드가 자동 교체되지는 않습니다.

KEY를 재발급했습니다.

AI에게 “AI SQUARE KEY 다시 연결해줘”라고 요청하고 현재 주소·채팅 기록 안내를 확인한 뒤 새 KEY를 전달합니다. 현재 서버 인증에 성공하면 다음 요청부터 새 KEY를 사용합니다. KEY만 갱신하면 재설치가 필요 없지만, MCP 코드 자체를 업데이트한 경우에는 AI 프로그램을 다시 시작합니다.

서버 주소가 없다고 나옵니다.

웹의 로컬 MCP 받기에서 최신 ZIP을 받으세요. GitHub 공통 ZIP 또는 예전 ZIP에는 사이트 주소가 없을 수 있습니다. 개발자용 환경변수 연결에서만 setup --token-from-env --url "http://회사서버주소"을 사용하며 HTTP이면 정확한 주소의 --accept-http-origin도 필요합니다.

401 / 403 / 409 / 서버 접속 오류는 어떻게 다른가요?

401: KEY 만료·취소·재발급 또는 사용자 비활성화 등으로 인증할 수 없습니다. 안내된 현재 사이트의 KEY 링크를 확인하고 필요하면 새 KEY로 연결합니다. 계정 비활성화는 운영자에게 문의합니다.
403: 해당 도구 조회 권한·본인 소유 여부·최신 웹 서버 여부를 확인합니다. 기존 유효한 읽기 KEY도 본인 도구 게시를 허용하지만 타인 도구나 관리 권한은 생기지 않습니다.
409: 초안의 확인 값·내용 일치 여부·만료·버전 충돌을 확인합니다. 같은 KEY로 통신을 재시도할 때는 기존 초안 상태부터 확인하고, KEY를 재발급했다면 새 초안을 준비합니다. 구버전 서버가 웹 승인을 요구하면 최신 웹 서버와 MCP 1.6.0 이상을 함께 반영합니다.
접속 실패·5xx: 사내망·서버 상태를 확인합니다. 이 오류만으로 KEY가 만료되었다고 판단하지 않습니다. 저장 요청이었다면 반영 여부를 먼저 확인합니다.

고급 설정: 환경변수로 연결하는 자동화 환경

setup --token-from-env는 이미 안전하게 설정된 PTAI_API_TOKEN을 매번 읽는 방식이며 KEY를 저장하지 않습니다. KEY를 명령줄에 넣지 않습니다. 필요한 경우에만 --url과 기존 폴더의 --workspace를 사용하고, HTTP는 사용자에게 확인한 정확한 --accept-http-origin을 지정합니다. 생략해도 별도 입력창으로 전환하지 않습니다.

이 방식을 계속 쓴다면 재발급 후 환경변수를 갱신하고 AI 프로그램을 다시 시작합니다. 일반 Windows 사용자는 채팅 연결의 DPAPI 암호화 저장을 사용하며, 원본·설치 폴더도 채팅에서 확인합니다.

운영자가 반영할 내용

기존 runtime_config.py, 업로드 저장소와 MongoDB 데이터는 그대로 유지합니다. 이번 변경으로 KEY를 일괄 재발급하거나 DB를 초기화하지 않습니다. 회사의 index.py·web_main.py 진입점과 포트도 유지합니다.

웹의 MCP 다운로드 처리, KEY 화면, MCP 원본·ZIP과 가이드를 함께 반영하고 웹을 재시작합니다. 새 ZIP을 웹에서 받아 connection.json에 실제 접속 주소가 들어 있는지 확인한 뒤 KEY 연결을 시험합니다. 웹 서버에는 MCP SDK를 추가로 설치할 필요가 없습니다.

웹은 KEY·사번·쿠키를 ZIP에 넣지 않습니다. PC는 웹 API로만 검색·다운로드·본인 도구 게시를 요청하며 MongoDB 주소나 계정을 받지 않습니다. 유효한 개인 KEY는 기존 읽기 KEY까지 본인 도구 신규 등록·새 버전 게시를 허용하며 재발급은 필요 없습니다. 인식하지 못하는 권한 값이나 무효 KEY는 거절합니다. 관리자 KEY도 타인 도구 수정·삭제·관리 설정은 할 수 없습니다. 채팅 게시에는 최신 웹 서버도 필요하며 서버는 같은 KEY·소유권·초안 내용·파일 해시·버전 충돌을 검사합니다. 클라이언트의 확인 표시는 사람이 실제로 확인했다는 독립적인 증명은 아닙니다. STORE·독립 CLI의 기존 웹 검토 방식은 유지됩니다.

정확한 설치 선언과 고급 사용법은 ZIP 안 README.md를 참고하세요. 실제 사내 네트워크·SSO·개별 설치 프로그램 동작은 운영 환경에서 확인합니다.
