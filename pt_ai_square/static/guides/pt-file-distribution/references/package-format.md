# 웹에서 읽는 배포 정보 v1

`assets/ai-square.example.json`을 실제 프로젝트에 맞게 채우고 ZIP 최상위에 `ai-square.json`으로 넣는다. 상위 폴더로 한 번 더 감싸지 않는다. 웹과 `scripts/prepare_package.py`가 같은 `package_contract.py` 규칙을 사용한다.

| 항목 | 규칙 |
|---|---|
| schemaVersion | 숫자 1 |
| packageId | 3~80자, 영문 소문자 시작, 소문자·숫자·점·하이픈. 같은 도구의 다음 버전도 유지 |
| name / desc | 도구 이름 50자 / 한 줄 소개 200자 |
| platform | Claude / ChatGPT / 기타 |
| type | MCP/Tool / Skill / 플러그인/하네스 |
| entryPoint | 시작 파일의 ZIP 내부 상대 경로. Skill은 SKILL.md, Python MCP는 실제 시작 스크립트 등 |
| guideFile | UTF-8 설치 안내 파일 경로. 최대 40KB, 내용 1~10000자 |
| requiredFiles | 필요한 파일 경로 목록, 최대 100개. 시작 파일과 안내 파일도 항상 검사 |
| requirements | 사용자에게 알릴 의존성·권한·설치 조건, 최대 20개·각 200자. 설치 명령으로 실행하지 않음 |
| workTags | 선택, 최대 8개·각 30자 |
| environment / changes | 선택, 환경 200자 / 변경 설명 2000자 |
| workflow | 선택, `steps`만 가진 객체. 단계 1~8개, 각 `title` 필수 60자 / `description` 선택 240자 |

경로는 `/` 구분자를 사용한다. 절대 경로, `..`, 빈 파일, 누락 파일, 중복 경로·중복 JSON 키, 알 수 없는 항목은 거절된다. guideFile 내용은 설치 안내 입력란으로 가져온다. 이름·설명·안내는 웹에서 검토하고 수정할 수 있다. 프로그램·유형은 ZIP과 일치해야 한다. 조직·업무 분야·담당자·권한은 웹에서 선택하며 패키지로 권한을 지정하지 않는다.

toolId·release·버전 확인 URL은 입력하지 않는다. 게시 후 웹에서 발급한 별도 배포 정보 JSON에 들어간다. 원본 ZIP은 서버에서 수정하지 않는다. JSON의 상대 URL은 사용자가 접속한 플랫폼 주소 기준이며 인증이 필요하다. 실행 파일에 버전 확인 코드를 넣거나 SSO 인증을 연결하는 작업은 자동 완료되지 않는다.

배포 정보가 없는 기존 ZIP·EXE·MSI·PS1·MD도 일반 등록을 유지한다. 웹에서 선언을 읽지 못하면 경고를 표시하고 수동 정보로 게시를 허용한다. 새 버전도 동일하다. 정상적으로 읽은 선언의 packageId는 기존 도구와 일치해야 한다. prepare_package.py는 제작 중 실수를 찾도록 잘못된 ZIP 선언을 계속 오류로 처리한다. ZIP 자체의 손상·안전하지 않은 경로는 웹에서도 차단한다. 선언은 코드의 실제 동작·호환성·보안 검증을 대신하지 않는다.

단일 MD는 별도 ZIP 선언 없이 원본 파일로 배포한다. 터미널 명령어와 URL은 파일을 만들지 않고 웹에서 각각 등록한다. 명령어는 프로젝트용·내 계정 전역용을 나누어 입력하며 배포 버전별로 저장된다. 설치 범위와 실제 대상 경로는 사용자가 먼저 선택하도록 안내한다.

## 동작 흐름 표시

실제 코드·지침에서 확인한 업무 흐름을 순서대로 기록한다. 예를 들어 입력 받기 → 데이터 정리 → 결과 확인이다. 서버는 이 텍스트를 도식으로 보여주며 코드를 실행하거나 문서를 LLM으로 분석하지 않는다. 근거가 없는 단계, 확인하지 않은 자동화·승인·보안 검사는 넣지 않는다. 의미가 불분명하면 작성자에게 확인하거나 workflow를 생략한다.

```json
{
  "workflow": {
    "steps": [
      {"title": "자료 입력", "description": "사용자가 분석할 자료를 선택합니다."},
      {"title": "결과 정리", "description": "도구가 지원하는 규칙으로 결과를 만듭니다."},
      {"title": "사용자 확인", "description": "결과를 검토하고 저장합니다."}
    ]
  }
}
```

제목·설명은 일반 텍스트다. HTML·Mermaid처럼 보이는 문자열도 코드로 해석하지 않는다. 실행 스크립트·URL 같은 별도 노드 속성은 받지 않는다. 복잡한 분기를 이 순서형 도식으로 왜곡하지 말고 핵심 단계만 적고 상세 조건은 설치·사용 안내에 설명한다. 흐름은 배포 버전별로 저장된다. 새 버전의 ZIP 선언이 흐름을 생략하면 이전 버전의 흐름을 재사용하지 않으며, 이전 버전으로 복구하면 그 버전의 흐름을 다시 표시한다. 승인형 도구는 조회 권한을 가진 사람만 흐름을 볼 수 있다.

단일 MD·URL·명령어를 자동 게시할 때도 `--metadata` JSON에 같은 `workflow` 구조를 넣을 수 있다. 흐름을 넣기 위해 MD를 ZIP으로 바꿀 필요가 없다. 일반 웹 수동 등록은 흐름이 없어도 정상적으로 게시된다.
