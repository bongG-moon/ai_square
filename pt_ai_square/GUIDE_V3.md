# P&T AI SQUARE v3.2 — 실행과 사용 안내

이 문서는 MongoDB 전용 구현을 기준으로 합니다. 이전 v2 기획서의 SQLite·혼합 저장, 조직별 목록 숨김, 통합 운영 관리 설명은 이 문서와 상세 기획서 v3로 대체합니다.

## 1. 무엇이 달라졌나요?

- **등록 관리**는 모두에게 보입니다. 들어가면 자기 계정으로 등록한 기능만 나옵니다. 관리자도 다른 사람의 기능은 별도 **관리자 → 전체 기능**에서 확인합니다.
- 조직·업무 메뉴는 검색과 키보드 조작을 지원하는 선택창으로 바뀌었습니다.
- **관리자 → 조직·업무**에서 선택지를 추가·변경·사용 중지합니다. 검색·등록·수정 화면에 반영됩니다.
- 승인형 기능도 목록에는 이름·한 줄 소개·유형·조직·업무가 표시됩니다. 상세를 열면 **조회 권한이 필요합니다** 팝업이 나오고 신청할 수 있습니다.
- **등록 관리 → 권한 관리**에 신청 대기와 승인된 사용자를 분리했습니다. 승인·반려·회수와 직접 사용자 추가를 지원합니다.
- 기능 상세의 **의견**에서 피드백을 남깁니다. 등록자·관리자는 답변과 처리 상태를 남깁니다.
- **기능 요청**에서 새 기능을 제안하고, 개발자가 접수해 개발 중·구현 완료로 바꾸고 등록된 기능을 연결합니다.
- 오른쪽 위 **종 모양**이 개인 알림입니다. 읽음·안읽음, 모두 읽음, 이전 알림 더 보기를 지원합니다.
- 모든 서비스 정보는 **MongoDB**에 저장합니다. ZIP·EXE·MSI·PS1 원본 파일만 서버의 `DATA_DIR/artifacts` 폴더에 저장합니다.

## 2. 내 PC에서 SSO 없이 실행하기

### 처음 한 번: Python 라이브러리 설치

프로젝트의 상위 폴더, 즉 `pt_ai_square` 폴더가 보이는 위치에서 터미널을 엽니다.

```powershell
python -m venv .venv-square
.venv-square\Scripts\python.exe -m pip install -r pt_ai_square\requirements.txt
```

### 먼저 화면만 둘러보고 싶다면

설정 파일 없이 `.venv-square\Scripts\python.exe -m pt_ai_square run`을 실행하고 브라우저에서 `http://127.0.0.1:5080/`을 엽니다. 이미 설정 파일이 있다면 그 파일의 `MONGODB_URI = ''`로 비우고 서버를 재시작합니다. 프로세스 환경변수에 URI가 설정되어 있으면 그 값이 우선이므로 함께 확인합니다.

상단에 **화면 체험 모드 / 데모 · 저장 안 됨**이 표시됩니다. `pt_ai_square/demo/catalog.json`에 있는 가상의 도구 10개로 순위·검색·상세·등록 양식·관리 화면을 볼 수 있습니다. 예시 좋아요와 다운로드 수는 실제 사용 이력이 아닙니다. 등록·수정·좋아요·권한 변경·파일 다운로드를 시도하면 MongoDB 연결이 필요하다는 안내가 나옵니다. 더미 데이터는 운영 DB로 자동 복사되지 않습니다.

### 실제 등록을 위한 MongoDB 준비

이미 켜져 있는 로컬 MongoDB가 있다면 그대로 사용합니다. 이 PC에서 검증한 주소는 `mongodb://127.0.0.1:27018/`입니다.

기존에 공식 MongoDB 압축 파일을 `.local-mongo/server`에 풀어둔 이 PC에서는 다음 스크립트로 시작할 수 있습니다.

```powershell
powershell -File pt_ai_square\start_local_mongo.ps1
```

앱에는 MongoDB 실행 파일이 포함되지 않습니다. 실제 등록·저장을 하려면 MongoDB 서버를 별도로 준비하거나 회사 서버 주소를 입력해야 합니다. 주소를 입력했는데 연결이 실패하면 오류로 중단합니다. 운영 장애를 체험 화면으로 숨기지 않습니다.

### 설정 파일 작성

`pt_ai_square/runtime_config.example.py`를 복사해 같은 폴더에 **runtime_config.py**라는 이름으로 저장합니다. 기존 파일이 있으면 덮어쓰지 말고 필요한 값만 수정합니다.

로컬에서 실제 등록·버전 관리를 검증하는 예시:

```python
PTAI_AUTH_MODE = 'mock'
PTAI_MOCK_USER = '1000001'
PTAI_MOCK_NAME = '개발 사용자'
PTAI_MOCK_ADMIN = True
PTAI_ADMIN_IDS = '1000001'
PTAI_COOKIE_SECURE = False
PTAI_HOST = '127.0.0.1'
PTAI_PORT = 5080
MONGODB_URI = 'mongodb://127.0.0.1:27018/'
MONGODB_DATABASE = 'pt_ai_square'
PTAI_MONGODB_TIMEOUT_MS = 3000
```

`mock`은 설정한 사번으로 이 PC에서 실제 저장 기능을 시험하는 인증입니다. 회사 운영에서는 `sso`를 사용하세요. `PTAI_MOCK_ADMIN=True`이면 설정한 체험 계정이 기본 관리자가 됩니다.

설정 적용 순서는 **실제 프로세스 환경변수 → runtime_config.py → 기본값**입니다. `.env` 파일은 읽지 않습니다. 예전 `PTAI_ACTIVITY_BACKEND` 값은 저장 방식을 바꾸지 않으며 모든 데이터는 MongoDB에 저장됩니다.

### 실행

VS Code에서 `pt_ai_square/web_main.py`를 열고 **Python 파일 실행**을 눌러도 됩니다. 또는 `pt_ai_square` 폴더 안에서 `python web_main.py`를 실행하세요. 직접 실행과 아래 모듈 실행은 같은 설정·Waitress 서버를 사용합니다. 운영 WSGI 서버에서 `pt_ai_square.web_main:app`으로 불러오는 방식도 유지합니다.

```powershell
.venv-square\Scripts\python.exe -m pt_ai_square run
```

브라우저에서 **http://127.0.0.1:5080/** 을 엽니다. 또는 `pt_ai_square/run_server.cmd`를 더블클릭합니다. 창을 종료하거나 Ctrl+C를 누르면 웹 서버가 멈춥니다. MongoDB와 웹 서버는 서로 다른 프로세스입니다.

설정 파일을 바꿨다면 웹 서버를 종료한 뒤 다시 실행해야 합니다. 웹 화면에서 조직·업무·추가 관리자를 바꾼 것은 서버 재시작 없이 반영됩니다.

`attempted relative import with no known parent package`가 나오면 이전 web_main.py 파일입니다. 최신 소스로 갱신하거나, `pt_ai_square` 폴더의 **상위 폴더**로 이동한 뒤 `python -m pt_ai_square run`을 실행하세요. import 한 줄만 바꾸는 것으로는 서버가 시작되지 않을 수 있으므로 최신 실행 파일 전체를 사용하세요.

## 3. 설정한 사번으로 mock 시험하기

로그인 모드는 **sso / mock 두 가지**입니다. 별도 아이디·비밀번호 로그인과 create-user 명령은 제거했습니다. 예전 설정이 `PTAI_AUTH_MODE = 'local'`이면 `mock` 또는 `sso`로 바꿔야 합니다.

설정 파일의 다음 값으로 시험합니다. 사번은 앞의 0이 사라지지 않게 따옴표로 감싼 문자열로 적습니다.

```python
PTAI_AUTH_MODE = 'mock'
PTAI_MOCK_USER = '1000001'
PTAI_MOCK_NAME = '시험 등록자'
PTAI_MOCK_ADMIN = False
PTAI_ADMIN_IDS = '1000001'
MONGODB_URI = 'mongodb://127.0.0.1:27018/'
MONGODB_DATABASE = 'pt_ai_square'
```

1. 서버를 시작하고 브라우저로 접속합니다. 비밀번호 입력 없이 설정한 사번으로 동작합니다. 처음 쓰는 사번이면 사용자 정보가 MongoDB에 만들어집니다.
2. 상단 **도구 등록**에서 ZIP과 설명을 입력하고 **게시**합니다. v1과 등록자 사번이 실제로 저장됩니다. 담당자 표시 이름을 다르게 적어도 등록자는 설정한 사번입니다.
3. **등록 관리 → 버전 → 새 버전 등록**에서 바뀐 ZIP을 게시합니다. v2가 생성되고 내려받으면 새 파일이 제공됩니다.
4. **이전 버전으로 복구**를 선택하면 웹의 현재 배포가 v1로 돌아가고 철회된 v2 다운로드는 중단됩니다.
5. 서버를 종료하고 다시 켜도 같은 MongoDB와 파일 저장 경로를 쓰면 등록 정보·버전·파일·이력이 유지됩니다.
6. 다른 사용자를 시험하려면 `PTAI_MOCK_USER = '2000001'`로 바꾸고 재시작합니다. `PTAI_MOCK_ADMIN = False`를 유지하고 기본 관리자 목록에는 새 사번을 추가하지 않습니다. 이전 사번의 기능을 임의로 수정·삭제할 수 없고, 승인형 기능은 조회 권한을 신청해야 합니다.

`mock`과 `sso`는 사용자 확인 방법만 다르고 업로드·업데이트·승인·알림 API와 MongoDB 저장 방식은 같습니다. mock은 로컬 접속만 허용합니다. 요청에 다른 사번을 넣거나 이전 로그인 세션이 남아 있어도 설정한 사번을 대신할 수 없습니다. `PTAI_MOCK_ADMIN=True`이면 현재 mock 사번이 관리자이므로 일반 사용자 권한 시험 때는 False로 둡니다.

**MongoDB 주소를 비운 데모 화면은 별개입니다.** 실제 업로드·업데이트를 확인하려면 URI를 입력하고 MongoDB를 실행해야 합니다. mock이라는 이유로 더미 데이터를 사용하지 않습니다.

## 4. 회사 운영환경에 넣을 값

| 설정 | 의미 | 예시 또는 입력 기준 |
|---|---|---|
| `MONGODB_URI` | MongoDB 연결 주소 | 회사에서 제공하는 URI. 인증이 필요한 경우 계정·인증 DB 포함 |
| `MONGODB_DATABASE` | 서비스 데이터베이스 이름 | `pt_ai_square` |
| `PTAI_ADMIN_IDS` | 기본 관리자 계정 ID | `'사번1,사번2'` |
| `PTAI_AUTH_MODE` | 인증 방식 | `sso` 또는 `mock` (mock은 로컬 시험) |
| `PTAI_SECRET_KEY` | 웹 세션 서명 키 | 회사에서 지정 가능. 비워두면 MongoDB에 최초 생성·보관 |
| `PTAI_DATA_DIR` | 업로드 파일 저장 경로 | 예: `r'D:\pt_ai_square_data'` |
| `PTAI_HOST` / `PTAI_PORT` | 웹 서버 바인딩 주소·포트 | 회사 배포환경에 맞게 입력 |
| `PTAI_COOKIE_SECURE` | HTTPS에서만 쿠키 전송 | 운영 HTTPS에서는 `True` |
| `PTAI_SESSION_COOKIE_NAME` | 로그인 쿠키 이름 | 기본 `pt_ai_square_session`. 같은 호스트에 별도 시험판을 실행하면 다른 이름 사용 |
| `PTAI_MAX_UPLOAD_MB` | 한 번에 올릴 수 있는 파일 크기 | 기본 128 MB |
| `PTAI_STORAGE_QUOTA_MB` | 파일 저장 공간 한도 | 기본 5120 MB |

SSO는 기존 Flask Portal과 같은 `hcputil.auth.sso.SSO` 인터페이스를 사용합니다. 모듈 설치와 회사 프록시·쿠키 전달 설정이 필요합니다. 인증 실패 시 다른 인증 모드로 자동 전환하지 않습니다. 현재 검증은 SSO 인터페이스 대역으로 수행했으며 실제 사내 SSO 접속은 별도 확인이 필요합니다.

회사 기본 `web_main.py` 포맷과의 대응은 배포 폴더의 `HCP_DEPLOYMENT.md`(회사 운영 배포 안내)를 확인하세요. `web_main:app`으로 불러오는 Flask 앱에 홈과 `/login`, `/login/<경로>`가 등록되어 있습니다. SSO 주석을 해제하는 대신 `PTAI_AUTH_MODE='sso'`를 지정합니다. `ORIGIN` 전달과 사번·이름·부서 등 6개 세션 필드 및 `logFlag`를 사용합니다.

비밀번호가 포함된 URI나 세션 키를 공유 문서·Git에 넣지 마세요. `runtime_config.py`는 배포 ZIP에서 제외됩니다.

## 5. 권한 신청부터 승인까지 따라 하기

1. 등록자가 **도구 등록**에서 **상세 내용을 보려면 등록자·관리자 승인이 필요합니다**를 체크하고 게시합니다.
2. 일반 사용자는 둘러보기에서 해당 카드를 볼 수 있습니다.
3. 카드를 누르면 조회 권한 안내가 나타납니다. **조회 권한 신청**을 눌러 사용 목적을 적습니다.
4. 등록자와 관리자의 개인 알림에 신청 소식이 도착합니다.
5. 등록자는 **등록 관리 → 권한 관리 → 대기**에서 **승인** 또는 **반려**를 누릅니다.
6. 신청자는 개인 알림에서 결과를 확인하고 기능을 엽니다.
7. 필요가 끝나면 등록자가 **승인됨 → 권한 회수**를 눌러 사유를 남깁니다. 이후 상세·파일·의견 접근이 차단됩니다.

등록 관리 목록의 **권한** 버튼은 사용자를 직접 추가하는 기능입니다. 이름 또는 사번을 검색하고 조회 승인을 누릅니다. 먼저 사이트에 한 번 로그인한 사용자가 검색됩니다. 원본 문서·데이터 시스템의 권한은 별도로 관리합니다.

## 6. 피드백과 기능 요청

기존 기능의 문제·개선은 상세 팝업의 **의견**에 작성합니다. 등록자·관리자는 **답변·상태 변경**에서 접수 / 검토 중 / 반영 중 / 반영 완료 / 보류를 선택합니다. 의견 작성자도 후속 답변을 남길 수 있습니다.

아직 없는 기능은 **기능 요청 → 새 기능 요청**에서 작성합니다. 개발자가 **제가 구현할게요**를 누르면 담당자가 지정됩니다. 담당자는 **개발 중**으로 바꾸고 진행 상황을 남깁니다. **구현 완료**를 선택할 때는 실제 등록된 기능을 함께 선택해야 합니다. 다른 사람이 먼저 접수하면 중복 접수를 막고 새로고침을 안내합니다.

현재 예제 요청은 화면 흐름을 확인하기 위한 자료입니다. 예제에 표시된 개발 상태가 실제 업무 기능의 구현을 의미하지는 않습니다.

## 7. 알림은 언제 누구에게 오나요?

| 사건 | 알림 대상 |
|---|---|
| 권한 신청 | 해당 기능 등록자와 관리자 |
| 승인·반려·권한 회수·직접 승인 | 해당 사용자 |
| 새 피드백 | 해당 기능 등록자와 관리자 |
| 피드백 답변·상태 변경 | 의견 작성자, 기능 등록자, 관리자 |
| 새 기능 요청 | 관리자 |
| 개발 접수·진행 상태·답변 | 요청자, 담당자, 답변 참여자, 관리자 |
| 새 버전 게시·롤백 | 업데이트 알림을 받는 사용자 중 현재 조회 권한이 있는 사용자 |
| 추가 관리자 지정·해제 | 해당 사용자 |

내가 한 행동으로 나에게 다시 알림을 보내지는 않습니다. 다운로드·권한 승인·피드백 작성 시 해당 기능의 업데이트 알림을 자동 구독합니다. 상세 화면의 **업데이트 알림 켜짐** 버튼으로 해제할 수 있습니다. 한 줄 소개나 분류 수정만으로 버전 업데이트 알림을 보내지는 않습니다.

알림은 **웹 안의 종 모양 받은편지함**입니다. 열린 웹은 약 30초마다 새 알림 개수를 확인하고, 종 버튼을 누르면 즉시 조회합니다. 브라우저를 닫아도 MongoDB에 보관되어 다음 접속 때 볼 수 있습니다. 이메일·Teams·운영체제 푸시 알림은 포함하지 않습니다.

## 8. 기존 SQLite 자료가 있는 경우

기존 웹 서버를 먼저 종료하고, 같은 파일 저장 경로를 유지한 상태에서 다음을 실행합니다.

```powershell
.venv-square\Scripts\python.exe -m pt_ai_square migrate-legacy "pt_ai_square\.preview\square.sqlite3"
```

운영 자료는 실제 기존 `square.sqlite3` 경로를 지정합니다. 대상 MongoDB는 설정 파일의 DB입니다. 신규 DB 또는 같은 이전 작업을 재개할 때만 실행할 수 있습니다. 원본 SQLite는 읽기 전용으로 열고 그대로 보관합니다. 재실행해도 같은 자료가 중복 등록되지 않습니다. 이전이 진행 중인 DB에는 웹 요청을 허용하지 않습니다.

기능 ID·등록자·버전 번호·승인 상태·좋아요·다운로드·피드백·기존 MongoDB 사용 이력을 옮깁니다. 업로드 파일은 재업로드하지 않고 기존 경로를 사용합니다. 기존 조직 제한 기능은 승인형으로 옮기며, 승인 없이 조직 단위로 열람하던 기존 사용자 권한을 유지합니다. 새 사용자의 기존 조직 권한을 자동 부여하는 정책으로 확대하지는 않습니다.

완료 후 서버를 다시 실행하세요. **실행 중 서비스는 SQLite를 읽거나 쓰지 않습니다.** MongoDB가 중단되면 저장·조회 오류를 표시하며, 과거 권한으로 우회하지 않습니다.

## 9. 삭제·복원·파일 정리

- 기능 삭제: 등록 관리의 휴지통 아이콘 → 확인. 목록과 다운로드가 중단되며 등록자·관리자는 복원할 수 있습니다.
- 버전 복구: **버전 → 이전 버전으로 복구**. 문제가 생긴 현재 버전은 배포 중단으로 표시합니다.
- 이전 버전 파일 삭제: 현재 배포·복구용 버전은 보호합니다. 삭제된 파일은 복구할 수 없고 이력은 유지합니다.
- 보관 정책: **관리자 → 저장 공간 → 보관 정책·이전 버전 정리**. 대상 미리보기 후 삭제합니다.
- PC에 설치된 프로그램의 자동 업데이트·삭제·복구는 후속 앱 연동 범위입니다.

## 10. 소스와 검증

### 실행할 때 최신 버전만 확인하기

이용자가 도구를 실행할 때 웹에 현재 배포 번호를 물어보는 방식입니다. 예를 들어 PC의 v2와 웹의 v3를 비교해 **새 버전 v3가 있습니다**라고 안내하고 기존 도구를 계속 실행합니다. 파일을 자동 교체하지 않습니다. 서버가 v3에서 v2로 복구된 경우에도 복구 안내를 구분합니다.

등록자는 상단 **파일 배포 Skill**을 내려받아 도구를 준비할 때 **실행 시 버전 확인도 연결해줘**라고 요청합니다. Skill 안의 `scripts/version_check.py`와 `assets/VERSION_CHECK_GUIDE.md`에 연결 예제가 있습니다. 웹 게시 후 발급된 도구 ID와 배포 번호를 설치 시 로컬 설정에 기록하고 실행 때 그 번호를 비교합니다. 새 파일을 실제로 설치한 뒤에만 로컬 번호를 바꿉니다.

공통 API는 `GET /api/tools/{id}/version-check?release={설치된번호}`입니다. 이 요청은 파일을 내려받거나 사용 이력을 늘리지 않습니다. 기존 로그인·조회 권한이 적용됩니다. 실행 프로그램은 브라우저 SSO 로그인을 자동으로 공유하지 않으므로 회사에서 허용하는 인증 클라이언트를 연결해야 합니다. 로컬 mock에서는 바로 시험할 수 있습니다. 네트워크·인증 확인 실패를 최신 버전으로 표시하지 않습니다.

코드 없는 Markdown Skill에는 자동 실행 지점이 없으므로 해당 도구의 Python 코드·MCP 시작 코드·플러그인 실행 훅 등에 실제로 연결해야 동작합니다. 웹에 올린 모든 기존 도구에 저절로 적용되는 기능은 아닙니다.

주요 코드: `mongo_api.py`(업무 API), `mongo_store.py`(MongoDB 연결·권한·알림 전달), `mongo_activity.py`(활동 집계), `auth.py`(인증), `frontend_workspace.js`(새 화면), `static/workspace.css`(디자인).

화면 코드를 수정한 뒤:

```powershell
python -m pt_ai_square.build_workspace
```

테스트용 로컬 MongoDB가 실행 중일 때:

```powershell
.venv-square\Scripts\python.exe -m pytest pt_ai_square\tests -q
```

테스트는 무작위 이름의 전용 MongoDB를 만들고 해당 DB만 정리합니다. 기존 preview·운영 데이터는 건드리지 않습니다. 실행에 필요한 테스트 패키지는 `python -m pip install pytest`로 별도 설치합니다.

디자인 참고: [Linear Inbox](https://linear.app/docs/inbox)의 개인 받은편지함·관련 업무 이동 방식과 [Atlassian Select](https://atlassian.design/components/select/code/)의 검색형 선택 경험을 참고했습니다. 외부 서비스를 연결하거나 화면 라이브러리를 그대로 설치한 것은 아니며, 기존 P&T AI SQUARE 디자인에 맞춰 직접 구현했습니다.
