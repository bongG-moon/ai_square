# P&T AI Square — AX Workspace 선택 확장 연동

2026-10-25 · 확장 버전 0.1.0

## 공개 배포 ZIP과 운영자 준비 순서

- **ai-square-2026.10.25-source.zip**: 플랫폼과 확장 개발 소스입니다. 기존 운영 설정·MongoDB·업로드 저장소를 유지한 채 웹 소스를 교체합니다.
- **PNT-AI-Square-0.1.0-Distribution.zip**: 서버 주소가 없는 공개 배포 준비 묶음입니다. 확장 template과 독립 설정 도우미를 포함하며 설치 EXE가 없습니다. 운영자가 서버 주소를 지정해 만든 **PNT-AI-Square-0.1.0.axextension**을 웹의 AX Workspace 탭에 직접 등록합니다. 사용자는 완성된 확장 파일을 더블클릭하고 앱의 설치 확인창에서 설치한 뒤 개인 KEY를 입력합니다.
- **SHA256SUMS.txt**: 두 공개 배포 파일의 검증용 SHA-256입니다.

Distribution ZIP을 푼 뒤 `configure_server.py` 상단의 `SERVER_URL`을 수정하고 `python configure_server.py`를 실행하세요. 기본 출력은 `.axextension` 파일이며, 사용자는 Python을 실행하거나 압축을 풀지 않습니다. 웹은 업로드된 파일을 그대로 제공하며 주소를 자동 삽입하지 않습니다. 서버 주소를 포함한 확장 파일은 사내 공유 대상으로 보관하고 공개 GitHub에 올리지 않습니다. 기존 확장 설치 EXE 자산은 검증 가능한 ZIP 컨테이너 방식으로 대체합니다.

공통 앱의 사내 GitLab 배포에는 [workspace-local-0.23.32-source.zip](https://github.com/bongG-moon/workspace_local/releases/download/v0.23.32/workspace-local-0.23.32-source.zip)을 사용합니다. PC 설치에는 [AX Workspace 0.23.32 설치 파일](https://github.com/bongG-moon/workspace_local/releases/download/v0.23.32/AX-Workspace-0.23.32-Setup.exe)을 사용합니다. 이전 동일 버전에는 `.axextension` 파일 연결이 없을 수 있으므로 이번 Setup으로 한 번 갱신해야 합니다.

## 최신 웹 배포 정책

AX Workspace 탭은 관리자가 완성된 프로그램을 직접 등록하는 자료실입니다. 웹에 특정 확장 소개나 고정 설치 EXE를 내장하지 않습니다. 관리자는 **AX Workspace → 파일 등록**에서 완성된 파일과 설명·분류·배포 버전을 등록하고, 사용자는 해당 카드를 찾아 다운로드합니다. KEY 페이지의 **내 PC에서 시작하기**에는 위쪽 **확장 프로그램으로 연결하기**, 아래쪽 **MCP로 연결하기**가 항상 표시됩니다. 확장은 AX Workspace 탭으로 안내하고, MCP는 ZIP 다운로드와 설치 안내서를 바로 제공합니다.

KEY 페이지의 Skill 연결 안내는 제거했습니다. 배포 Skill 자체와 웹 상단 **파일 배포 Skill**, 기존 Skill 패키지는 유지합니다. MCP 안내서는 준비·웹 ZIP 다운로드·KEY 연결·최초 AI 등록·실제 연결 확인을 순서대로 설명합니다. `Connect.cmd`는 KEY 연결만 담당하고 AI 등록은 별도이며, 서버 주소·다운로드 폴더 자동 설정과 기존 KEY 재연결 기능은 유지합니다.

등록된 파일은 원본 그대로 전달합니다. 프로그램이 설치 EXE와 `connection.json`을 함께 요구하면 **배포자가** 완성된 ZIP에 넣어 등록해야 합니다. 웹이 EXE를 추가하거나 서버 주소를 주입하지 않습니다. `organization-store/` 개발 소스는 보존하며 프로그램이 완성되면 관리자가 원하는 분류로 등록합니다.

P&T AI Square의 최신 선택 확장은 **별도 설치 EXE가 없는 `.axextension` 파일**로 준비합니다. 이 파일의 내부 형식은 ZIP이며 웹은 기존 ZIP과 같은 크기·경로·선언 검사를 적용합니다. 배포자가 서버 주소를 지정해 패키징한 파일을 AX Workspace 자료실에 직접 등록하고, 사용자는 파일을 더블클릭해 열린 공통 앱의 확인창에서 설치한 뒤 개인 KEY를 입력합니다. 기존 ZIP은 설정의 **추가 기능 → 확장 ZIP 가져오기**에서도 설치할 수 있습니다. 예전 0.23.32에는 파일 연결이 없을 수 있으므로 버전 숫자만으로 호환성을 판단하지 않습니다. 사내 주소를 넣은 확장 파일은 공개 Git에 올리지 않습니다. 구형 `StoreInstaller.exe`를 포함하지 않는 것과 V3의 안전 판정은 별개이며 실제 사내 환경 확인이 필요합니다. MCP/스토어에서 이 파일을 받을 때도 원본 확장자를 유지하고, Claude Skill/MCP로 자동 설치하지 않습니다.

기존 `/local-access/workspace-extension.zip`과 `/static/guides/ax-workspace-extension-setup.exe` 링크는 로그인 후 AX Workspace 탭(`/?view=ax`)으로 이동합니다. 최신 웹 소스에는 해당 고정 EXE가 포함되지 않습니다. 코드 교체 시 기존 `runtime_config.py`, MongoDB 데이터와 업로드 저장소는 유지합니다. 이미 등록한 AX 자료와 사용자의 설치 프로그램을 자동 교체하지 않습니다.

## 로컬 MCP 설치 위치 선택

설치 위치를 **공통 (내 계정) / 현재 프로젝트 / 기타 경로**로 안내합니다. `list_install_locations`로 AI 프로그램이 제공한 프로젝트 정보를 확인하며, 현재 프로젝트가 하나이면 별도 폴더 선택을 반복하지 않고 설치 준비안으로 이어집니다. 프로젝트를 확인할 수 없거나 여러 개이면 임의로 추측하지 않고 사용자가 선택합니다. AI 프로그램이 프로젝트 정보를 제공하지 않는 경우 실제 MCP 시작 폴더를 확인 후보로 표시할 수 있지만, 사용자가 경로를 확인해 선택하기 전에는 접근을 허용하지 않습니다. 다운로드 저장소 `AI_SQUARE/downloads`와 실제 설치 위치는 구분합니다.

폴더 선택 화면은 Windows 화면 배율과 탐색기 방식 선택 창을 사용합니다. `select_workspace`는 창을 연 뒤 대기 상태와 요청 번호를 즉시 반환하며 `get_workspace_selection`으로 선택 결과를 확인합니다. 선택 대기를 취소할 수 있고, 선택만으로 설치하지 않습니다. 기존 설치 범위·경로·실행 명령 승인 및 준비안 검증은 유지하며 KEY 연결·최초 MCP 등록 절차는 바꾸지 않습니다.

## AX Workspace 새 버전 알림

AX 카드에서 파일을 다운로드하면 사번별 업데이트 알림을 자동 구독합니다. 카드에서 알림을 직접 켜거나 끌 수 있으며, 끈 뒤 다시 다운로드해도 해제 상태를 유지합니다. 관리자는 기존 카드의 **새 버전 등록**으로 같은 프로그램을 갱신합니다. 기존 ID와 이전 파일을 유지하고 동시 변경·중복 버전을 검사하며, 독립된 파일 등록은 별도 카드로 구분합니다.

버전과 알림 outbox를 함께 저장하고 후속 알림 전달 실패는 재시도합니다. 웹 종 알림을 누르면 해당 AX 카드로 이동하며, 화면이 보이는 동안 약 30초마다 조회합니다. OS·CUBE 푸시나 PC 파일 자동 교체는 제공하지 않고 일반 도구의 다운로드 순위에도 합산하지 않습니다. 기존 AX 다운로드 이력은 추정할 수 없으므로 이전 사용자는 다시 받거나 카드에서 알림을 켜야 합니다. `workspace_subscriptions` 컬렉션·인덱스는 자동 준비하며 운영 설정·기존 DB·업로드 초기화는 필요하지 않습니다.

## 운영 서버 설정

- 공개 Git에 올리는 소스·배포 파일에는 사내 서버 주소와 개인 KEY, DB 접속 정보를 넣지 않습니다. 웹 운영 설정은 Git에 포함하지 않는 `runtime_config.py` 또는 서버 환경변수로 관리합니다. 사내 배포용 확장 ZIP에는 지정한 서버 주소만 포함할 수 있으며, 개인 KEY와 DB 접속 정보는 넣지 않습니다.
- 로컬 MCP 다운로드에 리버스 프록시의 내부 주소가 들어가면 `PTAI_PUBLIC_URL`에 사용자가 접속하는 웹 기본 주소를 지정합니다. 서버 실행 주소 `0.0.0.0`을 넣지 않습니다. 이 설정은 AX Workspace에 등록한 파일을 변경하지 않으며, 기존 DB 접속 설정과 실행 방식도 바꾸지 않습니다.
- 직원 사진은 선택 설정인 `PTAI_EMPLOYEE_PHOTO_BASE_URL`에 사진 폴더의 HTTP(S) 주소를 지정하면 제공합니다. 서버가 그 주소에 사번과 `.jpg`를 붙여 조회합니다. 미설정 또는 사진 조회 실패 시 이름 첫 글자를 표시하며 나머지 기능은 유지됩니다. 실제 주소는 운영 담당자가 설정합니다.

로컬 MCP의 기존 서버 주소 자동 설정과 KEY 재연결 기능은 유지합니다. AX 프로그램은 관리자가 등록한 설치 안내에 따라 연결합니다. 개인 KEY·쿠키·MongoDB 접속 정보를 배포 ZIP에 포함하지 않습니다.

## 부서 권한 직접 입력

**팀·부서로 추가**에서 기존 SSO 부서 검색 외에 **부서 코드 직접 입력**과 **부서명 직접 입력**을 선택할 수 있습니다. 구성원이 아직 로그인하지 않아도 규칙을 미리 등록하며, 이후 정상 SSO 로그인 정보와 대조해 적용합니다. 코드 등록을 권장하고, 명시적으로 이름을 선택한 규칙은 부서 코드가 있는 사용자도 정확한 SSO 부서명이 일치하면 적용합니다. 기존 코드 없는 이름 규칙의 범위는 유지합니다.

직접 입력은 쉼표로 여러 값을 구분하고 앞뒤 공백만 제거합니다. 내부 공백 보존·빈 항목 무시·중복 제거를 적용하며 한 도구당 최대 50개 부서 규칙을 허용합니다. 검색은 기존 로그인 이력을 사용하며 회사 전체 부서 목록을 제공하지 않습니다. 등록자·관리자의 웹 로그인과 기존 서버 권한 검사를 유지하고 새 설정이나 DB 초기화는 필요하지 않습니다.

## 목록 반응 속도와 댓글 알림 개선

- 목록 생성 시 도구마다 반복하던 분류·권한·구독·작성자 조회를 요청 단위 일괄 조회로 줄였습니다. 부서 권한은 DB에 저장된 실제 SSO 부서 정보를 기준으로 판단하고, 사용자 간 캐시를 공유하지 않습니다.
- 홈·둘러보기·AX 화면에서 보이지 않는 목록을 반복 생성하지 않으며, 이미 그린 아이콘과 변경 없는 프로필 사진을 유지합니다.
- 다른 사람이 남긴 댓글은 실제 도구 등록자에게 알립니다. 작성자의 자동 구독 오류나 다른 수신자 오류가 나머지 알림 전달을 막지 않으며, 실패한 후속 작업은 중복 없이 다시 처리합니다.
- 알림 창은 조회 중에도 바로 열리고, 읽음 처리 후 늦게 도착한 응답이 예전 알림 숫자를 복구하지 않도록 했습니다. 알림을 누르면 도구의 의견 탭으로 이동합니다.
- 격리 MongoDB의 도구 100개·댓글 400개·답변 800개에서 일반 사용자 목록 핸들러 읽기 명령은 1,808회에서 11회, 중앙 처리 시간은 약 2,114ms에서 21ms로 감소했습니다. 인증·네트워크·브라우저 시간은 제외한 시험 결과이며 운영 전체 로딩 속도를 보장하는 수치는 아닙니다.
- 관련 서버 회귀 시험, 화면 비동기 시험, 실제 브라우저의 알림→의견 이동을 검증했습니다. 운영 설정·업로드·DB 초기화는 필요하지 않습니다.
