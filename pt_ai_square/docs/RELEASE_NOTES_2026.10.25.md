# P&T AI Square — AX Workspace 선택 확장 연동

2026-10-25 · 확장 버전 0.1.0

## 공개 배포 ZIP과 운영자 준비 순서

- **ai-square-2026.10.25-source.zip**: 플랫폼과 확장 개발 소스입니다. 기존 운영 설정·MongoDB·업로드 저장소를 유지한 채 웹 소스를 교체합니다.
- **PNT-AI-Square-0.1.0-Distribution.zip**: 서버 주소가 없는 공개 배포 준비 묶음입니다. 사용자용 완성 설치 EXE 대신 확장 template, 독립 설정 도우미와 표준 NSIS 빌드 도구를 포함합니다. 운영자가 서버 주소를 지정해 만든 **PNT-AI-Square-0.1.0-Setup.exe**를 웹의 AX Workspace 탭에 직접 등록합니다. 사용자는 완성된 Setup.exe를 실행하고 앱의 설치 확인창에서 설치한 뒤 개인 KEY를 입력합니다.
- **SHA256SUMS.txt**: 두 공개 배포 파일의 검증용 SHA-256입니다.

Distribution ZIP을 푼 뒤 `configure_server.py` 상단의 `SERVER_URL`을 수정하고 `python configure_server.py`를 실행하세요. 기본 출력은 `PNT-AI-Square-0.1.0-Setup.exe`이며, 사용자는 Python을 실행하거나 압축을 풀지 않습니다. 웹은 업로드된 파일을 그대로 제공하며 주소를 자동 삽입하지 않습니다. 서버 주소를 포함한 확장 파일은 사내 공유 대상으로 보관하고 공개 GitHub에 올리지 않습니다. 기존 네이티브 StoreInstaller.exe 대신 표준 NSIS 진입점이 공통 앱의 검증·설치 확인창을 엽니다. 별도 파일 연결은 필요하지 않습니다.

공통 앱의 사내 GitLab 배포에는 [workspace-local-0.23.32-source.zip](https://github.com/bongG-moon/workspace_local/releases/download/v0.23.32/workspace-local-0.23.32-source.zip)을 사용합니다. PC 설치에는 [AX Workspace 0.23.32 설치 파일](https://github.com/bongG-moon/workspace_local/releases/download/v0.23.32/AX-Workspace-0.23.32-Setup.exe)을 사용합니다. 이전 동일 버전에는 새 파일 선택·업무 선택 연결부가 없을 수 있으므로 이번 Setup으로 한 번 갱신해야 합니다.

## 앱 안에서 설치·등록과 화면 개선

- 항목의 설치·연결에서 공통(내 계정) 또는 AX Workspace 업무 목록의 업무를 골라 설치합니다. 설치 정보가 없는 표준 Skill ZIP도 실제 SKILL.md 구조를 검증한 후 설치할 수 있습니다. 일반 ZIP의 명령어를 추측해서 실행하지 않습니다.
- 연결 버튼을 **저장된 플랫폼(MCP) 연결 사용**으로 명확히 표시합니다. 기존 MCP 주소와 KEY를 재사용하는 기능이며 MCP를 새로 실행하지 않습니다.
- **도구 등록**에서 신규 도구 또는 본인이 등록한 도구의 새 버전을 준비합니다. 배포 파일·URL·설치 명령 안내, 조직·업무 분류·공개 범위를 입력하고 기존 플랫폼의 웹 승인 후 앱에서 등록을 완료합니다. 승인 전에는 게시하지 않으며 같은 요청 재시도는 중복 버전을 만들지 않습니다.
- 목록과 상세·설치·등록 팝업을 앱의 Noto Sans KR 13px 기준으로 통일했습니다. 넓은 화면은 3열, 작은 화면은 2열/1열이며 설명은 두 줄까지 표시하고 상세에서 전체 내용을 읽습니다.
- 등록 파일 선택과 내장 글꼴 공유에는 이번 공통 AX Workspace 0.23.32 빌드도 함께 필요합니다. 기존 동일 버전의 이전 EXE와 새 확장만 조합하면 파일 등록 연결부가 없을 수 있습니다.
- 앱·확장 관련 회귀 검사 214개와 라이트/다크·좁은 화면의 실제 브라우저 검증을 통과했습니다. 등록은 로컬 모의 서버에서 검증했으며 실제 사내 KEY·게시 동작은 운영 환경 확인 대상입니다.

## 최신 웹 배포 정책

AX Workspace 탭은 관리자가 완성된 프로그램을 직접 등록하는 자료실입니다. 웹에 특정 확장 소개나 고정 설치 EXE를 내장하지 않습니다. 관리자는 **AX Workspace → 파일 등록**에서 완성된 파일과 설명·분류를 등록하고, 사용자는 해당 카드를 찾아 다운로드합니다. 배포 번호는 서버가 자동 발급합니다. KEY 페이지의 **내 PC에서 시작하기**에는 위쪽 **확장 프로그램으로 연결하기**, 아래쪽 **MCP로 연결하기**가 항상 표시됩니다. 확장은 AX Workspace 탭으로 안내하고, MCP는 ZIP 다운로드와 설치 안내서를 바로 제공합니다.

KEY 페이지의 Skill 연결 안내는 제거했습니다. 배포 Skill 자체와 웹 상단 **파일 배포 Skill**, 기존 Skill 패키지는 유지합니다. 최신 MCP 안내서는 준비·웹 ZIP 다운로드·최초 AI 등록·채팅 KEY 연결·실제 연결 확인을 순서대로 설명합니다. MCP 1.5.0의 `Connect.cmd`는 채팅 연결 방법만 안내하고 KEY 입력창을 열지 않습니다. 최초 AI 등록은 별도이며, 서버 주소·다운로드 폴더 자동 설정과 현재 사이트의 KEY 재연결 기능은 유지합니다. KEY는 채팅·모델·도구 호출 기록에 남을 수 있으며 로컬 암호화 저장이 이 기록을 삭제하지는 않습니다.

등록된 파일은 원본 그대로 전달합니다. 프로그램이 설치 EXE와 `connection.json`을 함께 요구하면 **배포자가** 완성된 ZIP에 넣어 등록해야 합니다. 웹이 EXE를 추가하거나 서버 주소를 주입하지 않습니다. `organization-store/` 개발 소스는 보존하며 프로그램이 완성되면 관리자가 원하는 분류로 등록합니다.

P&T AI Square의 최신 선택 확장은 **표준 NSIS Setup.exe**로 준비합니다. 설치 진입점은 서버 주소를 포함한 검증 가능한 ZIP을 공통 AX Workspace에 전달하며, 앱이 파일과 설치 정보를 확인한 뒤 사용자의 설치 선택을 받습니다. 사용자는 파일 연결·압축 해제·Python 실행 없이 Setup.exe를 열면 됩니다. 기존 ZIP은 설정의 **추가 기능 → 확장 ZIP 가져오기**에서도 지원합니다. 사내 주소를 넣은 완성 EXE는 공개 Git에 올리지 않습니다. 이전 StoreInstaller.exe를 포함하지 않는 것과 V3의 안전 판정은 별개이며 실제 사내 환경 확인이 필요합니다.

기존 `/local-access/workspace-extension.zip`과 `/static/guides/ax-workspace-extension-setup.exe` 링크는 로그인 후 AX Workspace 탭(`/?view=ax`)으로 이동합니다. 최신 웹 소스에는 해당 고정 EXE가 포함되지 않습니다. 코드 교체 시 기존 `runtime_config.py`, MongoDB 데이터와 업로드 저장소는 유지합니다. 이미 등록한 AX 자료와 사용자의 설치 프로그램을 자동 교체하지 않습니다.

## 로컬 MCP 설치 위치 선택

MCP 1.5.0은 설치 위치를 **공통 (내 계정) / 현재 프로젝트 / 기타 경로**로 채팅에서 안내합니다. `list_install_locations`로 AI 프로그램이 제공한 프로젝트 정보를 확인하며, 현재 프로젝트가 하나로 확인되면 기본 후보로 표시합니다. 후보가 없거나 여러 개이면 채팅에서 경로를 묻고 MCP 실행 폴더를 임의로 현재 프로젝트라고 단정하지 않습니다. 다운로드 저장소 `AI_SQUARE/downloads`와 실제 설치 위치는 구분합니다. 등록할 원본도 같은 현재 프로젝트 후보를 확인할 수 있습니다.

이전 Windows 폴더 선택 창 방식은 채팅 선택으로 대체했습니다. `select_workspace`는 비밀정보 없는 호스트 확인 질문 또는 요청 번호와 선택지를 반환하고, 사용자가 확인한 선택·경로로 이어서 완료합니다. `get_workspace_selection`은 상태 조회만 하므로 자동 반복 조회하지 않습니다. 취소하면 접근 범위가 늘어나지 않으며, 폴더 선택만으로 설치하지 않습니다. 기존 설치 범위·경로·실행 명령 승인과 게시 내용·소유권 검사는 유지합니다. 이미 PC에 설치한 MCP는 최신 ZIP의 파일로 갱신하고 AI 프로그램을 다시 시작해야 하며, 웹 서버 업데이트만으로 자동 교체되지는 않습니다. 기존 `.venv`와 개인 연결 설정은 보존합니다.

## MCP 1.6.0 — 채팅에서 게시 완료

MCP의 도구 등록은 필수 웹 승인 단계를 채팅 요청 확인으로 대체합니다. 사용자가 등록할 대상·내용·공개 범위를 명확히 요청했다면 초안 준비 후 같은 `reviewDigest`와 `confirmed=True`로 바로 게시합니다. 정보가 부족하거나 준비한 내용이 요청과 달라졌을 때만 채팅에서 확인합니다. 응답 유실 재시도는 같은 초안으로 결과를 확인해 중복 버전을 방지합니다.

최신 웹 서버와 MCP 1.6.0을 함께 적용해야 합니다. 구버전 서버는 `serverUpdateRequired`로 갱신을 안내합니다. 같은 KEY·사번·소유권·파일 해시·초안 digest·만료·revision 검사는 유지하며, 관리자 KEY에도 타인 도구 변경 권한을 주지 않습니다. 클라이언트의 확인 표시는 사람의 동의를 서버가 별도로 증명하는 수단은 아닙니다. 웹 검토는 원하는 경우를 위한 대안이며, 이 문서 앞부분의 STORE 앱과 독립 CLI는 기존 웹 검토 절차를 유지합니다. 기존 데이터·KEY 재발급이나 초기화는 필요하지 않습니다.

### 최종 검토 보완

- 삭제된 원본 폴더가 있어도 채팅에서 KEY를 다시 연결할 수 있습니다. 사라진 원본의 허용 권한만 정리하고 기본 다운로드 폴더만 복구하며, 남아 있는 원본 폴더는 유지합니다.
- 폴더 권한과 선택 결과의 저장 순서를 보완해 디스크 오류나 응답 유실 시 실패 표시와 실제 권한이 어긋나지 않도록 했습니다.
- 게시·설치·위치 선택의 확인 값은 실제 boolean만 허용합니다. 선택 사항인 웹 승인도 입력 형식과 확인 전 초안 내용의 무결성을 검증합니다.
- KEY 이름 입력란을 제거하고 기본 허용 작업을 간결하게 정리했습니다. 발급 안내에서 확장 프로그램 입력란과 MCP 채팅 입력을 구분합니다.

## AX Workspace 새 버전 알림


AX 카드에서 파일을 다운로드하면 사번별 업데이트 알림을 자동 구독합니다. 카드에서 알림을 직접 켜거나 끌 수 있으며, 끈 뒤 다시 다운로드해도 해제 상태를 유지합니다. 관리자는 기존 카드의 **새 버전 등록**으로 같은 프로그램을 갱신합니다. 기존 ID와 이전 파일을 유지하고 동시 변경을 검사하며, 독립된 파일 등록은 별도 카드로 구분합니다.

버전과 알림 outbox를 함께 저장하고 후속 알림 전달 실패는 재시도합니다. 웹 종 알림을 누르면 해당 AX 카드로 이동하며, 화면이 보이는 동안 약 30초마다 조회합니다. OS·CUBE 푸시나 PC 파일 자동 교체는 제공하지 않고 일반 도구의 다운로드 순위에도 합산하지 않습니다. 기존 AX 다운로드 이력은 추정할 수 없으므로 이전 사용자는 다시 받거나 카드에서 알림을 켜야 합니다. `workspace_subscriptions` 컬렉션·인덱스는 자동 준비하며 운영 설정·기존 DB·업로드 초기화는 필요하지 않습니다.

## AX 분류와 자동 배포 번호 · 도구 식별자 안내

- AX 분류를 **전체 / AX Workspace / 확장 프로그램 / 연동 도구**로 정리했습니다. 기존 기타 자료는 연동 도구로 표시하며 업로드 파일과 과거 기록은 보존합니다.
- 신규 AX 카드는 v1, 기존 카드에서 새 파일을 게시하면 v2·v3으로 자동 증가합니다. 수동 버전 입력을 제거하고 다음 번호를 표시합니다. 프로그램 자체 버전과는 별도의 플랫폼 배포 순서입니다.
- 일반 도구의 숫자 ID와 최초 정상 선언의 `packageId`는 플랫폼에 고정합니다. 기존 도구의 **새 버전 등록**에서는 새 ZIP의 packageId가 달라도 게시할 수 있습니다. 원본 ZIP·선언·해시는 유지하고 플랫폼 고정 ID와 원본 ID를 구분해 표시합니다.
- MCP와 배포 Skill은 선택한 기존 도구 ID로 업데이트합니다. 자동 후보 검색은 고정 ID와 이름을 사용하며 새 파일의 다른 ID를 기존 도구의 별칭으로 취급하지 않습니다. 원본 경로의 로컬 연결 기록은 같은 서버·사번에서 후보로 제시하고 게시 대상은 사용자 요청을 따릅니다. 공개 범위·소유권·revision·파일 검사·중복 게시 방지는 유지하며 MCP 1.6.0의 게시 확인은 위의 채팅 절차를 사용합니다. 독립 CLI와 STORE의 웹 검토 대안은 유지합니다.
- 실행 방식·포트·runtime_config·MongoDB·업로드 저장소 변경이나 초기화 없이 코드를 교체합니다.

## 운영 서버 설정

일반 도구의 **URL 연결** 등록은 사내 HTTP와 HTTPS 주소를 모두 지원합니다. API·MCP 주소에 필요한 포트·경로를 포함할 수 있으며 주소 안의 아이디·비밀번호와 잘못된 URL은 거절합니다. URL은 연결 안내로 보관하고 서버 호출이나 원격 MCP 설정을 자동 실행하지 않습니다. 기존 도구·버전 데이터는 유지하며 새 런타임 설정이나 데이터 마이그레이션이 필요하지 않습니다. AI SQUARE 개인 KEY 연결의 인증·HTTP 주소 확인·리디렉션 차단 규칙은 변경하지 않습니다.

- 공개 Git에 올리는 소스·배포 파일에는 사내 서버 주소와 개인 KEY, DB 접속 정보를 넣지 않습니다. 웹 운영 설정은 Git에 포함하지 않는 `runtime_config.py` 또는 서버 환경변수로 관리합니다. 사내 배포용 확장 ZIP에는 지정한 서버 주소만 포함할 수 있으며, 개인 KEY와 DB 접속 정보는 넣지 않습니다.
- 로컬 MCP 다운로드에 리버스 프록시의 내부 주소가 들어가면 `PTAI_PUBLIC_URL`에 사용자가 접속하는 웹 기본 주소를 지정합니다. 서버 실행 주소 `0.0.0.0`을 넣지 않습니다. 이 설정은 AX Workspace에 등록한 파일을 변경하지 않으며, 기존 DB 접속 설정과 실행 방식도 바꾸지 않습니다.
- 직원 사진은 선택 설정인 `PTAI_EMPLOYEE_PHOTO_BASE_URL`에 사진 폴더의 HTTP(S) 주소를 지정하면 제공합니다. 서버가 그 주소에 사번과 `.jpg`를 붙여 조회합니다. 미설정 또는 사진 조회 실패 시 이름 첫 글자를 표시하며 나머지 기능은 유지됩니다. 실제 주소는 운영 담당자가 설정합니다.

로컬 MCP의 기존 서버 주소 자동 설정과 KEY 재연결 기능은 유지합니다. AX 프로그램은 관리자가 등록한 설치 안내에 따라 연결합니다. 개인 KEY·쿠키·MongoDB 접속 정보를 배포 ZIP에 포함하지 않습니다.

## 부서 권한 직접 입력

**팀·부서로 추가**에서 기존 SSO 부서 검색 외에 **부서 코드 직접 입력**과 **부서명 직접 입력**을 선택할 수 있습니다. 구성원이 아직 로그인하지 않아도 규칙을 미리 등록하며, 이후 정상 SSO 로그인 정보와 대조해 적용합니다. 코드 등록을 권장하고, 명시적으로 이름을 선택한 규칙은 부서 코드가 있는 사용자도 정확한 SSO 부서명이 일치하면 적용합니다. 기존 코드 없는 이름 규칙의 범위는 유지합니다.

직접 입력은 쉼표로 여러 값을 구분하고 앞뒤 공백만 제거합니다. 내부 공백 보존·빈 항목 무시·중복 제거를 적용하며 한 도구당 최대 50개 부서 규칙을 허용합니다. 검색은 기존 로그인 이력을 사용하며 회사 전체 부서 목록을 제공하지 않습니다. 등록자·관리자의 웹 로그인과 기존 서버 권한 검사를 유지하고 새 설정이나 DB 초기화는 필요하지 않습니다.

## 목록 반응 속도와 댓글 알림 개선

- 목록 생성 시 도구마다 반복하던 분류·권한·구독·작성자 조회를 요청 단위 일괄 조회로 줄였습니다. 부서 권한은 DB에 저장된 실제 SSO 부서 정보를 기준으로 판단하고, 사용자 간 캐시를 공유하지 않습니다.
- 홈·둘러보기·AX 화면에서 보이지 않는 목록을 반복 생성하지 않으며, 이미 그린 아이콘과 변경 없는 프로필 사진을 유지합니다.
- 다른 사람이 남긴 댓글은 실제 도구 등록자에게 알립니다. 작성자의 자동 구독 오류나 다른 수신자 오류가 나머지 알림 전달을 막지 않으며, 실패한 후속 작업은 중복 없이 다시 처리합니다.
- 알림 창은 조회 중에도 바로 열리고, 읽음 처리 후 늦게 도착한 응답이 예전 알림 숫자를 복구하지 않도록 했습니다. 알림을 누르면 도구의 의견 탭으로 이동합니다.
- 격리 MongoDB의 도구 100개·댓글 400개·답변 800개에서 일반 사용자 목록 핸들러 읽기 명령은 1,808회에서 11회, 중앙 처리 시간은 약 2,114ms에서 21ms로 감소했습니다. 인증·네트워크·브라우저 시간은 제외한 시험 결과이며 운영 전체 로딩 속도를 보장하는 수치는 아닙니다.
- 관련 서버 회귀 시험, 화면 비동기 시험, 실제 브라우저의 알림→의견 이동을 검증했습니다. 운영 설정·업로드·DB 초기화는 필요하지 않습니다.
