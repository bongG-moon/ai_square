P&T AI SQUARE 로컬 배포 MCP 구현·검증 기록
2026-10-24

구성
- integrations/pt-square-mcp: 사용자 PC의 stdio MCP. 별도 MCP 서버/포트 없음.
- static/guides/pt-square-mcp.zip: 소스와 고정 SDK 의존성 목록 15개 파일.
- backend/catalog_search.py: 관련도·부서 추천·최근 7일/누적 순위.
- backend/publish_drafts.py: KEY 초안 → 웹 세션/CSRF 승인 → 동일 초안 게시.
- backend/install_profiles.py: 별도 설치 선언 검증 및 버전별 보관.
- templates/publish_review.html + static/publish_review.*: 웹 게시 검토 화면.
- docs/MCP_LOCAL_GUIDE.html: 운영 반영과 사용자 연결 순서.

주요 동작
- 개인 KEY 사번·권한을 서버에서 검사한다. 관리자 KEY도 본인 도구만 게시한다.
- KEY로 관리자 설정·삭제·다른 도구 수정·MongoDB 임의 명령·서버 파일 경로 탐색을 제공하지 않는다.
- 기존 웹의 관리자 세션 기능과 SSO 구현은 유지한다.
- HTTP는 최초 확인한 정확한 주소에만 KEY를 보낸다. 리다이렉트를 따르지 않는다.
- HTTP 전송 자체가 암호화되지는 않는다. Windows 저장 KEY는 사용자 DPAPI로 암호화한다.
- 로컬 범위는 사용자가 지정한 작업 폴더. 설치는 project/user를 반드시 지정한다.
- 단일 MD는 유지, 폴더는 배포 계약 ZIP, 기존 ZIP은 원본 유지·검증.
- 신규/업데이트와 조직·업무·조회 승인 여부를 확인하고 서버에 초안을 만든다.
- 웹 승인 이후 같은 초안 게시를 재시도하면 같은 결과를 반환한다.
- 승인 내용·파일 해시·KEY·등록자·revision을 서버에서 다시 검사한다.
- 지원하는 설치 선언에 대해서만 Skill 배치, MCP 설정 병합, EXE/MSI/PS1 실행을 지원한다.
- pip/npm 의존성 설치와 일반 임의 셸 명령 실행은 자동화하지 않는다.
- 설치기 실행(launched)과 설치 완료를 구분한다. 설치기 외부 변경 전체 복구는 지원하지 않는다.
- 다운로드는 기존 API를 사용하며 사번·도구당 최초 1회, 업데이트는 추가 집계하지 않는다.
- 기존 ai-square.json v1은 유지한다. installProfile은 별도 게시 메타데이터다.
- 배포 Skill/수신 Skill ZIP과 company Skill ZIP 14개를 정본 기준으로 다시 생성했다.

최종 검증
1. 공식 MCP SDK 1.30.0을 포함한 격리 Python 환경:
   python -X utf8 -B -m pytest pt_ai_square/tests -q
   결과: 490 passed (195.15초). 실패/skip 없음.
   MongoDB는 기존 데이터와 분리된 localhost:27018 임시 복제 세트.
2. Node 화면 테스트 7개 파일: 96 passed.
3. python -X utf8 -B -m unittest discover -s tests -p test_platform_skill_*.py -q
   결과: 43 tests OK. openpyxl이 있는 기존 Python 런타임 사용.
4. scripts/build-skill-packages.py --check: 14개 패키지 current, 변경 필요 없음.
5. 실제 Chromium: 데스크톱1440/모바일390, 웹 승인·공개 범위·새로고침 유지·3단계 흐름·KEY 화면 확인.
   가로 넘침 및 JS console error 없음.
6. 실제 MCP SDK stdio initialize → list_tools → call_tool, KEY 원문 비노출 확인.
7. 실제 로컬 HTTP + Flask + MongoDB:
   MD/ZIP 신규 등록, 웹 승인, v2 게시, 동일 요청 재시도, 프로젝트 설치,
   업데이트 다운로드 집계 제외, 이전 설치 복구, URL 등록 및 관리자 KEY 타인 수정 차단.
8. ZIP 내용은 최종 소스와 바이트 동일. 캐시·가상환경·runtime_config·개인 KEY 미포함.

검토 중 보완
- 만료 초안 정리 완료 표시 및 배치 순환으로 첫 20개 반복 문제 해결.
- 게시 결과 기록 실패 후 24시간이 지난 committing 초안도 결과 재조회 가능.
- 영구 삭제 후 이전 게시 초안이 도구를 재생성하지 않도록 예약 ID/삭제 기록 확인.
- 복구 전 이전 백업 해시 확인, 파일·설정·로컬 기록 저장 실패 시 현재 파일 보존.
- 기존 ZIP의 압축 해제 내용에도 인증정보 파일/패턴 검사.
- 다운로드 중 사용자가 바꾼 파일·설정 재검사 및 MCP 프로세스 간 로컬 작업 잠금.
- 패키지 ID 없는 MD/URL도 본인 이름·설명·태그로 업데이트 후보 조회.

범위와 한계
- 운영 DB, 실제 업로드 저장소, runtime_config.py, 회사 실행 진입점/포트를 변경하지 않았다.
- 사내 실제 HTTP 도메인·SSO SDK 연결과 네트워크 정책은 운영 환경에서 확인해야 한다.
- 실제 외부 EXE/MSI/PS1은 실행하지 않았다. 실행 분기는 모의 프로세스로 검사했다.
- 프로세스 강제 종료·정전·외부 설치기의 모든 시스템 변경은 검증하지 않았다.
- 설치 성공은 지원하는 파일 배치/연결 설정 확인 범위이다. MCP 업무 기능 실행과는 다르다.
- 만료 초안 정리는 다음 초안 생성 시 제한된 배치로 수행한다. 불명확한 committing 파일은 보존한다.
- 검색 후보 최대 5,000개 초과는 불완전 결과로 표시한다. 부서 추천은 현재 부서코드 기준이며 충분한 표본에서만 노출한다.
- 커밋/원격 반영 여부는 저장소의 Git 기록에서 확인한다.
