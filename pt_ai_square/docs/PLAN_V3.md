# P&T AI SQUARE 상세 기획서 v3.3

## 로컬과 운영의 동일한 저장 기능

인증 방식만 SSO 사용(sso)과 미사용(mock)으로 구분한다. 두 방식 모두 실제 MongoDB와 서버 파일 저장소를 사용한다. MONGODB_URI와 MONGODB_DATABASE가 없으면 시작 전에 설정을 요청하고, DB 장애 시 대체 데이터로 접근을 허용하지 않는다.

## 제품 방향

사내에서 만든 MCP, Skill, Tool, 플러그인, 하네스를 등록하고 찾아 쓰는 웹 플랫폼이다. 기존 데스크톱 앱과 분리된 웹 카탈로그이며, 후속 앱 연계를 위한 배포 manifest API를 제공한다. Claude / ChatGPT / 기타 3개 프로그램 구분을 유지한다.

기존 홈의 왼쪽 실시간 순위와 오른쪽 최다 다운로드·최근 등록, 둘러보기 카드 구성, 로고·한글/영문 폰트·검정/회색 메인 문구를 유지한다. 배경에 파랑/보라 그라데이션을 넣지 않고 중립색 반투명 패널, 얇은 경계, 작은 그림자로 깊이를 표현한다. MCP 파랑, Skill 보라, 플러그인 주황 등 유형 색은 아이콘·라벨에 사용한다.

## 탐색과 선택 메뉴

조직과 업무 선택은 검색 가능한 둥근 팝오버로 제공한다. 선택 항목 체크, 마우스 강조, 방향키 이동, Enter 선택, Esc 닫기를 지원한다. 드롭다운은 팝업 내부에서도 최상단에 표시한다. 등록과 수정에서도 같은 요소를 사용한다.

업무 분류는 관리자 기준의 한 가지 대표 업무로 선택하고, 관련 업무 태그는 자유 입력으로 최대 8개를 추가한다. 태그는 검색에 포함한다. 조직·업무 고유 ID와 표시 이름을 분리해 이름 변경이 기존 연결을 끊지 않도록 한다. 사용 중지 항목은 새로 선택할 수 없지만 기존 기능에서 유지할 수 있다. SSO 부서는 부서 코드로 연결해 관리자 표시 이름을 바꿔도 중복 조직이 생기지 않도록 한다.

## 기능 등록·수정·삭제

등록자는 상단 **도구 등록**을 누른다. 1단계에 이름·한 줄 소개·관련 업무·프로그램·유형·조직·담당자·조회 승인 여부를 입력한다. 2단계에서 ZIP/EXE/MSI/PS1 파일 또는 HTTPS 연결 URL, 사용 환경, 설치 방법, 변경 내용을 입력한다. 3단계에서 확인하고 게시하면 서버가 배포 버전 번호를 발급한다.

등록자 ID는 로그인 계정에서 결정한다. 화면의 담당자 표시 이름을 바꿔도 소유자는 바뀌지 않는다. 등록자와 관리자만 정보 수정, 새 버전 등록, 롤백, 삭제·복원할 수 있다. 서버 API에서도 동일한 권한을 확인한다.

삭제는 휴지통으로 이동하는 방식이다. 일반 목록·다운로드에서 제외하고 등록자·관리자 화면에서는 복원할 수 있다. 파일의 영구 삭제는 버전 정리 기능으로 구분하며 현재·복구용 버전은 보호한다.

## 공개와 조회 권한

목록은 로그인 사용자에게 공개한다. 승인형 기능의 이름·한 줄 소개·유형·등록 조직·대표 업무·관련 업무 태그·담당자 표시 이름·누적 지표를 공개 카드 정보로 취급한다. 이 정보에는 비공개 상세 내용을 적지 않는다.

등록 시 승인을 선택하면 일반 사용자가 카드를 눌렀을 때 **조회 권한이 필요합니다** 팝업을 보여준다. 사용자는 목적을 입력해 신청한다. 등록자·관리자는 기본 조회 가능하다. 승인된 사람에게만 설치 안내, 환경, 연결 URL, 버전 파일명·해시·변경 이력, 피드백 내용을 제공한다. 승인 전 상세 데이터를 내려받아 브라우저에서 숨기는 방식은 사용하지 않는다.

승인 담당자는 **권한 관리 → 대기 → 승인/반려**로 처리한다. **승인됨**에서는 현재 권한 보유자와 직접 추가된 사용자를 볼 수 있으며 사유를 남기고 회수한다. 신청 처리 결과와 현재 권한 보유 여부는 다른 필드로 저장한다. 승인 후 회수된 사람의 과거 승인 이력은 남는다. 회수 후 재신청할 수 있다.

## 등록 기능 피드백

기능 상세 → 의견에서 개선 의견 / 사용 후기 / 오류 제보 / 아이디어 제안을 작성한다. 조회 권한이 있는 사용자만 참여한다. 등록자·관리자는 답변과 접수 / 검토 중 / 반영 중 / 반영 완료 / 보류 상태를 남긴다. 원 작성자는 후속 답변을 남길 수 있지만 처리 상태를 바꾸지 못한다. 등록 관리의 피드백 탭에서 자기 기능의 의견을 모아 본다.

## 새로운 기능 요청

사용자가 **기능 요청 → 새 기능 요청**에서 제목·불편한 점·원하는 결과·업무 분류를 작성한다. 개발자가 **제가 구현할게요**를 누르면 담당자 지정 상태가 된다. 동시에 두 사람이 눌러도 하나의 접수만 성공한다.

기본 흐름은 접수 대기 → 담당자 지정 → 개발 중 → 구현 완료다. 개발 중 보류하거나 담당을 내려놓고 접수 대기로 돌릴 수 있다. 상태 변경은 개발 담당자·관리자만 가능하며 일반 사용자는 답변으로 의견을 추가한다. 구현 완료에는 실제 등록 기능을 선택해야 한다. 연결된 기능의 조회 권한은 별도로 적용된다.

## 개인별 알림

웹 우측 상단 종 아이콘과 안읽음 개수로 진입한다. 전체/안읽음 전환, 모두 읽음, 이전 알림 더 보기, 개별 알림 선택 후 해당 요청·기능으로 이동을 제공한다. 알림은 사용자 ID별로 분리하며 다른 사용자의 알림 ID로 읽음 처리해도 영향을 주지 않는다.

신청은 등록자·관리자에게, 승인 결과는 신청자에게, 피드백과 답변은 관련 작성자·등록자·관리자에게, 개발 요청 접수·진행은 요청자·담당자·참여자·관리자에게 전달한다. 새 버전·롤백은 현재 조회 권한이 있는 구독자에게 전달한다. 자신의 행동을 자신에게 중복 통지하지 않는다. 권한 승인·다운로드·피드백 작성 시 자동 구독하며 상세 화면에서 해제할 수 있다.

열린 웹은 30초 주기로 새 알림 개수를 확인한다. 웹을 닫아도 알림은 DB에 남는다. 외부 메일·메신저·OS 푸시 없이 웹 내 알림으로 구현한다.

## 관리자 정책

기본 관리자는 runtime_config.py 또는 실제 프로세스 환경변수의 PTAI_ADMIN_IDS에 지정한다. mock과 sso 인증 모두 같은 기준을 적용한다. 개발용 mock에서는 MOCK_ADMIN 설정 계정도 기본 관리자가 된다. 기본 관리자는 웹에서 삭제하지 못한다.

기본 관리자만 추가 관리자를 지정·해제한다. 추가 관리자는 분류·기능·권한·저장공간을 운영할 수 있다. 관리자 지정·해제와 운영 작업은 이력으로 남긴다. 역할은 매 요청마다 MongoDB·설정으로 판단해 해제된 권한을 오래된 세션에서 계속 쓰지 못하도록 한다.

## MongoDB 데이터 구조

| 컬렉션 | 내용 |
|---|---|
| users | 사번 _id 유지, emp_no·emp_name·dept·dept_cd, 기존 name·orgId, 활성 상태, 현재 연결 KEY ID |
| taxonomy | 조직·업무 고유 ID, 이름, 표시 순서, 활성 상태, SSO 부서 코드 |

| access | 기능·사용자별 신청 상태, 현재 권한, 사유, 승인자·시간, 처리 이력 |
| feedback | 기능별 의견, 작성자, 답변, 처리 상태·revision |
| ideas | 새 기능 요청, 개발 담당자, 상태, 연결 기능, 답변·revision |
| subscriptions | 기능별 개인 업데이트 알림 구독 |
| notifications | 개인 알림, 읽음 상태, 관련 화면 정보 |
| administrators | 추가 관리자와 지정·해제 기록 |
| activity_state | 현재 좋아요, 사용자·도구별 전체 기간 최초 다운로드 상태; 이전 일별 자료는 최초 수신으로 합산 |
| activity | 좋아요·취소·다운로드 개별 이력 |
| local_tokens | 연결 KEY 해시·사번·권한·취소·교체 이력; 새 KEY는 expires: null, 기존 기간형 KEY는 원래 만료일 유지; 원문 KEY는 저장하지 않음 |
| audit / settings / counters / login_attempts | 운영 이력, 보관 정책·세션 키, ID 발급, 로그인 시도 제한 |
| migrations | 명시적인 이전 작업의 진행·완료 상태 |

원본 배포 파일은 Flask 서버 디스크의 DATA_DIR/artifacts에 두고, DB에는 상대 파일명·원래 이름·크기·SHA-256·버전·생성 시각을 기록한다. Flask 세션은 서명 쿠키이며 로그인 계정·권한·로그인 시도 제한·기본 세션 키는 MongoDB를 사용한다. 실행 중 SQLite 파일이나 SQLite 대기열을 사용하지 않는다.

버전 목록과 현재 배포 포인터는 한 도구 문서에서 revision 조건으로 원자적으로 갱신한다. 권한 신청·현재 승인 여부·이력도 한 권한 문서에서 함께 갱신한다. 알림 발생 기록은 원본 문서의 outbox에 같은 변경으로 넣고, 사용자별 알림으로 전달한 뒤 제거한다. 중복 전달은 고유 알림 ID로 방지하고 다음 요청에서 실패한 전달을 재개한다. 단일 MongoDB 서버에서도 동작하며 replica set 트랜잭션을 전제로 하지 않는다.

## 실시간 순위

접속·새로고침·활동 후 저장 이력을 읽어 계산한다. 기본 선택은 실시간(최근 7일)이며 누적(전체 기간)으로 전환할 수 있다. 양쪽 모두 좋아요 2점 + 다운로드 1점이다. 좋아요 취소는 점수에서 제외하고 재클릭해도 최초 좋아요 날짜를 유지한다. 기존 이력에 최초 날짜가 없으면 저장된 마지막 변경 날짜를 기준으로 보존한다. 동점은 해당 기간 다운로드 수, 좋아요 수, 최근 등록일 순으로 정한다. 순위 행의 수치도 선택한 기간 기준이다. 5초마다 1–5위와 6–10위를 행별 플립으로 전환한다. 다운로드는 같은 사번·기능의 전체 기간 최초 수신만 순위와 누적 수에 반영한다. 날짜·버전이 바뀌어도 추가 집계하지 않으며 업데이트 수신은 제외한다. 실시간 7일 순위는 최초 수신일로 판단하고 개별 요청 이력은 남긴다. HEAD 조회는 다운로드로 세지 않는다.

카드가 공개되므로 승인형 기능도 순위에 포함된다. 화면은 1~5위와 6~10위를 5초마다 자동 전환하며 일시정지 버튼은 없다. 상세 팝업이나 숨겨진 브라우저 화면에서는 불필요한 순위 애니메이션을 멈춘다. 모션 감소 설정에서는 이동 효과 없이 전환한다.

## 배포·복구와 기존 데이터 이전

새 버전을 등록하면 최신 배포와 복구용 버전을 갱신한다. 이전 버전으로 복구하면 문제가 있던 배포를 철회하고 복구 버전을 현재로 지정한다. 이전 버전 삭제·보관 정책을 유지한다. 파일 삭제가 잠겨 실패하면 삭제 표시를 유지하고 정리 재시도 시 처리한다.

기존 자료는 서버를 중지한 뒤 migrate-legacy 명령으로 명시적으로 옮긴다. 원본 SQLite는 읽기 전용이며 완료 후 운영에 연결하지 않는다. 기존 MongoDB 활동 이력도 보존한다. 데이터 이전이 중단되면 같은 작업을 다시 실행한다. 이전 중 웹 요청은 차단한다. MongoDB 장애 시 예전 권한으로 접근을 허용하는 대체 DB는 없다.

## 구현 범위와 검증 경계

실행 시 버전 확인은 파일 자동 교체와 분리한다. 인증된 `GET /api/tools/{id}/version-check?release={설치번호}`에서 현재 배포·새 버전·서버 복구·알 수 없는 배포를 구분한다. API는 읽기 전용이며 다운로드 수를 증가시키지 않는다. 배포 Skill에 Python 확인 코드를 제공하되 도구 실행 지점과 사내 인증 클라이언트는 각 제작자가 연결한다. 확인 실패 시 최신 여부를 알 수 없다고 알리고, 기존 로컬 실행을 이 확인 기능 때문에 중단하지 않는다. 기존 업무 데이터의 접근 권한은 별도로 유지한다. 로컬 배포 번호는 실제 설치 완료 때만 기록한다.

이 문서의 웹 기능은 실제 Flask API와 MongoDB 저장소에 연결한다. 업로드 파일을 실행하거나 LLM으로 변환하지 않는다. 원클릭 EXE 생성·서명·악성코드 검사, 실제 PC 설치·업데이트·롤백, 회사 원본 데이터 권한 부여는 후속 연계 범위다.

실제 회사 SSO 인증과 운영 배포는 회사 환경에서 확인해야 한다. 현재 로컬 MongoDB에서 권한·승인·알림·동시성·배포·이전·SSO 인터페이스 대역·환경설정 검증을 수행한다. 상세 실행 순서와 버튼별 예시는 OPERATOR_GUIDE.md 및 USER_GUIDE.md에 있다.

## 인증 방식과 로컬 동등성

sso와 mock만 지원하며 비밀번호 로그인·계정 생성 CLI는 제공하지 않는다. mock은 설정한 사번을 사용자 ID로 사용하고 요청·세션에서 임의로 바꿀 수 없다. 사용자 ID를 얻은 뒤에는 동일한 Flask API와 MongoDB 저장소를 사용하므로 로컬 업로드·수정·새 버전 게시·다운로드·롤백·승인·알림이 실제 저장된다. 사번은 문자열로 유지한다. 기본 DATA_MODE='mongodb'에서는 MongoDB URI와 DB 이름이 필수이며 미설정 시 실행 전에 설정을 요청한다. 명시적인 DATA_MODE='dummy' 설정은 별도 샘플 파일만 읽는 로컬 화면 확인용이며, 실제 DB 연결과 쓰기는 모두 차단한다.

## v3.3 등록 경험과 자료 저장

공유 유형은 MCP/Tool, Skill, 플러그인/하네스 3종이다. 기존 값은 조회 및 수정 시 공통 유형으로 정규화하여 ID와 버전 연결을 유지한다. 파일 선택과 드래그 앤 드롭, 선택 취소를 제공하며 원본 형식으로 배포한다. 자동 EXE 변환은 제공하지 않는다. 조회 권한은 설명을 포함한 스위치 카드로 설정한다. 둘러보기는 12개씩 이전·다음 페이지를 제공한다.

기능 요청에는 최대 5개, 파일당 20MB의 이미지·문서·ZIP을 첨부한다. 첨부 원본은 DATA_DIR/request_attachments, 도구 배포 원본은 DATA_DIR/artifacts에 보관한다. 요청·첨부 메타데이터·권한·버전·이력·알림은 MongoDB에 저장한다. 요청 첨부 다운로드는 인증을 거치며 경로는 응답에서 숨긴다. 요청 첨부는 배포 버전 보관 정책으로 지우지 않는다.

웹 가이드는 사용자·등록자의 버튼 사용법만 담는다. 설정·실행·백업은 별도 실행·운영 HTML에 담고 웹 다운로드에 노출하지 않는다.

[Shopify Polaris Drop zone](https://polaris-react.shopify.com/components/selection-and-input/drop-zone)과 [Atlassian Toggle](https://atlassian.design/components/toggle)의 파일 선택·끌어넣기와 설정 패턴을 참고하여 기존 중립색 글래스 디자인에 맞춘다.

## 18. 명시적인 샘플 조회 모드

PTAI_DATA_MODE는 mongodb(기본)와 dummy를 지원한다. 기본 모드의 SSO·mock 실제 저장 동작은 동일하다. dummy는 AUTH_MODE=mock일 때만 허용하고 dummy/catalog.json에서 10개 도구·조직·업무·기능 요청을 읽어 화면을 구성한다. 버전·순위·좋아요·다운로드 수는 예시다. 샘플을 MongoDB에 삽입하지 않으며 실제 DB·파일 저장소에 접근하지 않는다. 쓰기 및 배포 파일 다운로드는 409로 거절한다. DB 장애 시 자동 전환하지 않는다.

runtime_config.example.py와 로컬 runtime_config.py에는 각 값의 한국어 설명·단위·예시를 제공한다. 실제 도구 다운로드 성공 시 하단의 다운로드 시작 안내는 표시하지 않으며 실패 안내는 유지한다. EXE 자동 변환은 미구현이며 업로드한 원본 파일과 서버 발급 배포 번호를 관리한다.

## 19. Skill과 웹의 배포 정보 연결

사용자가 요청한 범위는 원본 파일 가공 없이 선언 읽기·필수 파일 검사·배포 번호 및 확인 주소 연결이다. Skill은 ai-square.json, UTF-8 설치 안내, 원래 코드·리소스를 ZIP으로 준비한다. 웹 등록 첫 단계에서 ZIP을 선택하면 선언을 읽고 기본 정보를 입력한다. 입력 내용이 이미 있으면 적용 버튼으로 선택 반영하며 조직·권한·담당자 정보는 패키지에서 받지 않는다.

배포 정보 검사는 선언 버전·허용 필드·유형·프로그램·경로·중복·시작 파일·설치 안내·필수 파일 존재 여부를 확인한다. 읽기 실패는 경고로 표시하고 수동 정보로 게시를 허용한다. 클라이언트 사전 조회가 실패하거나 진행 중이어도 게시할 수 있으며, 서버는 실제 파일을 다시 검사한다. ZIP 자체의 경로 탈출·용량·암호화·링크·손상 검사는 게시를 차단하는 기본 검사로 유지한다. 유효한 선언을 읽은 경우 유형·프로그램·기존 packageId 일치 검사는 유지한다.

게시 시 검사된 선언을 MongoDB의 배포 버전에 보관하고, 별도 배포 정보 JSON에 서버가 발급한 toolId·release·파일 해시·버전 확인 주소를 연결한다. 원본 ZIP 바이트는 그대로 보관하며 EXE 생성·코드 실행·PC 설치·자동 파일 교체는 하지 않는다. 배포 정보 다운로드에는 도구 조회 권한과 버전 삭제·철회 상태를 적용한다. 이전 버전 복구 시 해당 배포 선언과 연결 정보가 일치한다.

## 20. 단일 MD·명령어 배포와 설치 범위

파일 등록은 ZIP·EXE·MSI·PS1·UTF-8 MD를 지원한다. 단일 MD는 확장자와 내용을 바꾸지 않고 원본 그대로 저장한다. 보조 코드가 있는 Skill은 ZIP으로 묶는다. 배포 Skill은 실제 진입점과 사용 방식을 보고 MCP/Tool·Skill·플러그인/하네스를 판단해 ZIP 선언에 기록한다. 웹 자동 입력은 선언을 읽는 기능이며 코드 의미를 추론하지 않는다. 선언이 없는 MD·URL·명령어는 등록자가 유형을 선택한다.

2단계에 파일 등록·URL 연결·명령어 안내를 제공한다. 명령어는 프로젝트용(commandProject)과 사용자 전역용(commandUser)으로 입력하며 하나 이상 필요하다. 비어 있는 범위는 지원하지 않음으로 표시한다. 각 명령어는 최대 8,000자이며 서버에서 실행하지 않는다. 명령어 문자열과 설치 안내는 MongoDB의 버전 문서에 저장하고, 파일은 생성하지 않는다.

사용자는 상세의 설치·연결에서 현재 디렉토리/전역·내 계정 중 직접 선택해야 명령어가 보인다. 기본 선택은 없다. 선택·복사 시 서버 상세 API로 조회 권한과 해당 버전의 철회·삭제 상태를 다시 확인한다. 복사는 다운로드 실적으로 기록하지 않는다. 새 버전 게시와 롤백은 활성 명령어·안내를 함께 변경하며 터미널에서 이미 실행한 설치를 되돌리지는 않는다.

배포 Skill이 만드는 설치 코드는 쓰기 작업보다 먼저 범위를 선택하도록 한다. Python 선택 도우미와 PowerShell 템플릿을 제공한다. 프로젝트는 사용자 작업 폴더, 전역은 현재 사용자 계정 기준이며 묵시적인 전역 기본값을 두지 않는다. 단일 MD는 실행 설치기가 없으므로 안내 첫 단계에서 범위를 선택해 수동 복사한다. 임의로 업로드한 기존 EXE·PS1의 내부 동작을 웹이 자동 변경하거나 검증하지는 않는다.

## 21. 개발 폴더와 실행 호환성

backend에는 API·SSO·MongoDB·파일 저장 코드를, frontend에는 기능별 JS를, scripts에는 개발·문서 생성 도구를, docs에는 설명 문서를 모은다. index.py·web_main.py·config.py·runtime_config.py·실행 명령·requirements는 최상위에 유지한다. 회사 기본 index.py는 web_main.app을 application으로 가져오며 직접 실행 시 application.run(debug=True, host='0.0.0.0')을 호출한다. 포트 인자나 다른 서버 실행 방식을 추가하지 않는다. WSGI 진입점은 index:application이며 기존 web_main:app도 같은 앱으로 호환된다. 상위 프로젝트 없이 폴더 단독으로 실행한다. static/app.js는 실제 브라우저 파일이고 확장 UI는 scripts/build_workspace.py로 조립한다. 초기 build_frontend.py는 역사적 디자인 가져오기 도구로 일상 개발에서 실행하지 않는다.
## 22. 관리자 저장 한도와 실제 디스크 조회

관리자 저장 공간 탭에 플랫폼 파일 사용량·디스크 남은 공간·추가 저장 가능량을 표시한다. 직접 지정/자동 계산, 플랫폼 최대 GB, 서버에 남겨둘 GB를 설정하고 즉시 저장한다. 저장 설정은 MongoDB settings/storage_limits 문서에 mode·quotaBytes·reserveBytes·revision·변경 관리자와 시각으로 기록한다. 환경 설정은 최초 관리자 설정 이전의 기본값이며, revision으로 동시 변경을 검출한다.

자동 한도는 현재 플랫폼 파일 사용량 + 실제 디스크 남은 공간 − 확보할 여유 공간이다. 직접 지정 모드의 추가 저장 가능량은 남은 플랫폼 한도와 디스크 여유 공간 중 작은 값이다. 음수는 0으로 표시한다. 현재 사용량보다 낮은 한도도 저장할 수 있지만 기존 자료를 지우지 않고 새 파일 저장만 막는다.

GET/PUT /api/storage/limits는 관리자만 호출한다. 디스크 수치는 DATA_DIR가 속한 볼륨을 운영체제로 조회하며 서버 전체·원격 MongoDB 용량을 의미하지 않는다. 조회 실패는 확인 불가로 표시하고 업로드를 중단한다. 배포 파일 검사·게시와 요청 첨부 저장이 같은 저장 한도를 적용한다. 저장 중 공간 부족은 507, 한도 초과는 409, 조회 실패는 503으로 안내하고 부분 파일을 제거한다. 파일 없는 URL·명령어 배포는 파일 한도로 제한하지 않는다.

보관 정책에 따른 이전 버전 삭제는 별도의 목록 확인·삭제 절차를 유지한다. 파일 저장의 쓰기 잠금은 한 프로세스 안에서 동작한다. 다중 프로세스/서버의 엄격한 공용 한도와 별도 컨테이너 할당량은 운영 파일시스템 quota로 관리한다. 더미 모드는 dummy/catalog.json의 예시 용량만 읽으며 실제 디스크를 조회하거나 설정을 저장하지 않는다.
## 로컬 수신 연계 추가 사항 (2026-10-20)

기존 등록·다운로드 구조에 로컬 수신과 배포 Skill 자동 게시 기능을 추가합니다. 설치·실행과 EXE 자동 변환은 수행하지 않습니다.

- 웹 상단 프로필 옆 **열쇠 아이콘**과 기존 **로컬에서 받기**에서 Skill ZIP과 사번별 연결 KEY 화면을 제공합니다.
- 클라이언트의 공통 JSON 설정에서 서버 주소를 바꿉니다. 운영 주소가 확정되기 전에는 동일 PC의 mock 서버로 시험합니다.
- 검색은 `GET /api/catalog`로 이름·설명·업무를 찾고 유형·조직·페이지를 지정합니다. 권한이 없는 항목은 카드 정보만 반환합니다.
- 연결 KEY는 SSO/mock 웹 세션으로 유효기간 선택 없이 발급합니다. 새 KEY는 `expires: null`로 저장하며 재발급·사용 취소·계정 비활성화 전까지 사용할 수 있습니다. 사번당 활성 KEY는 하나이며 재발급하면 이전 KEY의 이후 요청은 거절합니다. MongoDB에는 해시만 저장하고 현재 KEY ID·취소 상태·사용자 활성 상태·도구 권한을 매 요청에 확인합니다. 기존 기간형 KEY는 원래 만료일을 유지하며 이미 만료·취소된 KEY를 되살리지 않습니다.
- 인증키의 기본값은 조회·다운로드 전용입니다. 사용자가 업로드 포함으로 발급하면 신규 도구·관리 권한이 있는 도구의 새 버전 게시도 지원합니다. 기존 키는 자동으로 권한을 늘리지 않으며 삭제·권한 변경은 어느 키에도 허용하지 않습니다.
- 개인 API 화면에서 사번별·키별 게시/다운로드 건수와 최근 20개 이력을 확인합니다. 게시 기록은 버전과 함께 원자적으로 저장하고 다운로드는 기존 내구성 이벤트 대기열을 재사용합니다. 다운로드 건수와 순위는 웹과 API를 합쳐 사번·도구별 전체 기간 최초 1회만 반영하고 업데이트를 제외합니다.
- 파일 수신은 크기·SHA-256 확인과 최신 배포 재확인 후 저장하며, 기존 파일을 덮어쓰지 않습니다.
- 버전 확인은 정보 조회만 수행합니다. 다운로드 결과도 설치 완료로 간주하지 않습니다.
- URL·명령어형은 사용 안내만 제공합니다. 로컬 수신 Skill이 명령이나 파일을 자동 실행하지 않습니다.

구체적인 사용자 순서는 `docs/LOCAL_RECEIVER.md` 및 별도 HTML 가이드를 참고합니다.


## 배포 Skill 자동 게시

배포 Skill에는 prepare_package.py, publish_client.py, square_client.py를 함께 제공합니다. ZIP 선언과 실제 프로젝트 자료로 기본 정보를 채우고, 조직·업무 및 전체 공개/조회 승인 필요 여부를 확인한 후 게시합니다. 서버에는 LLM이 필요하지 않습니다. 단일 MD도 그대로 등록합니다. 저장된 서버·사번·자료별 도구 ID 또는 관리 가능한 동일 packageId로 기존 도구를 찾으며 모호하면 사용자에게 선택을 요청합니다. 공개 범위를 명시하지 않으면 게시하지 않습니다. 준비안의 clientRequestId로 동일 요청 재전송 시 중복 게시를 막고, 새 버전은 기존 revision으로 충돌을 검사합니다.

키가 없거나 인증에 실패하면 설정된 서버의 인증키 관리 페이지를 브라우저로 열고, 실패하면 링크를 반환합니다. 원문 키는 재조회하지 않으며 사용자 직접 발급·숨김 입력을 유지합니다. 업데이트 수신은 purpose=update로 명시하며 최초 수신 기록이 없어도 집계에서 제외합니다. 과거 일별 자료는 최초 날짜로 묶어 통계를 계산합니다.

## SSO 프로필과 사번 기반 데이터 연결 (2026-10-22)

회사에서 확인한 session['emp_no']는 사번, session['emp_name']은 이름, session['dept']는 부서명, session['dept_cd']는 부서 코드다. 기존 users._id를 사번으로 유지하고 네 항목을 같은 문서에 명시적으로 저장한다. 기존 name·orgId도 유지하여 화면·도구 등록자·권한 신청·알림·연결 KEY의 참조를 끊지 않는다. 인증된 SSO 로그인에서 프로필을 갱신하며 DB 초기화나 기존 사번 ID 변경은 하지 않는다. 아직 갱신되지 않은 문서는 이전 필드로 표시한다.

조직은 부서 코드와 기존 조직 ID를 연결하고 사용자의 최신 부서명은 별도로 보관한다. 이름이나 부서명이 바뀌더라도 같은 사번이 소유한 도구와 승인 이력은 그대로다. SDK의 쿠키 검증은 유효한 SSO 인증 세션이 없는 로그인 경로에서 수행한다. 인증된 신원·시각 표식이 있는 서명 세션만 최대 8시간 허용하며 일반 요청으로 만료 시각을 연장하지 않는다. 이전 프로필 문자열·logFlag만 있는 세션은 다시 로그인한다. 일반 페이지·API·삭제는 SDK를 다시 호출하지 않고 매 보호 요청의 MongoDB 계정 활성 상태·현재 역할·도구 권한을 검사한다. 회사 SSO 로그아웃은 기존 앱 세션을 즉시 취소하지 않으며 플랫폼 로그아웃·8시간 만료·DB 계정 비활성화가 접근을 차단한다.

사용자 API의 기존 org 별칭은 관리자가 정한 taxonomy 조직명을 유지하고 dept는 실제 SSO 부서명을 나타낸다. 프로필은 dept를 우선 표시한다. 두 값을 항상 같은 문자열로 강제하지 않아 관리자의 기존 분류 편집과 SSO 신원 갱신을 함께 보존한다.

상단에는 이름 TL, 부서명, 원형 사진과 연결 KEY 아이콘을 표시한다. TL은 화면 표기이며 관리자 권한이나 SSO 직책 매핑에 사용하지 않는다. 사진은 로그인한 사번으로 고정된 회사 사진 주소를 조회하는 GET /api/me/photo를 통해 제공한다. 회사 사진 서버에 브라우저 Cookie·Authorization을 전달하지 않고, 리디렉션·과도한 파일 크기·이미지 외 응답을 차단한다. 사진 실패 시 이름 첫 글자로 대체한다. mock·dummy에서는 실제 회사 사진을 요청하지 않는다. 브라우저에는 no-store를 적용하여 같은 브라우저의 계정 전환 시 다른 직원 사진이 남지 않게 한다.

## 함께 만드는 사람들

홈 순위 선택에 **실시간 / 누적 / 함께 만드는 사람들**을 제공한다. 함께 만드는 사람들은 도구를 개발·등록한 사람의 공유 기여도이며 전체 기간으로만 계산한다. 본인이 다른 도구에서 누른 좋아요·다운로드를 합산하는 사용자 활동 순위가 아니다.

순위 행은 부서 → 이름 → 원형 사진 순서로 정렬하며, 활동 수치는 다음 줄에 표시한다. 사진은 SSO 모드에서 활성 구성원이 등록한 삭제되지 않은 도구가 있을 때만 GET /api/people/사번/photo로 제공한다. 기존 사진 프록시의 고정 주소·형식 검사·캐시를 재사용하며 mock·dummy 또는 조회 실패 시 이름 첫 글자로 대체한다.

점수는 **등록한 도구 수 × 5 + 해당 도구들이 받은 좋아요 수 × 2 + 고유 다운로드 수 × 1**이다. 예를 들어 도구 2개, 받은 좋아요 7개, 고유 다운로드 3회면 27점이다. 한 도구에 버전이 여러 개여도 등록 수는 1개다. 본인 도구에 대한 본인 반응, 좋아요 취소, 반복 다운로드, 업데이트, 삭제 도구는 제외한다. 비활성 등록자는 표시하지 않는다. 동점은 등록 도구 수 → 받은 좋아요 수 → 고유 다운로드 수 → 사번 순이다.

GET /api/people/ranking은 MongoDB의 tools·users·activity_state를 집계하여 TOP 10과 현재 사용자의 순위·점수, 산식을 반환한다. 기존 일별 다운로드는 사용자·도구별 최초 수신으로 묶고 신규 update-only 기록은 제외한다. 서버의 권한 검사를 통과한 직원만 조회할 수 있으며 승인형 도구의 개별 이름이나 상세 내용은 반환하지 않는다. 사용자 이름·조직·등록 수·받은 반응 합계만 표시한다.

사용자는 홈에서 함께 만드는 사람들을 누르고 정보 아이콘으로 산식을 확인한다. 등록한 도구가 없는 사람은 등록 기여도가 0으로 표시된다. TOP 10은 1~5위와 6~10위 자동 전환을 유지하며 **집계 새로고침**으로 최신 합계를 확인한다.

## 사번당 하나의 연결 KEY

사용자는 상단 프로필 옆 열쇠 아이콘 → **내 연결 KEY**로 이동한다. 이름·허용 작업을 선택하고 처음에는 **연결 KEY 발급**, 이후에는 **KEY 재발급**을 누른다. 유효기간 선택 항목은 없으며 새 KEY에는 기간 제한이 없다. 원문은 그때 한 번만 보여주고 **KEY 복사**로 연결 프로그램에 전달한다. 서버는 이름이 아니라 로그인한 사번에 KEY를 연결한다.

MongoDB의 `users._id`는 사번이며 `users.activeConnectionKeyId`가 현재 인증할 KEY를 한 개 가리킨다. `local_tokens.user`에 같은 사번을, `local_tokens._id`에 KEY의 SHA-256 해시를 저장한다. 재발급의 활성 KEY 교체는 단일 사용자 문서 갱신으로 처리하며, 인증 시 해시·취소·활성 사용자·현재 KEY ID를 모두 검사한다. 새 KEY의 `expires: null`만 기간 제한 없음으로 취급하며, 기존 숫자형 만료일은 계속 검사한다. 필드 누락·잘못된 값은 인증하지 않는다. 따라서 같은 사번의 과거 KEY가 남아 있어도 현재 KEY가 아니면 사용할 수 없다. 이전 local_tokens 기록과 사용 이력은 삭제하지 않고 보관하여 누적 집계를 유지한다. 재발급 전에 이미 인증을 마친 실행 중 작업을 강제로 중단하는 기능은 아니다.

이전 화면이나 클라이언트가 발급 API에 `days`를 보내면 400 응답으로 화면 새로고침을 안내한다. 기간을 지정한 요청을 서버가 임의로 무기한 KEY로 바꾸어 발급하지 않는다.

이전 여러 KEY 방식에서 업그레이드한 사번은 첫 KEY 조회·인증 때 가장 최근 유효한 KEY 하나를 현재 KEY로 연결한다. 가장 최근 KEY 원문을 잃어버렸다면 새 KEY를 발급하고 기존 연결 프로그램도 갱신한다. 취소 후 옛 KEY가 자동으로 다시 활성화되지 않는다.

조회·다운로드 전용과 업로드 포함 권한은 유지한다. 어느 KEY도 도구 삭제·관리자 설정·권한 승인·다른 KEY 발급을 허용하지 않는다. 향후 CUBE·MCP·앱 연동의 사번 식별 수단으로 활용할 수 있지만 각 서비스의 실제 연결 기능이 이번 변경으로 자동 제공되는 것은 아니다.

## 카드 소개와 배포 정보 기반 동작 흐름

도구 카드에는 관련 업무 태그 외에 소개를 최대 두 줄로 표시한다. 소개 전체는 상세 팝업에서 읽는다. 배포 Skill은 실제 프로젝트의 입력·처리·출력을 확인해 ai-square.json에 선택 항목 workflow를 작성할 수 있다. 웹은 이 구조를 받아 단계 카드와 화살표로 표시한다.

```json
{
  "workflow": {
    "steps": [
      {"title": "자료 받기", "description": "사용자가 점검 Excel 파일을 선택합니다."},
      {"title": "점검 항목 비교", "description": "입력 자료와 기준을 비교합니다."},
      {"title": "결과 안내", "description": "확인할 항목을 보고서로 제공합니다."}
    ]
  }
}
```

steps는 1~8개이며 제목은 60자, 설명은 240자 이내로 제한한다. 단계는 순서대로 표시하는 설명 자료이고 임의 HTML·스크립트·실행 명령을 처리하지 않는다. 웹에서 LLM으로 자유 설명을 추론하거나 등록 코드를 실행하지 않는다. 정보가 없으면 흐름 영역을 숨기고, 잘못된 배포 선언은 기존 파일 등록 원칙에 따라 경고 후 수동 입력으로 진행할 수 있다.

등록자가 배포 파일을 준비하고 **배포 정보를 입력란에 적용**한 뒤 게시하면, 조회 권한이 있는 사용자는 도구 상세 소개의 **이렇게 동작해요.**에서 흐름을 읽는다. 흐름은 배포 버전과 함께 저장하며 새 버전에서 바뀐 경우 갱신한다. 조회 승인 전에는 동작 흐름을 제공하지 않는다. 도식은 실제 실행 상황이나 실행 성공 검증을 뜻하지 않는다.
