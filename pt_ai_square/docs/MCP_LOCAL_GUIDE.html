P&T AI SQUARE · LOCAL MCP · 2026.10.24

서버를 새로 만들지 않고,
내 PC의 AI와 연결합니다.

로컬 MCP는 AI가 사용할 작은 연결 프로그램입니다. 내 PC에서 실행되어 기존 AI SQUARE 웹에 검색·다운로드·게시를 요청합니다. 기존 웹과 MongoDB는 계속 실행되어 있어야 합니다.

1. 플랫폼 파일을 업데이트합니다 · 운영자

기존 runtime_config.py, 업로드 저장소와 MongoDB 데이터는 유지합니다. 새 소스의 backend/, __init__.py, templates/, static/, integrations/, receiver/, scripts/, 문서를 함께 반영하고 웹을 재시작합니다. index.py와 web_main.py의 실행 방식·포트·SSO는 이번 기능에서 바꾸지 않았습니다.

웹 서버에 MCP SDK를 설치할 필요는 없습니다. SDK는 아래에서 사용자의 전용 로컬 환경에만 설치합니다. 새로운 DB 계정이나 MongoDB 주소를 사용자에게 배포하지 않습니다.

2. KEY와 MCP 파일을 받습니다 · 사용자

  1. 기존 웹에 로그인한 뒤 우측 상단 열쇠 아이콘을 누릅니다.
  2. 조회·다운로드만 필요하면 읽기 권한, 도구 등록도 하려면 업로드 포함을 선택하고 연결 KEY 발급을 누릅니다.
  3. 같은 화면의 로컬 MCP 받기를 눌러 ZIP을 받고 원하는 폴더에 풉니다. 예: C:\도구\pt-square-mcp.

KEY 원문은 발급 직후 한 번만 보입니다. 재발급하면 기존 KEY는 즉시 해제됩니다. 채팅에 KEY를 붙여넣지 않습니다.

3. 로컬 연결을 준비합니다 · 사용자

Python 3.11 이상을 준비합니다. 압축을 푼 폴더에서 PowerShell을 열고 아래 순서로 실행합니다. 마지막 줄의 웹 주소와 실제 작업 폴더를 본인 값으로 바꾸세요.

python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe .\run_mcp.py setup --url "http://회사서버주소" --workspace "C:\Users\내사번\Desktop\공유할도구"

회사에서 지정한 Python 저장소가 있다면 pip에 그 저장소를 사용합니다. 작업 폴더는 먼저 만들어 두며 여러 폴더는 --workspace를 반복합니다.

HTTP 연결: setup에서 암호화되지 않은 연결임을 안내하고 정확한 서버 주소를 다시 입력받습니다. 지정한 주소로만 KEY를 전송하지만 HTTP 자체가 암호화되지는 않습니다.

이어서 KEY를 숨김 입력창에 붙여넣습니다. KEY가 없으면 Enter를 누르면 웹 발급 화면으로 안내합니다. Windows에서는 현재 사용자 계정에 묶인 DPAPI로 KEY를 암호화해 보관합니다. 설정은 %USERPROFILE%\.pt-ai-square\mcp 아래에 있습니다. .env 파일은 사용하지 않습니다.

4. AI 프로그램의 MCP 설정에 추가합니다

Claude Code 등 로컬 stdio MCP를 지원하는 프로그램의 설정에 다음 항목을 추가합니다. 실제 압축 해제한 절대 경로로 바꾸고 기존 MCP 항목은 유지합니다.

{
  "mcpServers": {
    "pt-ai-square": {
      "command": "C:\\도구\\pt-square-mcp\\.venv\\Scripts\\python.exe",
      "args": ["C:\\도구\\pt-square-mcp\\run_mcp.py", "serve"]
    }
  }
}

AI 프로그램을 다시 시작하고 “AI SQUARE 연결 상태 확인해줘”라고 요청합니다. 웹 전용 ChatGPT에 이 로컬 설정을 그대로 넣어 연결할 수는 없습니다.

5. 이렇게 사용합니다

하고 싶은 일사용자 요청과 결과
검색·추천“메일 검색 도구 찾아줘.” 이름·태그·설명·업무를 검색합니다. 같은 현재 부서에서 충분한 이용자가 있는 경우 추천 이유를 함께 제공합니다.
순위“실시간 TOP 10 보여줘.” 최근 7일 좋아요×2 + 고유 다운로드×1입니다. “누적”은 전체 기간입니다.
파일 받기·설치“이 Skill을 지금 프로젝트에 설치해줘.” 위치·변경 내용을 확인하고 파일을 받아 무결성을 검증합니다. 지원하는 설치 정보가 있는 항목만 자동 설치합니다.
신규 등록“이 폴더의 Skill을 등록해줘.” 설명·흐름·조직·업무·공개 범위를 준비하고 서버 초안을 만듭니다. 웹 확인 화면에서 사용자가 승인한 뒤 AI 대화에서 게시를 이어갑니다.
새 버전본인 기존 도구 후보가 있으면 업데이트인지 신규 등록인지 확인합니다. 승인된 초안으로 게시하면 같은 도구에 새 배포 번호가 생깁니다.
버전 확인“설치한 도구가 최신인지 확인해줘.” 버전만 확인하고 파일을 자동으로 교체하지 않습니다.

6. 설치와 권한에서 알아둘 점

  • 프로젝트 또는 현재 사용자 설치 범위를 확인합니다. 범위 선택 없이 전역 설치하지 않습니다.
  • Skill MD·ZIP 배치, 선언된 Python/Node MCP 설정, 설치기 실행을 구분합니다. 일반 터미널 명령과 미지원 형식은 안내를 보여줍니다. pip/npm 의존성은 자동 설치하지 않습니다.
  • 설치기 실행은 설치 완료와 다릅니다. EXE가 수정한 시스템 상태 전체를 되돌리는 기능은 아닙니다.
  • 관리자 KEY도 남의 도구 게시·삭제·권한 변경을 할 수 없습니다. 웹 관리자 메뉴의 권한은 기존대로 유지합니다.
  • MCP에는 MongoDB 인증정보나 DB 명령 도구를 넣지 않습니다. MCP 소스를 고쳐도 웹 서버의 소유권·승인 검사를 통과해야 합니다.
  • 다운로드는 웹과 합쳐 사번·도구당 최초 1회만 집계합니다. 반복 다운로드와 업데이트는 추가 집계하지 않습니다.
  • 게시 초안은 24시간 유효합니다. 만료·KEY 교체·파일 변경·다른 버전 게시 후에는 새 초안으로 확인합니다.

7. 문제가 있을 때

401: KEY가 재발급·취소되었는지 확인하고 setup을 다시 실행합니다.
403: 도구 조회 권한, 업로드 포함 KEY, 본인 소유 여부를 확인합니다.
409: 웹 승인 전인지, 검토 이후 버전이 바뀌었는지 확인합니다. 결과가 불명확하면 같은 초안으로 상태를 확인합니다.
HTTP 안내: 운영 주소를 HTTPS로 임의 변경하지 말고 실제 주소를 setup에서 확인합니다.
pip 설치 실패: 회사 Python 저장소와 설치 가능한 패키지를 담당자에게 확인합니다.

정확한 설치 선언 예와 도구 목록은 ZIP 안 README.md를 참고하세요. 사내 실제 SSO·운영 네트워크·모든 제3자 설치기의 실행은 운영 환경에서 별도 확인이 필요합니다.
