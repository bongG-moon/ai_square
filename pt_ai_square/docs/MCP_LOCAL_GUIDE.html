P&T AI SQUARE · LOCAL MCP · 2026.10.25

주소와 폴더는 자동으로.
내 KEY로 연결합니다.

사이트에서 받은 MCP를 실행하고 개인 KEY를 한 번 입력하세요. 서버 주소는 자동으로 채워지고, 다운로드 폴더도 내 PC에 자동으로 만들어집니다.

서버 주소 자동 설정다운로드 폴더 자동 생성실제 계정 인증 확인

이미 MCP가 등록되어 있다면 다시 등록할 필요가 없습니다. 최신 ZIP을 기존 MCP 위치에 반영하고 아래 KEY 연결을 진행한 뒤, 코드를 교체한 AI 프로그램을 다시 시작하세요. 기존 .venv와 개인 설정은 보존합니다.

STEP 01 · 사이트에서 받기

KEY와 MCP ZIP을 받습니다.

  1. AI SQUARE에 로그인하고 우측 상단 열쇠 아이콘을 누릅니다.
  2. 도구 등록까지 사용하려면 허용 작업 → 업로드 포함 → 연결 KEY 발급을 누릅니다. 검색·다운로드만 필요하면 읽기 KEY를 선택합니다. 이미 보관한 유효한 KEY는 그대로 사용할 수 있습니다.
  3. 같은 화면의 다른 방식으로 연결하기 → AI에서 MCP로 연결하기를 펼친 다음 로컬 MCP 받기를 눌러 ZIP을 받고 압축을 풉니다.

사이트에서 받는 ZIP의 connection.json에는 해당 사이트 주소만 포함됩니다. 개인 KEY나 사번은 들어 있지 않습니다. GitHub에서 직접 받은 공통 ZIP에는 운영 주소가 없으므로, 자동 연결을 사용하려면 웹 화면에서 받으세요.

로컬 MCP는 Python 코드가 담긴 ZIP으로 제공하며 EXE 설치 파일로 자동 변환하지 않습니다. 완성된 앱·플러그인 설치 파일은 AX Workspace 탭에서 관리자가 별도로 등록해 배포합니다.

KEY 원문은 발급 직후 한 번만 표시됩니다. 재발급하면 이전 KEY는 사용할 수 없으므로, 이미 연결한 프로그램에도 새 KEY를 반영해야 합니다.

STEP 02 · 개인 KEY 입력

Connect.cmd를 더블클릭합니다.

Windows에 Python 3.11 이상이 필요합니다. 압축을 푼 폴더에서 Connect.cmd를 실행하면 연결 창이 열립니다.

  1. 자동 표시된 서버 주소와 다운로드 폴더를 확인합니다. 직접 입력하지 않아도 됩니다.
  2. 개인 KEY 입력란에 KEY를 붙여넣습니다. 입력 내용은 가려집니다.
  3. HTTP 사이트라면 암호화되지 않은 연결 안내에 체크합니다. 주소를 다시 타이핑할 필요는 없습니다.
  4. 연결하기를 누릅니다. 서버에서 KEY를 확인한 뒤 본인 이름·부서가 표시되면 완료입니다.

잘못된 KEY나 서버 연결 실패가 발생하면 기존의 정상 연결 설정을 덮어쓰지 않습니다. KEY는 Windows의 현재 사용자 계정으로 암호화해 보관하며, 대화창이나 실행 명령줄에 입력하지 않습니다.

HTTP 안내는 암호화 기능이 아닙니다. 현재 사이트에 연결한다는 것을 한 번 확인하는 절차입니다. 회사 웹의 주소·포트·SSO 방식을 임의로 변경하지 않습니다.

AUTOMATIC DOWNLOADS

받은 파일은 여기에서 확인합니다.

C:\Users\내계정\AI_SQUARE\downloads\
└─ server-서버식별자\
   └─ tool-123\
      ├─ v1\
      └─ v2\

계정 이름은 자동으로 인식합니다. 폴더는 필요할 때 생성하고 서버·도구·버전별로 나누어 저장합니다. 로컬 시험 사이트와 운영 사이트에 같은 도구 번호가 있어도 파일이 섞이지 않습니다. 다운로드 결과에 실제 저장 경로가 표시됩니다.

다운로드 폴더와 실제 설치 위치는 다릅니다. 파일은 자동 폴더에 받고, 설치할 때 현재 프로젝트 / 내 계정 중 범위를 선택합니다. 업로드할 원본이나 설치할 프로젝트가 허용 범위 밖이면 AI가 여는 폴더 선택 창에서 해당 폴더를 직접 선택합니다. 취소하면 접근 범위가 늘어나지 않습니다.

FIRST INSTALL ONLY

처음 사용할 때만 AI에 MCP를 등록합니다.

이미 pt-ai-square가 등록되어 있다면 이 단계는 건너뜁니다. 처음이라면 압축을 푼 폴더에서 PowerShell을 열어 전용 실행 환경을 만듭니다.

python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt

공식 MCP SDK는 PC의 이 가상환경에 설치합니다. 회사망에서는 기존 사내 Python 패키지 저장소를 사용하세요. 연결 창은 Python 기본 기능으로 실행되므로 SDK 설치보다 먼저 KEY를 연결해도 됩니다.

사용하는 AI 프로그램의 MCP 설정에 다음 항목을 추가합니다. 예시 경로를 실제 압축 해제한 절대 경로로 바꾸고 기존 MCP 항목은 유지합니다. 등록 범위는 현재 프로젝트 또는 내 계정 중 선택합니다.

{
  "mcpServers": {
    "pt-ai-square": {
      "command": "C:\\Users\\내계정\\Tools\\pt-square-mcp\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\내계정\\Tools\\pt-square-mcp\\run_mcp.py", "serve"]
    }
  }
}

KEY는 위 JSON에 넣지 않습니다. AI 프로그램을 다시 시작한 뒤 “AI SQUARE 연결 상태 확인해줘”라고 요청합니다.

Claude의 Connected는 로컬 MCP와 통신한다는 뜻입니다. AI SQUARE 계정 연결은 실제 서버 인증에 성공하고 본인 정보가 조회되는 것까지 확인합니다. 웹 전용 ChatGPT에는 이 로컬 MCP 설정을 그대로 적용할 수 없습니다.

연결 후에는 이렇게 요청하세요.

하고 싶은 일요청 예시와 동작
검색·추천“메일 조회 도구 추천해줘.” 이름·태그·설명·업무를 검색하고, 제공되는 부서 선호 정보를 추천 근거로 안내합니다.
파일 받기“첫 번째 도구를 받아줘.” 자동 다운로드 폴더에 받고 저장 경로를 알려줍니다. 이 단계에서 파일을 실행하지 않습니다.
설치“이 Skill을 현재 프로젝트에 설치해줘.” 설치 범위·경로·변경 내용을 확인하고 진행합니다. 지원하는 설치 정보가 있는 항목만 자동 설치할 수 있습니다.
신규 등록“내가 만든 Skill을 등록해줘.” 필요하면 원본 폴더를 직접 선택합니다. 설명·흐름·조직·업무·공개 범위를 확인하고 웹에서 승인한 뒤 게시합니다.
새 버전기존 본인 도구 후보가 있으면 신규인지 업데이트인지 확인합니다. 승인된 내용으로 게시하면 같은 도구에 새 배포 번호가 생깁니다.
버전 확인“설치한 도구가 최신인지 확인해줘.” 버전만 확인하고 PC 파일을 자동으로 교체하지 않습니다.
KEY 다시 연결“AI SQUARE KEY 다시 연결해줘.” 현재 서버에 연결하는 숨김 입력 창을 엽니다. 새 KEY는 그 창에만 입력합니다.

다운로드는 웹·MCP를 합쳐 사번·도구당 최초 1회만 집계합니다. 반복 수신과 업데이트는 추가 집계하지 않습니다. 기존 업로드 파일은 그대로 검색·다운로드할 수 있고, 자동 설치는 설치 정보가 등록된 항목에 한해 지원합니다.

RECONNECT · 재설치 없이

KEY가 바뀌면 입력 창에서 다시 연결하세요.

MCP에서 401 인증 오류가 발생하면 현재 연결된 서버의 KEY 발급 화면 링크와 재연결 방법을 안내합니다. 예를 들어 현재 주소가 http://회사서버:5000이면 링크는 http://회사서버:5000/local-access입니다. 화면에 나온 실제 링크를 누르면 됩니다.

  1. 안내된 링크를 눌러 회사 웹에 로그인하고 내 연결 KEY → KEY 재발급에서 필요한 허용 작업을 선택합니다.
  2. 새 KEY를 복사한 뒤 AI에게 “AI SQUARE KEY 다시 연결해줘”라고 요청합니다.
  3. 인자가 없는 reconnect_key 도구가 개인 입력 창을 엽니다. 현재 서버 주소를 확인하고 가려진 개인 KEY 입력란에 새 KEY를 넣습니다. HTTP이면 연결 안내에도 체크합니다.
  4. 연결하기를 누르고 본인 이름·부서가 확인되면 완료입니다. 다음 요청부터 새 KEY를 사용합니다.

KEY는 대화창이나 MCP 도구 인자에 넣지 않습니다. 재연결 창은 현재 MCP 설정의 서버 주소로 열립니다. 다른 서버나 별도 설정 파일을 사용 중이어도 현재 연결을 유지합니다. 최초 연결 전이라면 웹에서 받은 ZIP의 Connect.cmd를 먼저 사용하세요.

KEY만 바뀐 경우 MCP나 설치한 도구를 재설치할 필요는 없습니다. Connect.cmd를 직접 실행하는 대안도 있으며, 이때는 ZIP의 사이트 주소가 현재 MCP와 같은지 확인하세요. 예전 MCP에 재연결 도구가 없으면 최신 코드·ZIP을 반영한 후 AI 프로그램을 다시 시작합니다.

재연결이 중단된 설치·업로드를 자동으로 다시 실행하지는 않습니다. 게시 초안은 생성한 KEY ID에 연결되어 있으므로 재발급 후에는 새 초안을 만들고 웹에서 다시 승인합니다. 이미 게시한 도구·버전과 PC의 설치 파일은 유지됩니다.

연결 창이 열리지 않거나, KEY를 바꿨다면

Python에 Tk가 없어 연결 창이 열리지 않습니다.

압축을 푼 폴더의 PowerShell에서 아래 명령을 실행합니다. 웹에서 받은 ZIP이면 주소·폴더 옵션 없이 진행할 수 있습니다.

python .\run_mcp.py setup

HTTP 확인 질문에 답하고 KEY를 숨김 입력에 넣습니다. 연결 확인은 다음 명령으로도 가능합니다.

python .\run_mcp.py status
KEY를 재발급했습니다.

AI에게 “AI SQUARE KEY 다시 연결해줘”라고 요청하고 열린 개인 입력 창에 새 KEY를 넣습니다. 현재 서버 인증에 성공하면 다음 요청부터 새 KEY를 사용합니다. Connect.cmd를 직접 사용할 때는 표시된 사이트가 현재 MCP와 같은지 확인합니다. KEY만 갱신하면 재설치가 필요 없지만, MCP 코드 자체를 업데이트한 경우에는 AI 프로그램을 다시 시작합니다.

서버 주소가 없다고 나옵니다.

웹의 로컬 MCP 받기에서 최신 ZIP을 받으세요. GitHub 공통 ZIP 또는 예전 ZIP에는 사이트 주소가 없을 수 있습니다. 개발자가 직접 연결할 때만 setup --url "http://회사서버주소"을 사용할 수 있습니다.

401 / 403 / 409 / 서버 접속 오류는 어떻게 다른가요?

401: KEY 만료·취소·재발급 또는 사용자 비활성화 등으로 인증할 수 없습니다. 안내된 현재 사이트의 KEY 링크를 확인하고 필요하면 새 KEY로 연결합니다. 계정 비활성화는 운영자에게 문의합니다.
403: 해당 도구 조회 권한·업로드 포함 KEY·본인 소유 여부를 확인합니다. 재연결만으로 권한이 생기지는 않습니다.
409: 게시 초안의 웹 승인 상태와 버전 충돌을 확인합니다. 같은 KEY로 통신을 재시도할 때는 기존 초안 상태를 먼저 확인하고, KEY를 재발급했다면 새 초안과 웹 승인이 필요합니다.
접속 실패·5xx: 사내망·서버 상태를 확인합니다. 이 오류만으로 KEY가 만료되었다고 판단하지 않습니다. 저장 요청이었다면 반영 여부를 먼저 확인합니다.

고급 설정: 추가 작업 폴더 / 환경변수 방식

별도 원본 폴더는 폴더 선택 창에서 허용하는 것이 기본입니다. CLI에서는 setup --workspace "C:\내작업폴더"로 기존 폴더를 추가할 수 있습니다. 드라이브 전체는 허용하지 않습니다.

--token-from-env는 KEY를 저장하는 옵션이 아닙니다. MCP를 실행하는 프로세스가 매번 PTAI_API_TOKEN 환경변수에서 읽는 자동화용 방식입니다. 이 방식을 계속 쓴다면 재발급 후 환경변수를 갱신하고 AI 프로그램을 다시 시작합니다. 일반 Windows 사용자는 개인 입력 창의 암호화 저장을 사용합니다.

운영자가 반영할 내용

기존 runtime_config.py, 업로드 저장소와 MongoDB 데이터는 그대로 유지합니다. 이번 변경으로 KEY를 일괄 재발급하거나 DB를 초기화하지 않습니다. 회사의 index.py·web_main.py 진입점과 포트도 유지합니다.

웹의 MCP 다운로드 처리, KEY 화면, MCP 원본·ZIP과 가이드를 함께 반영하고 웹을 재시작합니다. 새 ZIP을 웹에서 받아 connection.json에 실제 접속 주소가 들어 있는지 확인한 뒤 KEY 연결을 시험합니다. 웹 서버에는 MCP SDK를 추가로 설치할 필요가 없습니다.

웹은 KEY·사번·쿠키를 ZIP에 넣지 않습니다. PC는 웹 API로만 검색·다운로드·본인 도구 게시를 요청하며 MongoDB 주소나 계정을 받지 않습니다. 등록 전 웹 승인과 서버의 소유권 검사는 계속 적용됩니다.

정확한 설치 선언과 고급 사용법은 ZIP 안 README.md를 참고하세요. 실제 사내 네트워크·SSO·개별 설치 프로그램 동작은 운영 환경에서 확인합니다.
