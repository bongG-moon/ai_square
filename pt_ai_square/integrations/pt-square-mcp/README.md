# P&T AI SQUARE 로컬 MCP

Claude Code 등 **로컬 stdio MCP를 지원하는 프로그램**에서 실행합니다. 별도 MCP 호스팅 서버나 포트를 열지 않습니다. 기존 AI SQUARE 웹 서버에는 연결되어야 합니다. MongoDB 주소·계정·웹 서버 폴더 접근 권한은 이 패키지에 포함되지 않습니다.

처음에는 **준비 → KEY와 ZIP 받기 → AI에 MCP 등록 → 채팅에서 KEY 연결 → 실제 연결 확인** 순서로 진행합니다. MCP가 등록되어 있다면 **“AI SQUARE 연결해줘”**라고 요청하세요. 안내에 따라 채팅에서 개인 KEY를 전달하면 연결되므로 프로그램 경로를 찾아 실행할 필요가 없습니다. 채팅·모델·도구 호출 기록에 KEY가 남을 수 있다는 점을 먼저 확인하세요.

## 1. 내 PC에 필요한 프로그램 확인

Python **3.11 이상**과 **로컬 stdio MCP를 지원하는 AI 프로그램**이 필요합니다. 아래 AI 등록 명령은 Claude Code를 사용하는 경우의 예시입니다. 다른 AI에서는 그 프로그램의 로컬 MCP 설정 안내를 따릅니다.

Windows 시작 메뉴에서 **PowerShell**을 열고 `python --version`을 입력해 Enter를 누르세요. `Python 3.11` 이상이 표시되어야 합니다. 설치되지 않았다면 회사에서 허용하는 방법으로 Python을 준비하고 새 PowerShell 창에서 다시 확인합니다. Claude Code를 사용할 경우 `claude --version`으로 실행 가능한지도 확인합니다. 이 단계에는 KEY를 입력하지 않습니다.

## 2. 웹에서 개인 KEY와 MCP ZIP 받기

1. AI SQUARE 웹에 로그인하고 우측 상단 **열쇠 아이콘**을 누릅니다.
2. **연결 KEY 발급**을 누릅니다. 개인 KEY 하나로 검색·다운로드·좋아요와 본인 도구 신규 등록·새 버전 게시를 사용할 수 있습니다. 예전에 발급한 유효한 읽기 KEY도 같은 기능을 사용하며, 권한 선택이나 재발급은 필요 없습니다.
3. 같은 화면의 **내 PC에서 시작하기 → MCP로 연결하기 → 로컬 MCP 받기**를 누릅니다. 다운로드 버튼은 확장 프로그램 안내 아래에 항상 표시됩니다. 번호가 붙은 연결 순서는 필요할 때 펼쳐볼 수 있습니다. **MCP 설치 안내서**에서 상세 순서도 확인할 수 있습니다.
4. 받은 ZIP을 마우스 오른쪽 버튼으로 눌러 **모두 압축 풀기**를 선택합니다. 압축이 풀린 폴더 안에 `Connect.cmd`, `run_mcp.py`, `requirements.txt`가 보이는지 확인하세요. 이후 AI가 이 폴더에서 실행하므로 임의로 이동하거나 삭제하지 않습니다.

사이트에서 받은 ZIP의 `connection.json`에는 **다운로드한 사이트 주소만** 들어 있습니다. KEY나 사번은 들어 있지 않습니다. 서버 주소와 작업 폴더를 직접 입력하지 않아도 됩니다. GitHub 저장소에서 직접 받은 공통 ZIP에는 사이트 주소가 없으므로, 처음 연결할 때는 웹에서 다시 받거나 아래 고급 설정의 `--url`을 사용하세요.

이 로컬 MCP는 Python 코드가 담긴 ZIP으로 제공하며 EXE 설치 파일로 자동 변환하지 않습니다. 완성된 앱·플러그인 설치 파일은 **AX Workspace** 탭에서 관리자가 별도로 등록해 배포합니다.

## 3. 처음 사용하는 경우에만 AI 프로그램에 MCP 등록

이미 Claude Code 등에 `pt-ai-square`가 등록되어 있다면 **같은 경로에 새 파일을 반영하고 AI 프로그램을 다시 시작한 뒤 채팅에서 KEY 연결**을 진행합니다. 같은 MCP를 반복해서 추가할 필요는 없습니다. 압축을 푼 위치를 바꾸었다면 AI 프로그램에 등록된 실행 경로도 새 위치로 맞춰야 합니다.

Claude Code에 설치를 맡기려면 압축을 푼 MCP 폴더를 작업 폴더로 열고 아래처럼 요청할 수 있습니다. 실제 파일을 확인하고 **내 계정 / 현재 프로젝트** 중 등록 범위를 선택한 뒤 진행하세요. 기존의 다른 MCP 설정은 유지합니다.

> 현재 폴더의 pt-square-mcp를 설치해줘. run_mcp.py와 requirements.txt를 확인하고, 전용 .venv에 필요한 라이브러리를 설치해줘. 등록 범위는 내 계정과 현재 프로젝트 중 먼저 선택받아줘. 기존 MCP 설정을 보존하고 pt-ai-square로 등록한 뒤 실제 도구 연결을 확인해줘. 등록이 끝나면 connect_account로 연결 주소와 KEY 입력 안내를 보여줘. KEY를 명령줄이나 MCP 설정 JSON에 넣지 말고, 채팅 입력은 대화·모델·도구 호출 기록에 남을 수 있다고 먼저 알려줘.

처음에는 MCP가 아직 등록되지 않았으므로 Claude Code가 로컬 파일·명령 실행 도구로 설치를 진행합니다. MCP 도구가 나타나지 않으면 Claude Code를 다시 시작한 뒤 **“AI SQUARE 연결해줘”**라고 요청합니다. 회사의 설치 권한과 패키지 저장소 설정은 그대로 따릅니다.

직접 등록하려면 다음 순서를 따르세요.

처음 사용하는 경우에는 파일 탐색기에서 **`run_mcp.py`와 `requirements.txt`가 보이는 폴더**를 엽니다. 위쪽 주소 표시줄에 `powershell`을 입력하고 Enter를 누르면 그 폴더에서 PowerShell이 열립니다. 아래 두 줄을 **한 줄씩 입력하고 Enter**를 누르세요. 첫 줄은 이 MCP 전용 실행 환경을 만들고 두 번째 줄은 필요한 라이브러리를 설치합니다.

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

공식 MCP Python SDK **1.30.0**을 이 MCP 전용 가상환경에 설치합니다. 회사망에서 pip가 차단되어 있다면 회사의 Python 패키지 저장소를 사용하세요. 관리자 권한이나 전역 Python 변경은 필요하지 않습니다. MCP 등록에는 KEY가 필요하지 않습니다. 등록 후 채팅에서 개인 KEY를 연결합니다.

### Claude Code를 사용하는 경우

같은 PowerShell 창에서 아래 두 줄을 실행해 현재 MCP 파일의 전체 경로를 기억시킵니다. 경로를 직접 타이핑할 필요가 없습니다.

```powershell
$mcpPythonPath = (Resolve-Path -LiteralPath '.\.venv\Scripts\python.exe').Path
$mcpScriptPath = (Resolve-Path -LiteralPath '.\run_mcp.py').Path
```

이어서 **등록 범위를 선택하고 아래 두 방법 중 하나만** 실행합니다.

- **내 계정에서 여러 업무에 사용:** 같은 PowerShell에서 다음 명령을 실행합니다.

```powershell
claude mcp add --transport stdio --scope user pt-ai-square -- "$mcpPythonPath" "$mcpScriptPath" serve
```

- **특정 업무 폴더에서만 사용:** 아래 예시 경로를 실제 업무 폴더로 바꿔 이동한 다음 등록합니다. 위에서 경로를 기억시킨 **같은 PowerShell 창**을 사용하세요.

```powershell
Set-Location -LiteralPath 'C:\실제업무폴더'
claude mcp add --transport stdio --scope project pt-ai-square -- "$mcpPythonPath" "$mcpScriptPath" serve
```

성공 메시지를 확인하고 Claude Code를 다시 시작합니다. 이미 같은 이름이 등록되어 있다는 메시지가 나오면 중복 추가나 삭제부터 하지 말고 `claude mcp get pt-ai-square`로 실행 경로를 확인하세요. 등록 범위와 명령 형식은 [Claude Code 공식 MCP 안내](https://code.claude.com/docs/en/mcp#mcp-installation-scopes)를 참고할 수 있습니다.

### 다른 로컬 MCP 지원 프로그램을 사용하는 경우

그 프로그램의 MCP 설정 화면 또는 설정 파일에 **이름 `pt-ai-square`**, 실행 프로그램 `.venv\Scripts\python.exe`의 전체 경로, 인자 `run_mcp.py`의 전체 경로와 `serve`를 입력합니다. JSON 설정을 받는 프로그램에서는 아래 형식을 참고하되 해당 프로그램의 규칙에 맞춥니다. 예시를 실제 압축 해제한 **절대 경로**로 바꾸고 기존 MCP 항목은 유지합니다.

```json
{
  "mcpServers": {
    "pt-ai-square": {
      "command": "C:\\도구\\pt-square-mcp\\.venv\\Scripts\\python.exe",
      "args": ["C:\\도구\\pt-square-mcp\\run_mcp.py", "serve"]
    }
  }
}
```

여기에 KEY를 넣지 않습니다. 사용 중인 프로그램이 로컬 stdio MCP를 지원해야 하며, 웹 대화창에 이 JSON을 붙여넣는 것으로 등록되지는 않습니다. 설정을 저장한 뒤 AI 프로그램을 다시 시작합니다.

## 4. 채팅에서 개인 KEY 연결

이 안내는 **MCP 1.6.4 이상**과 최신 웹 서버 기준입니다. KEY 연결, 폴더 선택, 도구 등록은 채팅에서 진행하며 별도 KEY 창이나 필수 웹 승인 화면을 열지 않습니다. 예전 버전은 AI에 등록된 실제 MCP 폴더의 코드 파일을 최신 ZIP으로 교체하고 AI 프로그램을 완전히 종료한 뒤 다시 시작하세요. 웹 서버만 업데이트해도 이미 설치한 MCP 코드가 바뀌지는 않습니다. 기존 `.venv`와 개인 설정은 보존하며 MCP SDK는 기존 **1.30.0**을 그대로 사용합니다.

1. Claude Code에 **“AI SQUARE 연결해줘”**라고 요청합니다. AI가 `connect_account`를 호출하면 연결할 사이트와 개인 KEY 입력 안내를 보여줍니다.
2. 표시된 사이트가 맞는지 확인하고, 채팅의 안내에 따라 웹에서 발급한 개인 KEY를 전달합니다. AI는 KEY를 `connect_account`의 `key` 인자로 전달합니다. 별도 프로그램이나 입력창을 열지 않습니다.
3. HTTP 사이트는 **해당 주소로 KEY가 암호화되지 않고 전송되는 것에 동의**해야 합니다. 지원하는 AI에서는 채팅 안의 확인 질문(HITL)으로 연결 동의만 받습니다. 미지원 AI는 채팅에서 정확한 사이트 주소에 대한 동의를 받은 뒤 `accept_http_origin`으로 전달합니다. AI가 임의로 동의하면 안 됩니다. 이미 동의하여 저장된 같은 주소는 다시 확인하지 않습니다.
4. 실제 서버 인증이 성공하면 AI가 이름·부서와 연결 결과를 알려줍니다. 잘못된 KEY나 접속 실패는 연결 완료로 처리하지 않으며 기존 정상 설정을 덮어쓰지 않습니다.

**채팅 입력은 비밀 입력창이 아닙니다.** KEY는 대화 내용·모델 입력·도구 호출 입력 기록에 남을 수 있습니다. MCP는 KEY를 도구 결과나 오류 메시지에 다시 출력하지 않지만, 로컬 암호화 저장이 이미 남은 채팅 기록을 삭제하지는 않습니다. 일반 MCP 폼 elicitation으로 KEY를 요청하지 않습니다. 호스트의 확인 기능은 HTTP 연결 동의처럼 비밀이 아닌 내용만 확인합니다. 폴더 위치는 일반 채팅에서 확인합니다.

KEY는 실제 인증 성공 후 현재 Windows 사용자에게 묶인 DPAPI로 암호화해 보관합니다. 실행 명령줄이나 MCP 설정 JSON에는 KEY를 넣지 않습니다. 연결 성공 후 다음 작업부터 새 KEY를 읽으므로 재설치할 필요는 없습니다. MCP 코드 자체를 교체했다면 AI 프로그램을 다시 시작합니다.

기본 다운로드 폴더는 자동 생성됩니다.

```text
C:\Users\내계정\AI_SQUARE\downloads\
```

다운로드 파일은 `downloads/server-서버식별자/tool-도구ID/v버전/` 아래에 구분하고, 받은 결과에 실제 경로를 표시합니다. 이미 받은 파일이 있어도 현재 연결된 사번으로 다운로드 내역을 확인합니다. 같은 사번의 반복 다운로드는 중복 집계하지 않으며, 알림을 직접 껐다면 다시 켜지 않습니다. 정확한 집계를 위해 기존 파일이 있어도 서버에서 파일을 다시 받아 검증하므로 파일 크기만큼 네트워크가 사용됩니다. 기존 수신 기록이 없는 계정의 첫 업데이트 요청은 다운로드로 기록됩니다. 로컬 시험 사이트와 운영 사이트에 같은 도구 ID가 있어도 파일이 섞이지 않습니다. **다운로드 위치는 받은 파일을 보관하는 곳이고, 설치 위치는 AI가 그 기능을 사용하는 곳입니다.** 설치할 때 **공통 (내 계정) / 현재 프로젝트 / 기타 경로** 중 하나를 선택합니다. 기본 다운로드 폴더가 생겼다고 PC 전체에 접근 권한이 생기는 것은 아닙니다.

## 5. 실제 연결 확인 후 사용하기

AI 대화창에 **“AI SQUARE의 connection_status를 실행해서 내 계정 연결 상태를 확인해줘”**라고 요청합니다. 실제 도구 호출 결과에서 본인 계정과 부서·허용 작업이 확인되면 사용할 준비가 끝납니다. 이미 연결을 마쳤다면 KEY를 다시 보내지 않아도 됩니다.

Claude의 `Connected`는 로컬 MCP 프로세스와 통신한다는 뜻이며, 실제 웹 계정 인증까지 보장하지 않습니다. `connection_status`나 `connect_account`를 찾을 수 없다면 3번의 AI 등록과 프로그램 재시작을 확인합니다. 인증 오류는 아래 KEY 재연결 안내를 따릅니다.

이후 **“회의록 요약 도구 찾아줘”**, **“첫 번째 도구를 받아줘”**처럼 요청합니다. 다운로드 결과에서 자동 저장된 실제 경로를 확인할 수 있습니다. 파일 다운로드와 설치는 별개이며 설치 시에는 범위와 변경 내용을 다시 확인합니다.

## KEY가 만료·취소·재발급되었을 때 다시 연결하기

MCP 요청에서 **401 인증 오류**가 나면 현재 연결된 서버의 **KEY 발급 화면 링크**와 다시 연결하는 방법을 보여줍니다. 링크는 현재 MCP 설정의 서버 주소에 `/local-access`를 붙인 주소입니다. 예를 들어 `http://회사서버:5000`에 연결 중이면 `http://회사서버:5000/local-access`로 안내하며 다른 사이트로 보내지 않습니다.

1. 오류 안내에 표시된 **KEY 발급 화면 링크**를 누르고 회사 웹에 로그인합니다.
2. **내 연결 KEY → KEY 재발급**에서 새 KEY를 복사합니다. 재발급하면 같은 사번의 이전 KEY는 사용할 수 없습니다. 계정이 비활성화된 경우에는 재발급으로 해결되지 않으므로 운영자에게 확인합니다.
3. AI에게 **“AI SQUARE KEY 다시 연결해줘”**라고 요청합니다. `connect_account` 또는 기존 `reconnect_key`가 현재 연결 주소와 채팅 기록 안내를 보여줍니다.
4. 해당 주소가 맞는지 확인하고 새 KEY를 채팅으로 전달합니다. HTTP 주소를 아직 승인하지 않았다면 그 정확한 주소에 대한 비암호화 연결 동의를 먼저 확인합니다.
5. 본인 이름·부서가 표시되면 완료입니다. 다음 검색·다운로드 요청부터 새 KEY로 인증합니다. MCP나 이미 설치한 도구를 다시 설치할 필요는 없습니다.

두 연결 도구는 기존 설정이 있으면 **현재 서버 주소(`Settings.url`)**를 유지합니다. 최초 연결은 웹에서 받은 ZIP의 사이트 주소를 사용합니다. 별도 `--config`를 쓰는 경우에도 실행 중인 MCP의 설정이 기준입니다. 재연결에서도 KEY 입력용 프로그램이나 폴더 창을 열지 않습니다.

재연결은 인증정보만 갱신합니다. 중단된 설치·업로드를 자동으로 다시 실행하지 않습니다. 등록이나 설치 결과가 불명확했다면 결과를 먼저 확인하세요. **게시 초안은 생성 당시 KEY ID에 묶여 있으므로 KEY 재발급 후에는 새 초안을 준비**합니다. 새 초안의 대상·내용·공개 범위를 기존 게시 요청과 대조한 뒤 진행하며 달라진 사항이 있으면 채팅에서 확인합니다. 이미 게시된 도구·버전과 PC에 설치한 파일은 유지됩니다.

## 연결 안내 파일과 고급 설정

`Connect.cmd`는 AI에 MCP를 등록하고 채팅에서 연결하는 방법을 안내하는 파일입니다. 직접 실행해도 KEY 입력창을 열거나 KEY를 받지 않습니다. 일반 사용자는 이 파일을 실행하지 않고 위의 채팅 연결 순서를 따르면 됩니다. 실제 연결은 다음 명령으로도 확인할 수 있습니다.

```powershell
python .\run_mcp.py status
```

서버 주소가 없는 공통 ZIP 대신 웹의 **로컬 MCP 받기**에서 해당 사이트의 ZIP을 받으세요. 설치할 프로젝트와 등록할 원본 폴더는 아래 절차에 따라 채팅에서 지정합니다. 일반 검색·다운로드에는 작업 폴더 옵션이 필요 없습니다.

설정 위치는 `%USERPROFILE%\.pt-ai-square\mcp\config.json`입니다. 별도 설정을 쓰려면 명령의 맨 앞에 `--config "C:\별도폴더\config.json"`을 넣습니다. `.env`를 사용하지 않습니다.

자동화 등 고급 환경에서는 이미 안전하게 설정된 `PTAI_API_TOKEN`을 사용하는 `setup --token-from-env`를 선택할 수 있습니다. KEY를 명령줄에 쓰지 않습니다. 이 방식은 **KEY를 저장하지 않고**, MCP를 실행할 때마다 해당 프로세스의 환경변수에서 읽습니다. KEY를 재발급했다면 실행 환경의 값을 갱신하고 **AI 프로그램을 다시 시작**합니다. 다른 사이트는 `--url`, 추가로 허용할 기존 폴더는 `--workspace`로 지정할 수 있습니다. 비대화형 HTTP 연결은 사용자가 확인한 정확한 주소를 `--accept-http-origin "http://회사서버주소"`으로 지정해야 하며, 미지정 상태에서 별도 확인창으로 전환하지 않습니다. HTTP 확인은 전송 암호화를 제공하지 않으며 일반 웹 포트나 실행 방식을 바꾸지 않습니다.

## 실제 사용 예

- “여러 엑셀 파일을 하나로 합치고 싶어. 쓸 만한 도구 있어?”
- “회의 내용을 짧게 정리해서 공유하고 싶어.”
- “메일 조회 도구 추천해줘. 같은 부서에서 많이 쓰는 것도 알려줘.”
- “김하늘님이 등록한 도구 찾아줘.” → 실제 등록자 이름과 등록 정보의 담당자 이름도 검색합니다. 등록자 이름은 현재 플랫폼 계정 이름 기준이며 도구 접근 권한은 그대로 적용합니다.
- “최근 7일 순위 TOP 10 보여줘.” / “누적 순위로 보여줘.”
- “이 도구에 좋아요를 눌러줘.” / “이 도구의 좋아요를 취소해줘.” → 선택한 도구의 좋아요 상태를 반영합니다. 검색이나 다운로드만으로 좋아요가 자동으로 눌리지는 않습니다. `like_item`의 `liked=true`는 추가, `false`는 취소이며, 반복해도 같은 상태를 유지합니다. 결과의 `count`가 비어 있으면 상태는 저장됐지만 전체 개수는 아직 확인되지 않은 것입니다.
- “첫 번째 Skill을 현재 프로젝트에 설치해줘.” → 설치 위치·변경 내용 확인 → 파일 받기·해시 검사·배치.
- “설치한 도구에 새 버전이 있는지만 확인해줘.” → 교체하지 않고 확인 결과만 반환.
- “이 폴더를 공통 업무의 새 Skill로 전체 공개 등록해줘.” → 원문 확인·소개와 동작 흐름 작성 → 신규 대상·조직·업무·공개 범위 확인 → ZIP/MD·초안 준비 → 채팅에서 게시 완료. 이미 명확히 요청한 내용을 다시 승인받지 않습니다.

등록 정보는 사용하는 AI가 실제 소스와 지침을 읽고 작성합니다. MCP나 웹 서버에 별도 LLM 키는 필요하지 않습니다. 여러 파일 폴더는 `ai-square.json` v1에 맞는 ZIP으로 준비하고, 단일 MD는 **그대로 MD**로 등록합니다. 단일 ZIP을 입력하면 원본을 유지합니다. `installProfile`은 등록 메타데이터의 별도 속성이며 ZIP v1 선언 안에 넣지 않습니다.

### 이름을 몰라도 필요한 일로 찾기

무슨 자료로 어떤 일을 하고 싶은지 말하면 됩니다. AI는 그 뜻을 짧은 검색어로 정리하고, 등록된 이름과 소개, 업무 태그, 등록자 이름에서 맞는 도구를 찾습니다. 예를 들어 “여러 엑셀 파일을 하나로 합치고 싶어”는 “엑셀 파일 합치기”로 찾습니다. 결과가 부족하면 같은 뜻의 업무 표현으로 다시 찾아봅니다. 실제 등록된 정보 안에서 찾는 방식이므로, 원하는 기능이 없으면 없다고 안내합니다.

추천에는 도구가 하는 일과 요청에 맞는 이유를 함께 보여줍니다. 조직 선호도는 관련도가 같은 후보를 비교할 때 참고하고, 사용자가 말하지 않은 조직이나 프로그램, 유형으로 결과를 제한하지 않습니다. 자세한 사용 조건은 도구 설명에서 확인하며 검색만으로 다운로드하거나 설치하지 않습니다.

### 동료가 알아보기 쉬운 등록 설명

MCP **1.6.1**부터 AI가 등록 설명을 쓸 때 다음 기준을 사용합니다. 이름과 소개를 이미 정했다면 그 내용을 우선하고, 어색한 부분은 제안합니다. MCP가 기존 도구 이름이나 업로드한 ZIP을 자동으로 바꾸지는 않습니다.

- 이름에는 “엑셀 파일 합치기”, “회의 내용 요약”처럼 무엇을 하는지 짧게 적습니다. 개발 프로젝트명이나 홍보 문구만으로 이름을 짓지 않습니다.
- 소개에는 어떤 자료로 무엇을 만들고 언제 쓰는지 1~2문장으로 적습니다. 코드에서 확인되지 않은 기능이나 시간 절약 효과를 덧붙이지 않습니다.
- 기술 설명과 설치 조건은 상세 안내에 적습니다. Claude나 Codex 이용 여부처럼 실제 사용에 필요한 조건은 빠뜨리지 않습니다.
- 제목과 소개, 사용 안내, 동작 흐름, 검색 추천 문장에서 여러 항목을 가운데점으로 이어 쓰지 않습니다. `글자·도형·표·차트를` 대신 `글자와 도형, 표, 차트를`처럼 쉼표나 자연스러운 연결 표현을 씁니다. 나열이 길면 문장을 나눕니다. 공식 고유명과 코드, 필드명, 식별자, 원문 인용은 일괄 치환하지 않습니다.
- 업무 태그에는 동료가 검색할 만한 말을 최대 8개 적습니다. 예를 들어 실제 회의 요약 도구에는 “회의록”, “회의 내용 요약”을 쓸 수 있습니다. 지원하지 않는 기능을 태그로 넣지는 않습니다.

예를 들어 업무 지침과 메모, 본인의 Claude와 Codex 대화를 모아 보여주는 도구라면 아래처럼 소개할 수 있습니다. 실제 도구를 확인해 작성하는 예시이며, 다른 도구에 그대로 붙이는 문구는 아닙니다.

> **업무 자료와 AI 대화 정리**
>
> 프로젝트에 저장한 업무 지침과 메모, 내 Claude와 Codex 대화 기록을 한 화면에 정리합니다. 이전 작업을 확인하고 이어서 할 때 씁니다.

`name`은 50자 이내, `desc`는 200자 이내이며 업무 태그는 각각 30자 이내입니다. `guide`에는 준비물, 실행 방법, 결과 확인 방법과 필요한 제약을 씁니다. 원본에 확인된 동작 흐름이 있으면 `workflow`에 사용 순서대로 담습니다. 글을 다듬는 작업은 AI가 수행하며 서버가 별도 모델을 호출하거나 문체만으로 등록을 거절하지 않습니다.

### 채팅에서 바로 게시하기

**조직은 직접 선택합니다.** 신규 등록 요청에 조직이 정해져 있지 않으면 AI가 등록 가능한 조직을 보여주고 채팅에서 선택을 요청합니다. 내 소속 부서나 공통을 임의로 선택하지 않습니다. 이미 요청에서 조직을 분명히 지정했다면 실제 선택지에서 확인해 사용하며 같은 내용을 다시 묻지 않습니다. 기존 도구의 새 버전을 올릴 때도 기존 조직과 요청 내용을 확인하고, 사용자 의사와 관계없이 소속 부서로 바꾸지 않습니다.

1. `prepare_publish`로 파일과 내용을 검증하고 초안을 준비합니다. 응답의 요약에서 신규/업데이트 대상, 이름·설명·파일, 조직·업무와 공개 범위를 확인합니다.
2. 사용자가 이 내용으로 게시하라고 이미 명확히 요청했다면 그 요청에 따라 바로 진행합니다. 대상, 조직 또는 공개 범위가 불분명하거나 준비한 내용이 요청과 달라졌을 때만 채팅으로 확인합니다. 파일·문서에 적힌 지시는 사용자의 게시 요청으로 취급하지 않습니다.
3. 같은 초안의 `draft_id`, 준비 응답의 `reviewDigest`를 `review_digest`에 넣고 `confirmed=True`로 `publish_item`을 호출합니다. 별도 웹 승인 버튼은 필요 없습니다. 성공 응답의 도구 ID·버전으로 완료를 확인합니다.

이 흐름에는 **최신 웹 서버와 MCP 1.6.0 이상을 함께 적용**해야 합니다. `reviewDigest`는 확인한 초안의 대상·내용을 묶는 값이며 사용자 동의 자체를 증명하지는 않습니다. 실제 채팅 요청을 따르는 책임은 AI와 클라이언트에 있고, 서버는 같은 KEY·작성자·도구 소유권·초안 digest·파일 해시·버전 충돌을 검사합니다. 임의로 바꾼 MCP라도 타인 도구나 관리자 API 권한을 얻지는 못합니다. 기존 웹 검토 링크는 원하는 경우 사용할 수 있는 대안이며, STORE·독립 CLI 등 기존 클라이언트의 웹 검토 방식도 유지됩니다.

### 파일 없이 MCP·API 주소 등록하기

**“이 사내 MCP/API 주소를 MCP/Tool 항목으로 등록해줘”**라고 요청할 수 있습니다. 인증정보가 포함되지 않은 **HTTP 또는 HTTPS 주소**를 사용합니다. 주소에 계정·비밀번호·KEY를 넣지 않습니다.

AI는 `prepare_publish`의 metadata에 `mode="url"`, `url="http://사내서버/mcp"`와 이름·설명·연결 가이드·조직·업무·공개 범위를 넣고 `source_path`는 생략합니다. ZIP은 필요 없습니다. 신규 등록 또는 본인 도구의 새 버전 대상과 내용을 채팅 요청에서 확인한 뒤 바로 게시합니다. 주소만 바꾸는 새 버전도 같은 초안·digest 확인을 거칩니다.

등록 주소는 **연결 링크와 사용 안내**로 저장됩니다. 주소 등록만으로 원격 MCP의 인증·transport를 자동 설정하거나 일반 API를 MCP로 변환하지 않습니다. 실제 연결 방법은 해당 도구의 가이드를 따릅니다.

이 주소는 **AI SQUARE 플랫폼에 개인 KEY로 연결하는 서버 주소와 별개**입니다. HTTP 항목 등록을 위해 연결 설정이나 `--accept-http-origin`을 바꾸지 않습니다. 플랫폼 자체에 HTTP로 연결할 때의 정확한 주소 확인과 암호화되지 않은 KEY 전송 안내는 그대로 적용됩니다. HTTP 주소 등록은 최신 웹 서버와 MCP **1.2.2 이상**을 함께 사용하세요.

### 기존 도구에 새 버전 등록하기

1. AI가 먼저 `prepare_publish(target="review")`로 본인이 등록한 도구를 확인합니다. packageId가 일치하는 항목이 없으면 이름으로 후보를 다시 검색합니다. **이름이 비슷하다는 이유만으로 업데이트하거나 새 도구로 확정하지 않습니다.**
2. 후보의 이름과 도구 ID를 보고 **기존 도구의 새 버전**인지 **별도 신규 도구**인지 직접 선택합니다. 기존 도구라면 그 `tool_id`를 지정해 준비합니다. 관리자 KEY도 다른 사람의 도구에는 새 버전을 등록할 수 없습니다.
3. 선택한 기존 도구를 업데이트할 때는 새 ZIP의 packageId가 달라도 가능합니다. 플랫폼의 **고정 packageId**는 처음 연결된 식별자를 유지하고, **sourcePackageId**는 이번 ZIP의 `ai-square.json`에 적힌 원본 값을 보여줍니다. 서로 다르면 `packageIdentityChanged`가 표시됩니다. ZIP 파일명이나 내부 선언을 고쳐 맞출 필요는 없습니다.
4. 폴더에서 ZIP을 새로 만들 때 packageId를 생략했고 기존 선언 파일도 없다면, 선택한 도구의 고정 packageId를 기본값으로 사용합니다. 직접 지정한 다른 packageId나 이미 있는 `ai-square.json`은 바꾸지 않습니다. 설치 경로에 쓰는 `installProfile.slug`와 실제 시작 파일 검사는 별도로 유지됩니다.
5. 채팅 요청과 준비한 대상 도구·내용·공개 범위가 맞으면 같은 초안과 `reviewDigest`로 바로 게시합니다. 명확한 게시 요청을 다시 묻거나 웹 승인 화면을 필수로 열지 않습니다. 기존 버전 원본과 새 ZIP 원본은 각각 보관합니다. 다른 관리 작업으로 배포 정보가 바뀌었다면 새 초안을 준비하고 달라진 내용을 확인합니다.

이 동작은 MCP **1.2.1 이상**과 최신 웹 서버를 함께 적용해야 합니다. MCP 파일을 교체한 뒤 AI 프로그램을 다시 시작하세요. 기존 KEY와 연결 설정을 다시 만들 필요는 없습니다.

## 설치할 위치 선택

1. AI에게 **“이 Skill을 설치해줘”**라고 요청합니다. AI는 `list_install_locations`로 실제 현재 프로젝트 정보를 확인하고 다음 세 가지를 채팅에서 안내합니다. 확인된 현재 프로젝트가 하나이면 그 경로를 기본 후보로 보여줍니다.
   - **공통 (내 계정):** 이 PC의 내 사용자 계정에서 여러 프로젝트에 사용할 때 선택합니다. 다른 사람의 계정이나 PC 전체에 설치하는 뜻은 아닙니다.
   - **현재 프로젝트:** 지금 AI에서 작업 중인 프로젝트에만 설치합니다. 채팅에 표시된 실제 경로가 맞는지 확인합니다.
   - **기타 경로:** 다른 프로젝트의 전체 경로를 채팅으로 지정합니다. 별도 폴더 선택 창은 열지 않습니다.
2. 프로젝트가 여러 개이거나 확인할 수 없으면 AI가 채팅에서 원하는 경로를 묻습니다. MCP 실행 폴더를 현재 프로젝트라고 단정하지 않습니다. 실행 작업 폴더가 후보로 보이더라도 실제 사용할 경로인지 확인해야 합니다.
3. AI가 채팅에 표시한 선택지에서 범위와 전체 경로, 접근 목적을 확인하고 답합니다. 별도 폴더 선택창이나 대화형 폼은 열리지 않습니다. 확인된 현재 프로젝트 후보가 없으면 **기타 경로**를 고르고 사용할 폴더의 전체 경로를 알려주세요. 취소하면 접근 범위가 늘어나지 않으며 드라이브 전체는 허용하지 않습니다.
4. 이어서 **설치 범위·실제 경로·변경할 파일·실행할 명령**이 담긴 준비안을 확인하고 설치를 승인합니다. 폴더 접근 확인만으로 설치나 실행이 승인되지는 않습니다.

`select_workspace`의 첫 응답은 `pending`과 `requestId`, 후보를 반환합니다. AI는 사용자의 채팅 답변을 받은 뒤 같은 `request_id`와 목적, `selection`(`current`/`user`/`other`), 필요한 전체 `path`, `confirmed=True`로 확정합니다. 후보가 없으면 `other`와 사용자가 지정한 경로를 사용합니다. `user`는 설치에만 해당합니다. 선택을 취소하면 기존 요청을 재사용하지 않고 다시 선택을 요청할 때 새 요청을 시작합니다. 별도 창을 기다리거나 완료 여부를 반복 조회하지 않습니다. 다운로드 파일은 이 선택과 관계없이 기본 `AI_SQUARE/downloads`에 보관됩니다.

이미 만든 ZIP을 등록하려면, ZIP이 있는 폴더의 접근을 채팅에서 확인한 다음 **등록할 ZIP 파일의 전체 경로**를 함께 지정하세요. 예를 들어 “`C:\업무\팀공유\도구.zip`을 신규 Skill로 등록해줘”라고 요청합니다. 폴더를 선택했다고 그 폴더의 모든 파일을 올리는 것은 아닙니다. AI는 지정한 ZIP 한 개를 원본으로 확인하고 업로드합니다. 반대로 폴더 자체를 원본으로 선택하면 그 폴더가 패키징 대상이므로 관련 없는 자료가 섞이지 않은 원본 폴더를 선택하세요.

## 설치 지원 범위

| 유형 | 지원 범위와 결과 |
|---|---|
| Claude Skill MD | 선택한 프로젝트 또는 내 계정의 `.claude/skills/<slug>/SKILL.md`에 복사하고 내용 확인 |
| Claude Skill ZIP | ZIP 최상위 SKILL.md와 보조 파일을 같은 위치에 함께 배치 |
| Python/Node MCP ZIP | 시작 파일·런타임 확인, 프로젝트 `.mcp.json` 또는 내 계정 `.claude.json`에 지정 MCP 항목 추가. 다른 항목 보존. 연결 설정 완료와 실제 MCP 핸드셰이크 성공은 구분 |
| EXE·MSI·PS1 | 사용자가 확인한 범위별 선언 인자로 설치기를 실행. 관리자 승격·실행 정책 우회 없음. `launched`는 설치 완료가 아님. `verify_install`은 선언한 결과 파일 존재만 확인 |
| URL·터미널 명령·지원하지 않는 호스트 | 상세의 연결·설치 안내 제공. 일반 임의 명령 실행 도구는 제공하지 않음 |

자동 설치는 등록자가 올바른 `installProfile`을 명시한 항목만 지원합니다. 의존성 pip/npm 설치는 자동 실행하지 않습니다. 기존 도구에 선언이 없으면 수동 설치 안내로 연결됩니다.

설치 범위는 사용자가 선택합니다. 현재 프로젝트 경로를 자동으로 찾았더라도 **공통 (내 계정)** 설치로 임의 전환하지 않습니다. **기타 경로**는 사용자가 선택한 프로젝트 폴더이며 PC 전체 설치를 뜻하지 않습니다. 준비안에 보이는 경로와 인자를 확인한 뒤 설치합니다. 새 버전·설정·로컬 파일이 바뀌면 준비안을 다시 생성해야 합니다. 이 MCP가 설치한 파일과 해당 MCP 설정은 백업·복구할 수 있지만, 사용자가 바꾼 파일을 덮어쓰거나 EXE가 바꾼 시스템 상태를 되돌리지는 않습니다.

파일·설정 변경 전에 복구 기록을 저장합니다. 설치나 복구 중 프로세스가 강제로 종료된 경우, 다음 설치 준비·검증·복구에서 승인된 파일 해시와 현재 상태를 비교합니다. 이미 완료된 결과는 기록만 확정하고 미완료 변경은 원상 복구하며, 사용자가 추가로 변경한 파일·설정은 보존하고 확인 필요 상태로 안내합니다. 이 과정에서 파일을 다시 다운로드하거나 EXE를 자동 재실행하지 않습니다.

## 등록용 설치 선언 예

단일 MD 또는 최상위 SKILL.md가 있는 ZIP의 등록 metadata에 넣습니다.

```json
{
  "installProfile": {
    "schemaVersion": 1,
    "kind": "skill",
    "host": "claude",
    "slug": "memo-summary",
    "scopes": ["project", "user"],
    "entrypoint": "SKILL.md"
  }
}
```

MCP는 `kind: "mcp"`, 실제 `entrypoint: "server.py"`와 `command: {"executable":"python", "args":["{entrypoint}"]}`를 사용합니다. 실행 인자는 `{entrypoint}`, `{installDir}`, `{scopeDir}`만 치환하며 셸로 해석하지 않습니다. EXE·MSI·PS1은 `kind: "installer"`와 `installerArgs: {"project":["실제 지원 인자"], "user":["실제 지원 인자"]}`를 명시합니다. 실제 설치기에서 지원하지 않는 옵션을 만들지 마세요. 범위를 지원하지 않으면 `scopes`에서 빼고 이유를 guide에 적습니다.

## 권한과 데이터

- 유효한 개인 KEY는 기존 `read` KEY까지 검색·다운로드·좋아요와 본인 도구 신규/버전 게시를 허용합니다. 권한 선택이나 재발급이 필요하지 않습니다. 인식하지 못하는 권한 값이나 무효 KEY는 거절합니다. 다른 사람 도구 수정, 관리자 설정, DB 명령, 임의 서버 파일 경로 API는 제공하지 않습니다.
- 서버가 매 요청마다 KEY의 사번·권한·소유권을 검사합니다. MCP를 수정해도 서버 검사를 우회할 수 없습니다. 사용자가 이미 별도의 DB 접속 권한을 가진 경우까지 이 MCP가 제한하는 것은 아닙니다.
- 초안 준비만으로 일반 목록에 게시되지는 않습니다. 채팅에서 확인한 내용의 `reviewDigest`와 명시적 `confirmed=True`로 같은 KEY가 게시하거나, 기존 웹 검토 대안을 사용할 수 있습니다. 내용·파일·대상을 바꾸려면 새 초안을 준비합니다. 서버는 초안 일치 여부를 검사하지만 사람이 실제로 확인했는지는 독립적으로 증명하지 않습니다.
- 다운로드는 웹과 같은 API를 사용하여 도구당 사번별 첫 다운로드만 집계합니다. 업데이트 수신은 집계하지 않습니다. 파일 수신과 실제 설치 완료는 별개입니다.
- 로컬 작업 폴더 허용 목록, ZIP 경로/링크/크기 검사와 단순 인증정보 패턴 검사를 수행합니다. 악성코드 검사나 임의 코드의 안전성 보증은 아닙니다.
- 자동 실행 프로그램이 사용자의 권한으로 작동한다는 점은 일반 설치기와 같습니다. 로컬 확인 단계는 사용 편의를 위한 절차이며, 수정한 로컬 프로그램을 신뢰 경계로 삼지 않습니다.

## 문제 해결

1. **401:** 이전 기간형 KEY의 만료·취소·재발급 또는 사용자 비활성화 등으로 인증할 수 없는 상태입니다. 안내된 현재 서버의 `/local-access` 링크를 확인하고 새 KEY가 필요하면 발급한 뒤 “AI SQUARE KEY 다시 연결해줘”라고 요청합니다. 계정 비활성화는 운영자에게 문의합니다.
2. **403:** 인증과 별개로 해당 도구 조회 권한, 본인 도구인지, 최신 웹 서버인지 확인합니다. 기존 유효한 읽기 KEY도 본인 도구를 게시할 수 있지만 타인 도구 권한이나 관리 권한은 생기지 않습니다. 관리자 KEY도 남의 도구를 업데이트할 수 없습니다.
3. **409:** 초안의 확인 값·digest·만료·배포 버전 충돌을 확인합니다. 같은 KEY의 단순 통신 재시도는 같은 draft ID와 확인 digest를 사용하면 중복 게시하지 않습니다. KEY를 재발급했다면 새 초안을 준비합니다. 오래된 웹 서버가 웹 승인을 요구하면 최신 서버와 MCP를 함께 반영하세요.
4. **허용 폴더 밖:** AI에게 원본/프로젝트 폴더를 채팅에서 지정하고 표시된 전체 경로와 접근 목적을 확인합니다. MCP가 임의로 접근 범위를 늘리거나 폴더 창을 열지 않습니다.
5. **서버 주소가 없다는 안내:** 웹의 **로컬 MCP 받기**에서 새 ZIP을 받으세요. 저장소의 공통 ZIP에는 운영 주소가 들어 있지 않습니다.
6. **Claude Connected만 표시됨:** “AI SQUARE 연결 상태 확인해줘” 또는 `python run_mcp.py status`로 본인 계정 인증까지 확인합니다.
7. **접속 실패 또는 5xx:** 사내망 연결·서버 상태를 확인합니다. 이것만으로 KEY가 만료되었다고 판단하거나 재발급하지 않습니다. 저장 요청이었다면 반영 여부부터 확인하고 다시 시도합니다.
